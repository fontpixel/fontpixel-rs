All committed third-party fonts are small and freely licensed. Infrastructure tests construct synthetic bytes in memory; imported and generated fixtures are inventoried below.

## W0.2 charset fixtures (no fonts)

- `crates/fontpixel/tests/data/charset_canonical.json`: the `canonical` section
  of supplied `reference/bdfparser-js/test/fixtures/charsets.json`; MIT,
  copyright 2017–2025 Tom Chen. Tests name/property normalization without needing
  a reference checkout. Source hash and complete license: THIRD_PARTY_NOTICES.md
  and LICENSES/bdfparser-MIT.txt
- `crates/fontpixel/tests/data/charset_maps.json`: generated by
  `tools/gen_charsets.py` from strict CPython codec queries. Per-map counts and
  non-cryptographic regression digests; independent byte-for-byte validation is
  in `tools/check_charsets.py`. See THIRD_PARTY_NOTICES.md for provenance

## W1.1 generated bitmap oracle (no fonts)

- `crates/fontpixel/tests/data/bitmap_reference.json`: 3,841 deterministic,
  synthetic bitmap cases generated by `tools/gen_bitmap_cases.py` with seed
  `0xBDF301`. Expected pixels and bounds come from the supplied MIT bdfparser
  `bitmap.py`, not from the Rust implementation. Source hash and license are in
  THIRD_PARTY_NOTICES.md and LICENSES/bdfparser-MIT.txt. Tests cover geometry,
  four-way concatenation with negative gaps and degenerate inputs, overlay/paste,
  discrete 0/1/2 effect labels, bold/italic, padding and pattern replacement.
  Regeneration requires a read-only reference checkout and uses no bytecode files;
  ordinary Cargo tests replay the fixture without Python or a reference checkout.

- `tests/data/bdf/3x5-block.bdf`: verbatim supplied

  SHA-256 `8db8ea30e14b6d7abe9add82a2330c8c6d108ae02f6028dc700c70553c1041de`.
  102 glyph records, 9,512 bytes; SIL OFL 1.1, copyright 2026 mazeon. Original
  notice/Reserved Font Names: `LICENSES/bdf-fonts/3x5-block.txt`; complete OFL
  text: `LICENSES/OFL-1.1.txt`. Source FONT/name is unchanged. Its independently
  generated `.golden.bdf` is byte-identical; tests real FontForge-style output,
  unencoded glyphs, offsets and properties
- `tests/data/bdf/spleen-5x8.bdf`: verbatim supplied
  `samples/fontpixel-catalogue/spleen/spleen-5x8.bdf`, upstream
  https://github.com/fcambus/spleen, SHA-256
  `40488184d075d0c752cdd239b441c5ece51e50b353156f2496c756c384ab01cb`.
  472 glyphs; BSD-2-Clause, copyright 2018–2026 Frederic Cambus. Complete notice:
  `LICENSES/bdf-fonts/spleen-BSD-2-Clause.txt`. `.golden.bdf` is Python SPEC-v3
  canonical output (quoted/reordered comments); SHA-256
  `b3f3f107d5afcc36e38a71f2aa21facfec6ec9fcc8f2d1544e19ed6ded5a4654`
- `crates/fontpixel/tests/data/bdf_reference.json`: 924 deterministic synthetic
  BDF parser/writer cases, generated by `tools/gen_bdf_cases.py` using the supplied
  MIT Python reference. Includes exact bytes, all 17 metadata slots, properties,
  headers, original names, warning order/text and fatal errors. Seeds:
  `0xBDF30102` and `0xBDF00BAD`; no third-party font data inside the JSON
- Large reference fonts and all 59 supplied BDF corpus fonts are only read by
  `tests/crosscheck/bdf.py`. They are not copied into the repository. Results and
  output SHA-256 hashes are in `tests/crosscheck/bdf-results.json`

## W1.3 PCF fixtures

- `tests/data/pcf/syn-*.pcf.gz`: 46 verbatim tiny PCF goldens from
  `reference/bdfparser/tests/fonts/golden/`; font designs authored in the
  MIT-licensed `reference/bdfparser/tests/test_pcf.py`, Tom Chen. Full license:
  `LICENSES/bdfparser-MIT.txt`. Per-file source/hash/license inventory:
  `tests/data/pcf/SOURCES.json`. Some nondefault swap-unit goldens already contain
  the reference's documented correction of bdftopcf's buggy ink/terminal pass
- `crates/fontpixel/tests/data/pcf_reference.json.gz`: 455 synthetic cases from
  `tools/gen_pcf_cases.py`; 42 valid layout combinations for each of four source
  fonts, 128 Python-seeded random fonts, 113 BDF edge cases, and the 46 copied
  compiler-golden read/rewrite cases. Exact PCF bytes and reconstructed BDF text
  are generated by Python. Gzip has zero mtime; Cargo tests need no Python/tools
- All 139 supplied physical PCF files, all 59 supplied BDF corpus files, the
  Python 107-entry SHA256SUMS and the TypeScript 800-entry random hash manifest
  are exercised read-only by the crosscheck scripts. Real reference fonts are
  not copied into the repository. Results retain file identities and SHA-256

## W1.4 rendering fixtures

- `crates/fontpixel/tests/data/render_reference.json`: 24 project-generated
  synthetic BDF fonts, seed `0xF04D14`, and 1,680 Python-rendered expected
  pixel/dimension or error cases. Generated by `tools/gen_render_cases.py`.
  Project MIT license; reference implementation attribution and hashes are in
  THIRD_PARTY_NOTICES.md. No third-party real font design is embedded
- The corpus mode reads all supplied BDF reference/sample fonts at runtime;
  generated corpus JSON is deliberately temporary and not committed
- `reports/evidence/w1.4/preview.*` and `svg-raster.png` are rendered screenshots
  of `Hello, 世界! 永` from supplied Tong Pixel Sans 14 Large SC (SIL OFL 1.1),
  not redistributed font files. Rendering output does not relicense the font.
  The independent image comparisons record exact RGBA output hashes in
  `tests/crosscheck/render-image-results.json`

## W1.6 YAFF fixtures

- `tests/data/yaff/portable.yaff`: original project-authored MIT synthetic font
  collection (Tom Chen), covering aliases, sequences, unencoded glyphs, additive
  bearings, comments, multiline strings and 256-level pixels.
- `portable.golden.yaff`: canonical Rust output of the above; exact SHA-256 and
  regeneration command are in `tests/data/yaff/SOURCES.json`. Its semantic pixels,
  horizontal metrics and complete label sets are independently crosschecked with
  monobit 0.54.0. This is a deterministic output regression, not an independent
  byte-format oracle (YAFF has no single mandatory spelling).
- The two already-licensed BDF fixtures above are also roundtripped through YAFF
  with exact native model and canonical BDF byte equality; they are not copied.
