## Reproduced issues, fixed before acceptance

1. **Gzip aggregate budget omitted retained wire bytes.** The shared transport
   correctly capped compressed and decoded bytes, but the console parser started
   its model charge with only the decoded input. A limit exactly sufficient for
   decoded input plus model incorrectly admitted the additional retained gzip
   buffer. Both registry readers now seed the budget with the read context's
   complete retained input charge. Direct uncompressed reads still charge once.
   PSF and HEX regressions test rejection below the combined boundary and success
   exactly at it. Independent primary-input and decompression caps are preserved.
2. **HEX comments bypassed the output record cap.** A 257-byte comment record was
   written with a 64-byte record limit. Every comment line is now checked before
   output, including its hash prefix. Exact inclusive boundary tests also confirm
   that the LF delimiter is outside the record length, as on reading.

Both initial regression cases fail against the unchanged candidate; the captured
`reproductions.log` is intentionally a failure record. The final four regression
cases pass. No font pixels, Unicode mappings, charset interpretation or valid
canonical output bytes were changed by these fixes.

## Semantic and malformed-input conclusions

- PSF1 uses little-endian FFFE/FFFF markers, accepts legacy mode 4/5 tables and
  documented interoperable mode 6/7. Its writer emits canonical mode bits.
- PSF2 distinguishes raw FE/FF separators from UTF-8 U+FFFE/U+FFFF. All valid
  scalars, aliases, multiple sequences, single-scalar/sequence-only entries and
  empty mapping entries are preserved. Invalid UTF-8, surrogates, empty sequences,
  truncations, inconsistent geometry and trailing entries are rejected.
- Table-less PSF retains positional legacy codes with explicit unknown charset;
  it does not imply Unicode. The original candidate's correction was verified.
- HEX implements the requested 8/16/24/32 widths, explicit height/descent, scalar
  validation, duplicate retention, deterministic case/newlines and comments.
- Glyph geometry translation/padding, unavailable metadata, unsupported PSF1
  mappings, HEX alias identity/sequences and explicit grayscale thresholding are
  represented in loss reports. Strict registry/CLI writes reject losses without
  replacing existing destinations. PSF1 count padding is explicit, never truncates.
- Resource checks precede relevant input, table, glyph, pixel and output growth.
  Model charges are conservative logical accounting, not a claim that allocator,
  sanitizer or process RSS overhead is exactly equal to the configured number.
