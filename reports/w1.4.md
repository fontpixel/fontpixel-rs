### Performance

Five-call wall-clock medians on the documented shared 9-CPU guest:

| Operation | Rust | Python | Node |
|---|---:|---:|---:|
| 80×25-cell screen (2,000 Tong characters) | **1.006 ms** | 43.804 ms | 9.282 ms |
| drawall, 38,653 effective Tong codes | **29.189 ms** | 1103.633 ms | 423.255 ms |

The actual full-cell outputs are 2560×450 and 512×43,488 in all languages.
Criterion's smaller synthetic screen estimate is **383.42 µs**. PLAN §7's
microsecond-to-millisecond screen goal is met in these measurements. Full method,
CPU/memory/software versions, raw samples and limits are in
[RENDER-REPORT.md](../benches/RENDER-REPORT.md); these are resident APIs, not FFI or
WASM binding results. No later codec/export performance goal is claimed.

## Decisions and known limits

Three decisions were added to [decisions.md](../docs/decisions.md):

1. Retain Python's full-cell mode 0 and width-based vertical wrapping; expose tight
   ink explicitly rather than change compatible defaults. Newlines remain glyphs
2. Borrow packed source rasters and separately bound hash-deduplicated loss
   reports; invalid unchanged BDF hex fails rather than rendering placeholders
3. Deliver native PNG/SVG image export without advertising W2.8 SVG-font/contour
   serialization or W3.3 mapped image atlas codecs. Empty PNG output fails

Native errors are typed Rust errors. Corpus error checks assert failure, not exact
Python exception class/text; full warning semantics, facade state and the complete
SPEC default differential runner remain W1.5. No shaping/bidi reordering occurs.
PNG output is Mono plus a two-entry RGBA palette; gray conversion is explicit and
loss-reported. No new font reader was introduced, so no additional reader fuzz
campaign is claimed. Existing BDF/PCF tests remain green. Reference paths are only
needed for optional external regeneration/corpus checks, not standard Cargo tests.
