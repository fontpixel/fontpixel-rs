# W4.3 detector integration repair, final2

The first frozen NFNT implementation produced an integration ambiguity with generated embedded TrueType fonts. The issue was reproduced with:

`cargo test -p fontpixel --all-features --test vector_raster embedded_outline_detection_not_ambiguous -- --nocapture`

Before the repair, the test failed with `AmbiguousFormat { candidates: ["nfnt", "ttf"] }`. Root's original full gate log is `../local-work/results/fontpixel-rs/phase4-check-final.log`. The first freeze is unchanged at `reports/w4.3-freeze.json`; an exact historical copy is `reports/w4.3-freeze-before-detector-fix.json`. Root reported that the first freeze completed 611 seconds of ASAN fuzzing, 3,898,506 executions, before this independent integration failure was found; that campaign does not validate final2.

Cause: the previous detector promoted a weak MacBinary classifier directly to Certain. A TrueType scaler header `00 01 00 00` also resembles MacBinary's zero version byte and one-byte filename length. Some legal sfnt table directories happen to have zeroes at MacBinary's reserved-byte positions and a nonzero word at the supposed fork-length field. No fork or resource-map validation had been required before claiming the input.

Repair: keep the existing parser dispatch and explicit malformed-input handling, and introduce detector probes that follow the actual bounded structures. MacBinary requires its supported-version CRC where applicable, secondary/data/resource/comment ranges, and a bitmap-bearing resource fork. AppleSingle/Double require supported versions, bounded entries and a bitmap resource fork. Resource-fork detection checks header/map ranges, header copies, type/reference/name/payload ranges and an actual non-name-only FONT or NFNT raster. Bare raster detection validates location/width/optional tables, terminators, extents and defined-glyph presence. No sfnt magic blacklist or sample-specific condition was added. Probes do not create bitmaps or model records; reference work is bounded by the physical map size. Parsing and writing behavior is unchanged.

Validation:

- Standalone NFNT integration suite: 30 passed.
- `cargo test -p fontpixel --all-features --test nfnt --test vector_raster`: 31 NFNT tests and all 31 vector_raster tests passed, including both original failing detection tests.
- New NFNT regression includes 12 generated combinations of ordinary/embedded TrueType/CFF and bitmap widths, plus forged MacBinary and unrelated resource/container records.
- Positive detection tests retain bare NFNT, resource forks/dfont/suitcase, classic FONT naming resources, palettes, extended width offsets, MacBinary I/II/III, AppleSingle/Double v1/v2 and the Apple data-fork variant. Invalid truncated records and malformed raster tables are excluded.
- The 135-case independent oracle crosscheck now additionally checks detection for every case, including the real ufond/fondu and CiderPress2 files. Results: `reports/w4.3-crosscheck-final2.json`.
- Standalone NFNT clippy (lib/test/example), all-features clippy for the NFNT test, and rustdoc pass with `-D warnings`.
- `nfnt-only` fuzz target compiles. The harness now explicitly calls `black_box(nfnt::detect(data))`; this ensures the next campaign covers the detector. Original seed generator now also emits an adversarial nonfont MacBinary lookalike, for 22 deterministic seeds.

All builds use `../local-work/target-w43`, two jobs, dev debug 0 and incremental 0. Final2 production files and evidence are frozen by `reports/w4.3-freeze-final2.json`. Root must rerun the NFNT 610-second campaign and shared final gate on this version; no new long campaign or performance gate was run by this worker.
