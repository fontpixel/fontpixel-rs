# Proposed decisions for coordinator integration (2026-10-04)

* DRCS omitted dimensions are terminal-dependent. Add typed VT320 (default) and
  VT510 profiles; raw matrix data is preserved without simulating device scaling
  or centering. Legacy graphic-set codes remain distinct from Unicode. Pe=1 is
  accepted only when every slot of the selected set is supplied; partial reloads
  need previous terminal state and return an error. Recognize a matching G0 SCS
  suffix without executing it. Emit a final semicolon for native compatibility.
* Keep all embedded source variants under format `c`, with `Family` selecting
  U8g2/LVGL/NetBSD/U8glib/U8x8. LVGL binary is a typed `CContainer`, detected only
  after its mandatory sized table sequence validates. Pre-2019 U8x8 is explicit.
* C source is parsed as literal data. NetBSD's ordinary constant metadata permits
  checked literal addition/subtraction and byte character literals; no names,
  function calls, macro expansion or execution participate in that arithmetic.
* Native LVGL kerning has no core model field: validate pair/class data and emit
  Loss, as for fractional 8.4 advance rounding. Subpixel fonts, fallback chains
  and custom callbacks fail explicitly. Normal field widths constrain emitted
  C structures; signed native heights and counters constrain U8g2/U8x8 output.
* For the LVGL binary container, share bitmap/cmap interpretation with the C
  reader via a bounded internal literal representation. All intermediate storage
  counts cumulatively; files are not compiled by the codec.
* Native generated LVGL files select split initializers with version guards.
  A bounded literal conditional selector assumes the documented v8.3.11 ABI and
  recognizes only LVGL version names/checks and 0/1 font feature guards. It does
  not load headers, expand arbitrary macros or invoke a compiler. Unknown active
  conditions fail explicitly, avoiding accidentally combining both branches.
