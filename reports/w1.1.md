## Decisions and remaining adapter boundaries

All details are in `docs/decisions.md` and `docs/bitmap-model.md`:

- Core keeps both zero-area dimensions; Python row lists lose width at height zero
- Core operations are fallible and mostly return new values; SPEC facade will add
  mutating/chaining signatures, warning emission and <=1 enlargement normalization
- 0/1/2 effect labels use an explicit Gray8 palette; no hidden thresholding
- Ragged legacy pattern replacements are outside the rectangular core invariant;
  W1.5 must preserve any such successful cases needed by the full compatibility
  corpus using its adapter, not falsely claim they already pass or weaken final parity
- Core numeric row export is u64 up to 64 pixels; arbitrary-width exact hex is
  available for binding/JSON adapters. Raw code domains store u32 source numbers,
  including Unicode-tagged non-scalars; per-format writers own legality/loss reports
- Allocation limits are per bitmap/result, not a process-wide allocator quota.
  Codecs must enforce input/model budgets before allocations and validate results
- Raw property records are provenance, not permission to ignore semantic edits
- SVG/outlines, language bindings and real codec/renderer behavior remain in their
  assigned later work items. This does not reduce the final full requirements

## W1.2 integration points

1. Document BDF format mapping before implementing the codec
2. Construct Mono with `from_hex_rows`/`from_bytes` and limits derived from
   `ReadContext::limits`; retain original raw fields/properties and actual read Report
3. `Glyph::new`, explicit codepoints and optional metrics; use no aliases for
   unencoded glyphs and ordered per-glyph properties for alternate/source codes
4. Use `Font::add_glyph` and its exposed duplicate IDs to apply SPEC replacement
   and warnings explicitly; the core itself preserves all duplicate source glyphs
5. Store headers separately from properties; use FontCharset's exact codec and
   report unknown/unsupported maps without guessing
6. Return `FontSet` from `FormatReader<FontSet>` and in-memory `Written` bundles
   from `FormatWriter<FontSet>`; register actual feature-gated hooks in `registry()`
7. Keep combined read/write loss, strict-before-output and all W0 safe-resource
   contracts. `Loaded<FontSet>::into_single` retains diagnostics
