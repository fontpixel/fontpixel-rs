## Findings and repairs

1. FON budget accounting retained encoded bytes between fonts but forgot all
   other source models and accumulated diagnostic reservations. Preflight now
   charges the entire collection and deducts that retained cost from each FNT
   operation's allowance.
2. Container property names/values could allocate arbitrarily large diagnostics
   outside both FNT and FON budgets. They now use the same bounded metadata
   traversal as font/glyph properties, before formatting messages.
3. FONT payloads and NE alignment padding could exceed the resource limit used
   by the reader. Encoded payload and aligned resource sizes are now capped;
   the 15-bit FONTDIR name-offset field is checked before output allocation.
4. All-zero-advance or entirely unmappable FNT sources lost their omission
   report in a generic error. `ReportedErrors` now preserves every per-code and
   per-glyph omission plus `fnt.no_representable_glyphs`. FON retains previous
   reports and gives the failing font its actual collection index. No output
   bytes are returned. Fatal conversion exits 1; representable but lossy strict
   conversion still exits 3.

Five new tests failed on the restored code for these concrete gaps. The corrected
suite has **23 tests** with only `fnt,fon`, including 160 generated cases across
three versions. Further regressions cover repeated NE payloads, 256 byte-slot
aliases, and actual CLI JSON errors with existing destination protection.

## Quiet-window timing

All task-owned builds, crosschecks and fuzz processes had exited before timing.
The existing `windows_timing` example measured five-run medians, 1,000 operations
per run, 256 glyphs at 8×16. This is a local workstation; unrelated desktop
processes were not stopped. Peak benchmark RSS was **16,404 KiB**.

| Operation | Median per operation |
| --- | ---: |
| FNT1 read / write | 43.842 / 103.386 µs |
| FNT2 read / write | 46.450 / 94.048 µs |
| FNT3 read / write | 44.577 / 93.873 µs |
| Eight-font NE read / write | 0.355 / 0.817 ms |
| 1,000 NE roundtrips, 1 / 2 / 4 workers | 1379.365 / 807.538 / 458.662 ms |

Four workers achieved **3.01×** serial throughput. This does not replace the
phase-2 exporter or final project-wide performance criteria.

The first new CLI test incorrectly read failure JSON from stdout; the existing
CLI contract emits it on stderr. The test was corrected to require empty stdout
and validate stderr. No production behavior or assertion was weakened to hide
the failure. Failed and successful run records remain in local evidence.
