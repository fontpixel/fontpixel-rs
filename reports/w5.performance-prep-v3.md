## Repair and regression checks

Log names now append the stream suffix to the complete invocation stem, e.g. `e2-ssfn-original.sfn-rust-1.stdout`. Both names are checked before launching the child, and exclusive `xb` opens prevent overwriting existing evidence. An existing stderr alone also rejects the invocation without creating stdout.

The common validator checks distinct invocation paths and every stdout/stderr hash. Preparation runs it before publishing the manifest; manifest validation checks all preparation command logs again. Smoke and formal measurement run it after every invocation has finished and immediately before publishing their result. Missing, altered or reused logs prevent a successful summary. Multi-record adapters intentionally share a single verified invocation's logs; they do not masquerade as separate invocations.

The six new regressions use **ten real child commands** for `.sfn` and `.asc`, each repeated five times, and verify 20 distinct, intact logs. They also exercise same-path refusal before launch, a stderr-only conflict, independent stdout/stderr tampering, and duplicate invocation detection. Together with the existing 16 unit checks, **22 checks pass**. The new guard rejects the actual archived v2 collisions, not only synthetic inputs.

The other `with_suffix` uses were reviewed: they select actual `.nl2`/`.pbm` companion resources and remain correct. Prepared inspection metadata derives its log path from `command()`'s returned record, so all dotted inspection cases now point to their own complete stem. No hard-coded preparation log consumer required a compatibility workaround.
