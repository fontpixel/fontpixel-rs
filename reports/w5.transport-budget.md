## Implementation and API

`resources::TransportLimits` (also reexported by `formats`) contains `resources: ResourceLimits` and `max_output_bytes: usize`. `WriteOptions::transport_limits: Option<TransportLimits>` defaults to `None`. Built-in registry installs and typed setters use private adapters in `formats/transport.rs` to expose their actual typed resource and output limits. Optional common transport limits intersect every field and cannot enlarge a typed budget. Existing nested SVG, outline/sfnt and embedded/color limits have explicit projections; codecs with no independent output cap remain bounded by their input and aggregate byte caps.

Compression writes directly into a fallible bounded sink. Gzip header, payload and trailer count toward both `max_input_bytes` and `max_output_bytes`; plaintext counts toward `max_decompressed_bytes`. Retained plaintext and compressed vector capacities and the merged report's vector/string capacities share `max_total_bytes`. Buffer growth is geometric, bounded by the remaining budget, with checked arithmetic and fallible reservation. Nested gzip is rejected consistently with the reader.

After compression, the first native byte buffer is released. Only the gzip bytes and original merged diagnostics remain reserved while the same typed native writer validates again under the remaining aggregate allowance. This preserves native profile choices, including a raw writer whose independently configured registry reader has no layout. It never guesses a reader profile from the registry. Original read/write diagnostics appear once; if repeated validation fails with structured diagnostics, a linear comparison removes its already reported writer prefix before appending the new failure. Strict loss rejection still precedes compression. Native output without gzip performs one serialization. Native directory output, including a directory named `.gz`, is unchanged; gzip still rejects multi-asset file bundles.

BDF's older typed writer has no `ResourceLimits` field. Its adapter uses default shared resources plus its actual output cap, validates the model, then checks its self-describing output using the matching BDF reader. Other adapters reuse their native writer's existing validation and readback behavior. Custom `FormatWriter` implementations retain source compatibility through default transport hooks; they should override the budget and validation hooks to account for their own model/profile, or provide explicit common envelope bounds. This is byte-buffer/model accounting, not a process RSS hard limit.

## Coordinator revision final3: retained input capacity

The independent transport harness review identified a decode-side mismatch:
a 14,000-byte gzip payload could grow an internal Vec to 16,384 bytes while the
shared context charged only its 14,000-byte logical length. The decoder now caps
geometric allocation growth at the remaining byte allowance and charges the
actual retained capacity. This preserves amortized growth without an unbudgeted
buffer. Resolved sidecars likewise charge Vec capacity, and the resolver contract
requires capacity, not only length, to fit its allowance.

The new 14,000-byte regression verifies successful capped growth and complete
reservation of spare capacity; a one-byte-too-small budget fails. A separate
resolver regression supplies a one-byte vector with 32-byte capacity and verifies
both cumulative and single-call refusal at the boundary. The final3 targeted
run passes 24 contract tests and 14 transport tests. The all-repository gate and
public transport long-ASAN campaign remain separate coordinator acceptance.
Final1/final2 evidence is retained in the superseded directories unchanged.
