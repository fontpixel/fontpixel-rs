## Implemented

HEX supports 8/16/24/32 columns, fixed default height 16, explicit other heights
and descent, supplementary Unicode/noncharacters, duplicate mappings, comments,
BOM/CRLF, bounded detection/read/write and deterministic canonical text. PSF
supports both headers, 256/512 PSF1 positions, arbitrary positive PSF2 dimensions,
legacy positional maps without a table, full Unicode aliases and multiple or
sequence-only entries, strict UTF-8/LE16 interpretation, gzip transport, padding
normalization, bounded headers/tables/model allocations and deterministic output.

Typed options and registry setters are available in both modules. The CLI enables
both by default; library features remain independent and no production dependency
was added. CLI controls include `--hex-height`, `--hex-descent`, `--psf-version`,
`--psf1-count`, `--psf-unicode-table` and the existing `--gray-threshold`.
All target losses are surfaced through structured reports and strict conversion
preserves existing destinations on failure. PSF1 pads when requested/necessary
with an explicit loss; it refuses excessive glyph count/width/height rather than
silently discarding glyphs. HEX refuses clipping outside its selected cell.

## Decisions and known format limits

See `docs/decisions.md`, `docs/formats/hex.md` and `docs/formats/psf.md`.

- Default baseline is zero; HEX offers explicit descent. Readers derive the
  conventional point-size = cell height / 72-dpi scale to support BDF conversion;
  no physical resolution is claimed to exist in the input file.
- PSF table-less positions remain legacy codes with an explicitly unknown charset,
  avoiding the generic BDF-oriented missing-charset Unicode fallback.
- kbd's PSF1 `FE FF` sequence marker is authoritative. Modes 4/5 imply a table;
  mode 6/7 is accepted as an interoperability extension. PSF2 rejects unknown
  versions/flags and inconsistent charsize. Extended header bytes produce a
  read-loss diagnostic; nonzero unused bitmap bits produce a repair diagnostic.
- PSF1 cannot store supplementary scalars or its FFFE/FFFF marker values. Whole
  unsupported sequences are reported/omitted, never shortened into new mappings.
- Neither format can retain arbitrary names, source properties and all metrics.
  HEX cannot encode unencoded glyphs or sequences; aliases become separate cells.
  Strict writes reject those losses. Gray8 requires an explicit threshold.
- No per-glyph threads are spawned for tiny byte records. Immutable codecs can
  process independent fonts concurrently; the benchmark demonstrates scaling.
  Generic `fontpixel batch` remains W6 scope.

### External oracle limits and PLAN §9.5

The supplied catalogue contains **no HEX or PSF importer/tests**. Its manifest
explicitly excludes HEX (`trevorld--hexfont`) and PSF (Tamsyn). The crosscheck
verifies those facts and runs the actual `test_bdf.py` mini-font assertions at
the BDF boundary through both new formats: encoded characters, aligned pixels,
advances and normalized baseline/cell geometry agree. This is not represented
as testing an absent importer.

Monobit 0.54.0 passes bidirectional standard HEX and ordinary PSF1/PSF2 cases,
including 256/512 positions and non-byte-aligned widths. Its documented observed
limitations are retained in `tests/crosscheck/hex-psf-results.json`:

- It interprets 24×16/32×16 HEX as 16×24/16×32.
- PSF2 sequence markers cause its reader to raise UnicodeDecodeError.
- Its sequence writer emits different alias/sequence semantics.
- Its PSF1 reader treats the specified LE sequence marker as a character.

Complete sequence behavior is therefore checked against the primary kbd grammar
and native property/fixture tests, without changing valid output to accommodate
those oracle bugs. No external tool is claimed to validate cases it cannot read.

### Validation corrections and infrastructure

An initial aggregate attempt exhausted disposable build-cache space. The full
matrix was rerun with `CARGO_PROFILE_DEV_DEBUG=0`, `CARGO_PROFILE_TEST_DEBUG=0`,
`CARGO_INCREMENTAL=0`, `CARGO_BUILD_JOBS=4`. Only this worktree's generated caches
and one explicitly authorized old Phase 2 debug cache were removed; sources,
accepted reports/history and old release binaries were preserved.

Review added output-total and alias-expansion limits and separated gzip wire
limits from decompressed data. A no-loss fuzz assertion caught an overbroad
loss warning on embedded carriage returns in comments, not a codec panic or
memory-safety fault. The regression is fixed and covered. Exploratory runs and
source-changing runs do not count toward final fuzz acceptance.

## Performance

Five-run wall-clock medians, measured after all sanitizer work finished.
Synthetic input contains 38,653 16×16 monochrome cells, one scalar mapping per
cell: HEX 2,705,710 bytes, PSF2 1,389,364 bytes. These are in-memory codec/batch
measurements, not the future real-catalogue W6 benchmark. Output equality is
asserted on every timed iteration.

Host: Intel(R) Xeon(R) Platinum 8370C CPU @ 2.80GHz, nine available logical CPUs,
Linux x86-64, 10,206,504 KiB total memory; Rust 1.99.0 release/thin-LTO.

| Codec | Read | Write |
|---|---:|---:|
| HEX | 20.036 ms | 15.901 ms |
| PSF2 | 11.564 ms | 4.072 ms |

Eight-font parse/write batches (each cell-equivalent input independently parsed):

| Workers | HEX wall time | PSF2 wall time |
|---:|---:|---:|
| 1 | 368.600 ms | 144.688 ms |
| 2 | 177.815 ms | 100.540 ms |
| 4 | 126.378 ms | 75.694 ms |
| 8 | 86.083 ms | 43.791 ms |

Eight workers improve these batches by 4.28× (HEX) and
3.30× (PSF2) without changing bytes or lowering quality.
Fine-grained per-cell parallelism is deliberately avoided; the format codecs
remain dependency-light and thread-safe. Raw timings/environment are in
`timing-verified.json` and `environment-verified.json`. Preliminary measurements
under competing validation load were discarded in favor of these final medians.
