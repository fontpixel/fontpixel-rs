### Resource safety

TOC arithmetic, table sizes/slices, string offsets/counts, metric counts,
encoding indices, per-glyph pixels, model allocations and bitmap extents are
checked before expansion. Only missing accelerator padding beyond EOF is
accepted, matching bdftopcf's overdeclared final table. Required bytes cannot be
truncated. Output tables have an exact size preflight before emission, alongside
raster/intermediate budgets. Compression is disabled for metrics counts beyond
u16; unreachable >16-bit glyph indices/codes are reported instead of wrapped.
The limits bound the model and per-operation buffers, not the entire process's
allocator or caller-owned inputs.

## Decisions and known boundaries

1. Default bytes match SPEC/bdftopcf; nondefault flags reproduce the reference's
   repaired scan-unit sequencing and pad-8 format bit. The compiler's unsafe
   scanunit > glyphpad mixed-order combination is rejected, not reproduced
2. Core aliases share a glyph rather than legacy-map duplication. Input attributes
   survive. A future compatibility facade can expose expanded alias records and
   omit source-only fields where SPEC requires that legacy projection
3. PCF writes canonical tables and recalculated bounds/accelerators. Unknown
   extensions, arbitrary opaque values, unsupported model fields and overwritten
   source semantics are reported; the writer never returns a stored input file
4. PCF has no vertical/y advances. Those are accepted in the model but omitted
   only with a loss diagnostic; Gray8 requires an explicit Rust-API threshold
5. BDF effective records precede unencoded records for SPEC ordering. Dropped
   duplicate codes, alternate markers, out-of-range codes and name truncation are
   reported. The core still retains original duplicate records before conversion
6. monobit 0.54's `_generate_codepoints` / `_create_encodings` reverse the two-byte
   row/column axes. Full-font code comparisons differ at 99 codes for 3x5 and
   311 for Spleen in both directions. Pixel/metric and exact one-byte tests pass;
   Python, TypeScript, bdftopcf and raw PCF layout agree with Rust's mapping.
   No approximate remapping or external-tool modification is used
7. Direct `pcf::read` takes uncompressed bytes. Shared registry transport handles
   gzip limits/CRC/truncation and deterministic `.pcf.gz` output. Multi-strike
   sets fail explicitly instead of silently selecting a font
8. Work remains in W1.4 and later: yaff, full compatibility operations, rendering,
   additional CLI workflows, bindings and the remaining formats

## W1.4 integration points

Use `FontSet` and registry hooks as before; no changes to the generic codec
contracts are needed. Internal `formats::x11` now owns shared X11 projection and
BDF field snapshots; BDF public `source_rows` / `validate_bitmap` are unchanged.
A new consumer must validate source BDF pixels (or explicitly implement and
report its format's own lenient interpretation). PCF source fields live in
`pcf.*` properties/headers, documented in `docs/formats/pcf.md`; don't silently
copy these as portable yaff user metadata. Preserve arbitrary source fields or
report loss, and retain combined `write_with_report` strict behavior.
