# W5.4 Palm OS and Psion/EPOC GDR

Native codecs are implemented with independent external-tool validation. No new runtime dependency is required. All production code is original Rust; no GPL/MPL code or font artwork is copied into the crate. The format research in `docs/formats/palm.md` and `docs/formats/gdr.md` preceded implementation.

## Implemented profiles

| Family | Native input | Native output |
|---|---|---|
| Palm | v1 NFNT; v2 nfnt; ARM afnx; FontSubst afnx; bare resources; PDB record databases; PRC resource databases | All listed layouts; typed container and version choice |
| Palm densities | 72, 108, 144, 216, 288 dpi; all density strikes per resource | Exact standard-coordinate geometry; multi-density source resource grouping retained |
| GrayFont | GrFn v1/v2 and compatible low-nibble revisions; GU14/GU34/GL14/GL34/GR14/GR34; aliased bitmap indexes; uncompressed and scanline compressed images | GrFn v1/v2 with GU34 four-bit images; split resource payloads |
| GDR | compiler layouts 39/40/41/42; all native strikes; sparse inclusive 16-bit mapping sections; v40 inline metrics; other versions' short/long shared metric indexes; repeated and literal row packets | All four compiler layouts; native row compression; bounded section splitting |
| GDR metadata | collection and strike UIDs, aspect ratio, copyright descriptors, typeface associations, synthetic scale factors, multilingual SCSU names, v42 extra vertical metrics | Preserved when representable; same-limit output reread and complete model audit |

Both codecs implement `FormatDetector`, `FormatReader<FontSet>` and `FormatWriter<FontSet>`. Registry and CLI wiring is coordinator-owned. Public options are `PalmReadOptions { container, rounding }`, `PalmWriteOptions { container, version, densities, unicode_as_legacy, gray_threshold, limits, max_output_bytes }`, `GdrReadOptions { unicode }`, and `GdrWriteOptions { version, collection_uid, unicode, gray_threshold, limits, max_output_bytes }`. Palm versions are V1/V2/Afnx/FontSubst/Gray1/Gray2; GDR versions are V39/V40/V41/V42.

## Independent evidence

`tests/crosscheck/w54.py --setup` pins and fetches external source snapshots into `../local-work`, builds the tools, generates original synthetic fonts, and checks complete mapped pixels and metrics. It records every subprocess command, exit code, output hash, source fingerprint, source porting diff and generated artifact hash in `w5.4-oracles.json` and `w5.4-crosscheck.json`. The original 2x6 glyphs, 256-glyph 16x16 fixture, synthetic triangle outline and BDF/GD inputs are MIT artwork created for this task. No commercial device fonts are used.

- MIT monobit 0.54 validates v1, v2, PDB, PRC and real glyphs in a 72/144-dpi resource. Fingerprints cover the installed Palm/NFNT/NFNT2/GrayFont modules; the coordinator independently verified the installed package against the PyPI sdist.
- Alexander Pruss's original FontConv 1.63 validates afnx native bytes, writes independent afnx/nfnt2 fixtures, and `fsconvert` confirms both directions of the FontSubst type change. Original `topalmtext` and `togray` generate all six GrayFont profiles from an original outline. The complete output matrices, bearings, advances and mappings match Rust. Pillow independently unpacks the writer's four-bit GU34 output for both GrFn versions.
- Nokia/Symbian EPL-1.0 `fnttran` writes an independent v41 GDR fixture from original BDF/GD input. Rust recovers every positioned pixel, advance and code; the tool's removal of blank bottom rows is accounted for by comparing font-coordinate ink, not just raw rectangle bytes.
- The unmodified GPL-3.0-or-later EKA2L1 GDR loader validates v39/v40/v41 output, including the dense 256-glyph fixture. An external-only build adds the five v42 header bytes specified by Nokia's runtime; its bitmap and metric decoder is unchanged. This is explicitly an adaptation, not a claim of upstream v42 support. The descriptor shim uses ICU SCSU, and a multilingual name containing a supplementary-plane character and Unicode quote case is checked as UTF-16 units.

The external build adjustments are ABI/header compatibility changes: Symbian's `long`/`streamoff` wire fields become explicit 32-bit integers on LP64; FontConv's `DWord` becomes a 32-bit integer; its obsolete FreeType header is removed and the obsolete parameter tag supplied. Original and compiled-source hashes and unified diffs are recorded. GPL executables remain external oracles and are never linked into fontpixel.

Two monobit discrepancies are deliberately asserted: its afnx reader reverses the one-byte offset/advance fields, and high-density ff/ff missing-slot sentinels become a phantom character after scaling. Original FontConv confirms the library's afnx interpretation. Monobit's incomplete GrayFont module has no complete registered loader, and monobit has no GDR codec; neither capability is claimed here.

## Bounds, losses and native limits

Readers account for retained input, aggregate glyphs and strikes, metadata, decompression buffers, index tables and diagnostics. Palm resources use a prebuilt ordered index, so repeated GrFn lookup and aggregate counting do not scan the full font set per resource. Chained directories are cycle/overlap/header checked; PRC identities are unique; table ranges and raster runs are bounded before allocation. GDR glyph packets are bounded by the next physical bitmap offset, including alias offsets and native empty v40 glyph streams. Writers check dimensions, integer conversions, output size and allocation budgets, then reread every successful output under the same limits.

Writer audit compares original input with actual decoded output and reports each lost/changed field, including names, source properties, order, mappings, aliases, unencoded/default glyphs, bearings, advances, grayscale, synthetic associations and container metadata. Strict behavior uses the shared coordinator-owned report mechanism.

Native representational limits are explicit:

- Palm character codes are 16-bit legacy numbers; using Unicode values requires an option. Density 108 fractional coordinates reject by default; explicit floor interpretation reports Repair. Native output requires exact geometry and cannot represent arbitrary bearings.
- GrayFont specifically permits four-bit bitmaps without color tables or transparency and with optional scanline compression, according to the author's GrayFormat.txt. Other Palm bitmap API compressions and runtime pointer structures are outside this font profile and are rejected. Quantization/padding/orientation changes are audited. Remap-only fonts require external system pixels and cannot produce a standalone FontSet; mixed database remap resources are preserved as opaque records.
- FontSubst output encodes its native resource layout; it does not synthesize a complete four-system-font installer. Standard resource tags follow the selected native encoding. Conflicting resource identities reject rather than returning an unusable database.
- GDR metrics are signed bytes, code values are 16-bit, and shared metric indexes are at most 15-bit. Unicode surrogate codes require explicit native interpretation. External typeface references and synthetic scaling remain preserved associations; external fonts and fabricated scaled strikes are not substituted. Unknown versions/encodings reject.

## Verification and handoff

`w5.4-gates.json` records seven successful commands: Palm's 7 tests, GDR's 6 tests, each standalone feature's all-targets Clippy with `-D warnings`, the combined adapter Clippy, and each standalone feature's rustdoc with `-D warnings`. Tests cover native layouts, exact pixels/metrics, all density identifiers, multi-strike resources, long metric indexes, strict losses, extreme metrics, zero-area inline streams, truncation, aggregate limits, invalid offsets, cycles and duplicate resource IDs.

`w5.4-final-runs.json` records the final adapter build, complete independent crosscheck and separate short ASAN smoke command exits. Fuzz targets exercise bounded read → all native write versions → same-limit reread, and assert complete model equality whenever no Loss is reported. `fuzz/seed_w54.py` embeds only original synthetic wire fixtures, including native external-tool outputs, dense strikes and truncations. Exact final run statistics and hashes are in the freeze manifest.

The coordinator owns the final >=610-second ASAN runs, complete repository gates and five quiet release performance runs. This group's short smoke is not presented as satisfying that requirement. `w54_timing emit DIR` supplies `large-palm.bin` and `gdr-large.bin` (256 glyphs, 16x16); `w54_timing bench FORMAT INPUT` warms up then reports 400 read/write iterations, per-operation microseconds and output size. No concurrent/debug measurement is claimed as performance evidence.

Suggested decision entry: Palm coordinates remain native legacy codes with explicit fractional-density rounding; GrayFont uses its documented resource profile and source properties. GDR preserves native typeface associations separately from raster strikes and uses full Symbian descriptors. Original compiler output and external decoders, including clearly labeled v42 adaptation, validate interoperability independently of writer/reader roundtrips.
