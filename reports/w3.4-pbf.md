## Layout and behavior

Format decisions were written in `docs/formats/pbf.md` before implementation.
Official Pebble runtime sources resolved v1: six-byte header, no hash table,
u16 codepoints/u16 word offsets, and an eight-byte glyph header with advance at
byte seven. V2/v3 instead use byte offsets and five-byte glyph headers. V3
supports raw and RLE4 payloads, 16/32-bit offsets, 16/32-bit Unicode fields,
native alias offsets, missing wildcard diagnostics and retained header extensions.

Independent glyphs with equal pixels remain independent; aliases on one glyph
share their record. Writers reserve offset zero for the runtime's null glyph,
sort each hash bucket and produce deterministic payloads. Reader table coverage,
bucket identity/hash, duplicates, overlapping glyph records, truncation, decoded
pixel counts, table lengths and aggregate allocation budgets are checked.

Native rectangles are retained by default. Explicit `trim` matches the catalogue,
including already-empty rectangles with nonzero offsets. Inherited font advance
is materialized in the output glyph. Metadata, Unicode sequence, gray threshold,
same-limit output readability, removed slot and incompatible property losses are explicit. Empty extension/zero
padding properties and special-property raw provenance also report loss because
those exact property records cannot be reconstructed on readback.

The actual TUMBLED v1.11 `TUMBLED_28_BOLD.pbf` exposed 7,829 RLE records ending
inside a row. Both the official runtime and supplied catalogue floor the decoded
height. The reader follows that rendering and records one `pbf.read.rle_tail`
loss per affected glyph. It never indexes the discarded pixels into the raster.
Strict conversion must reject these read losses before any output is replaced.

## Completed checks

- `cargo test -p fontpixel --no-default-features --features pbf --test pbf`
  passed **18** tests. These include independent hand-packed headers, v1/v2/v3
  roundtrips, raw/RLE and offset widths, aliases versus independent glyphs,
  negative/empty advances, exact 255-run boundary, non-byte-aligned bitmap rows,
  unsigned bucket counts above 127, truncation/overlap/corruption, resource caps,
  source metadata losses, header/padding retention and the oracle/review regressions.
- `cargo clippy -p fontpixel --no-default-features --features pbf --all-targets -- -D warnings`
  passed.
- `RUSTDOCFLAGS='-D warnings' cargo doc -p fontpixel --no-default-features --features pbf --no-deps`
  passed.
- `tests/crosscheck/pbf.py` passed **17** groups in 56.95 seconds (busy-host
  functional validation, **not** a performance measurement). Seven original
  wire fixtures cover all versions, compression, codepoint widths, offset widths
  and aliases, with applicable CLI writer combinations independently decoded.
  Every v3 output also passes the supplied MIT catalogue's `read_pbf` decoder.
- Ten real TUMBLED v1.11 fonts, each **10,978 mappings**, match the supplied MIT
  catalogue's trimmed pixels, bounds, advances, ascent, descent and pixel size:
  **109,780 mappings** in total. All aliases are expanded independently from the
  image sidecar, and pixels are decoded by Pillow rather than by the PBF reader.
  The RLE font's **7,829** read losses are retained in the machine report.
- monobit 0.54 has no PBF handler; no monobit PBF pass is claimed.

Results are in `reports/w3.4-pbf-crosscheck.json`; binary/license provenance in
`reports/w3.4-pbf-upstream.json`; candidate source SHA-256 in
`reports/w3.4-pbf-source-hashes.json`. Upstream font binaries and generated
artifacts stay outside the repository under `../local-work/`.

## Reproduction

Use the oracle environment from `scripts/local-env.sh`, then:

```sh
../local-work/oracles/bin/python tests/crosscheck/pbf.py \
  --binary ../local-work/target-w33-focused/debug/fontpixel \
  --output-dir ../local-work/pbf-crosscheck-new \
  --source-dir ../local-work/third-party/pbf-tumbled-v1.11
```

The directory must not already exist. `--source-dir` is optional; without it the
seven independently generated fixture groups still run. The upstream manifest
pins the v1.11 archive and each of its ten PBFs by SHA-256; its OFL license is
linked and hashed. No upstream font binary or implementation was copied into the
repository.

Fuzz target `fuzz/fuzz_targets/pbf.rs` reads both trim policies, writes all four
version/compression families and requires produced fonts to decode. A zero-loss
write must reconstruct the native model exactly. The writer and output reread use exactly the same
64 KiB input, 4 MiB aggregate and 512-mapping limits. Writer output is capped by
that input limit even when its separate output cap is larger; an allocation-free
preflight shares the reader model budget, including dense aliases. Original corpus fixtures can be regenerated
from `tests/crosscheck/pbf.py::fixture(version, rle, cp_bytes, off_bytes)`; six
version/alias seeds plus partial-tail/header-extension variants were staged only
in ignored `fuzz/corpus/pbf/`.
