# W3.5 HBF implementation checkpoint

Final integrated fuzz, performance and acceptance evidence is consolidated in
[the phase 3 report](phase-3.md). The implementation checkpoint below records
what was verified before the coordinator ran those final gates.

The HBF codec and focused checks are complete. This is **not yet acceptance**:
coordinator-run 610-second final-source fuzz, the global workspace gates and a
quiet five-run performance comparison remain pending.

## Scope

- HBF 1.1 required records, counts, ASCII text, doubled-quote properties, signed
  and unsigned C-style integers, comments, distinct font/bitmap boxes.
- One-, two-, and three-byte coding spaces; dense rank/unrank skips forbidden
  second/third bytes without scanning numeric holes.
- Ordered nonoverlapping code ranges, checked offsets, per-resource cached bitmap
  assets, explicit legacy domains and GB/JIS/KSC GL/GR validation. Unknown vendor
  schemes and CNS planes keep their exact numeric codes.
- Deterministic header plus one/multiple bitmap assets. Native metadata projection
  preserves representable properties; complete font metrics/names/charset
  comparisons report unsupported data. Raw records and changed numeric property
  types receive explicit loss diagnostics. Duplicate native structural metadata
  and invalid zero SIZE fallback are rejected.
- Gray8 requires an explicit threshold and produces a per-glyph loss diagnostic;
  thresholded rows are packed directly into the output buffer.
- Reader and writer account for retained input, metadata, glyph/index estimates,
  cached sidecars, model and output bytes. Writer also checks the matching reader's
  allowance, so a successful bounded output can be decoded under the same limits.

No reference/samples files were edited. No GPL source or external font fixture was
copied. Fixtures and fuzz seeds are original synthetic data derived from the
public specification.

## Verification

[`focused-validation.json`](w3.5/focused-validation.json) records commands, exact
source SHA-256 hashes and the independently tested CLI binary hash.

- 12 dedicated integration tests pass with only the `hbf` feature.
- All-target standalone Clippy passes with warnings denied.
- Standalone rustdoc passes with warnings denied.
- [`crosscheck.json`](w3.5/crosscheck.json) records 2/3-byte sparse ranges,
  multiple files/offsets, Unicode, strict native bundle rewrites, monobit HBF/BDF
  comparisons and catalogue Unicode BDF import. Unknown vendor codes deliberately
  remain Legacy; the catalogue cannot map them to Unicode and therefore drops
  them, while monobit confirms their numeric BDF codes and pixels.
- Bidirectional monobit 0.54 validation discovered two oracle writer defects:
  absent mandatory `HBF_END_FONT` and an absolute bitmap path that its own loader
  cannot reopen. The script preserves the raw output and normalizes only the
  terminator/path before Rust import; bitmap bytes, codes and metrics are intact.
- `fuzz/seed_hbf.py` produces eight original header/sidecar seeds for ASCII,
  Unicode CJK/supplementary, sparse two/three-byte, GB GL, JIS GR and CNS planes.

Reproduction starts with `source scripts/local-env.sh`; focused commands use
`CARGO_BUILD_JOBS=2`. The coordinator owns CLI registry/options and global gates.

Primary authority and all representability decisions are documented in
[`docs/formats/hbf.md`](../docs/formats/hbf.md). No performance claim is made from
the non-quiet debug validation runs.
