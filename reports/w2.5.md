## Delivered

- Public, feature-gated `woff::woff1::{encode,decode}` and
  `woff::woff2::{encode,decode,encode_many}` over complete standalone sfnt bytes.
- WOFF1 per-table pure-Rust zlib, adjustable levels 0–9; compression only when
  smaller; physical table order retained separately from the tag-sorted directory.
  Well-formed sfnt bytes, including DSIG and unusual physical order, roundtrip
  exactly. Nonzero hidden-data loss/structural repairs are reported; invalidated
  signatures are removed with a loss diagnostic.
- WOFF2 mandatory default glyf/loca preprocessing, all 128 triplet classes,
  short/long loca, exact original bbox/bytecode/component/overlap preservation,
  optional hmtx transforms and their null forms; CFF/bitmap/unknown-table transport.
- Deterministic Brotli quality 0–11, required default 11; bounded, ordered
  independent-font jobs and legal single-stream intra-font parallel Brotli.
  Fixed inputs/options are deterministic. No C/C++ codec is a production dependency.
- Editable header version, separately compressed metadata, opaque private bytes;
  explicit invalid-metadata/signature diagnostics and resource limits.
- Budgets cover input, actual decompressed/reconstructed data, tables, points,
  components, instructions and auxiliary blocks. Batch queue/input/retained-output
  budgets prevent repetition or metadata from bypassing per-font bounds.
- Format designs were written before code. `docs/formats/woff.md`,
  `docs/formats/woff2.md`, and appended `docs/decisions.md` record all choices.

## External-oracle findings (not hidden)

1. Google WOFF2/FreeType consult advisory original sizes during reconstruction.
   Normalize input glyph records to four-byte boundaries before recording lengths;
   upgrade short loca when required. The native decoder still honors W3C advisory
   length semantics. This fixed real OTS and last-glyph FreeType failures.
2. fontTools 4.66.1's transformed-hmtx reader can minimize redundant long-metric
   counts without updating exposed hhea bytes. Preserve those input hmtx bytes
   with the optional null transform; decoding retains the full declared count.
3. Stock fontTools repeatedly copies the remaining composite stream per component.
   The full-SC dot correctness run was censored after roughly 20 minutes of total
   validation time without finishing its first equivalence check. An isolated
   read-only memoryview transport adapter calls the unchanged component decoder.
   Its rebuilt glyf bytes are identical on representative simple, composite,
   Latin, hinted, affine, explicit-bbox and overlap fonts. All full-SC assertions
   then pass, corroborated independently by the official Google C++ decoder,
   FreeType, OTS and HarfBuzz. No installed package/reference was changed.
   Adapter observations are NOT labeled stock performance measurements.
4. WOFF1's normative physical-order rule is stronger than glyph equivalence.
   Final review added an order-preserving assembler, explicit signature/hidden-data
   reporting and exact-byte regressions rather than documenting a spec deviation.

## Performance

Complete report: `../benches/WOFF-REPORT.md`; raw data:
`../benches/results/woff-resumed.json`. There are 29 complete groups with five
wall-clock samples each. Tests/builds/fuzzers were stopped before measurements.
CPU: Intel Xeon Platinum 8370C @ 2.80 GHz, nine visible CPUs, about 9.7 GiB RAM;
shared/unpinned VM, Rust 1.99.0 release, brotli 9.0.0. An infrastructure disconnect
split the run into documented segments; incomplete observations were discarded,
resource profiles rechecked, and a native baseline repeated for the post-restart
C++ comparison. The WOFF1-only final fix changes no WOFF2 timing algorithm.

- Full-SC CFF square q11: single-thread 13.507 s / 842,840 bytes;
  four intra-font threads 4.889 s / 842,540 bytes (2.76× observed speedup).
- Full-SC TrueType dot q11: single-thread 45.130 s / 669,740 bytes;
  four intra-font threads 19.360 s / 670,048 bytes (2.33× speedup, +0.046% bytes).
- Dot quality 9: 1.066 s / 830,792 bytes, about 42.35× faster than q11 with
  24.05% more bytes on the same input/segment. Default remains q11.
- Four-font q11 batch jobs 1/2/4: 125.077 / 74.510 / 49.642 s, identical total
  3,025,160 bytes. Four jobs give 2.52× observed throughput.
- Honest stock comparisons: post-restart full-SC dot q11 native 45.772 s versus
  Tong's exact woff 0.6.3 C++ call 34.134 s; native Rust is slower here. Identical
  Latin-dot q11 input: native 1.404 s, C++ 1.166 s, stock fontTools 2.109 s.
  Full-SC CFF q11: native 13.507 s, C++ 12.498 s, stock fontTools 13.784 s.

Do not compare the Latin and SC workloads as a speed ratio. Gains mainly come
from explicit parallelism or lower quality, not a universal Rust advantage.
The full Tong eight-vector/PCF/OTB/locl export ≤40-second target remains a later
integration measurement and is not claimed by this work item.

## Scope and known limits

- These are complete standalone webfont-container APIs, not a claim to rasterize
  arbitrary sfnt into FontSet. Native TTF/OTF/vector-raster/WOFF registry and CLI
  integration, plus TTC/OTC and WOFF2 collection handling, remain W2.7 dependencies
  under the established W2.1–W2.4 layering decision. Collections fail explicitly.
- Metadata is transported opaquely; no XML schema/display validation is claimed.
  No cryptographic validation of a retained DSIG is claimed.
- Transformed zero-contour glyphs with nonzero bounds/instruction programs error
  rather than lose data. One contour cannot exceed 255UInt16's 65,535-point limit.
  Explicit null transforms are available for such unusual source records.
- CFF is preserved without external de-subroutinization. Hint programs are opaque
  and never executed by the container codec. Opaque table semantic validation
  remains the respective sfnt table layer's responsibility.
- Byte/work limits are configurable; parallel compressor working memory scales
  with the selected worker product (hard maximum 64).
- The deliberate WOFF/WOFF2 features add no Brotli/Fontations production dependency
  to BDF/PCF-only builds. See `w2.5/bdf-pcf-dependencies.txt`.
