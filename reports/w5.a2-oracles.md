# W5.A2 external oracle provenance and observed limitations

Scratch root: `$FONTPIXEL_WORK_ROOT/w5a2`. Dedicated virtual environment:
`oracles/bin/python`, Python 3.12, monobit 0.54.0, Unicorn 2.1.4, z80 1.2.0.
Installation logs are `z80-install.log` and `extra-oracles-install.log` there.
The shared oracle and reference samples were not modified. The parent separately
verified the shared monobit distribution against the PyPI 0.54.0 source release.
This worker installed the same published release in its own environment.

* [monobit 0.54.0](https://pypi.org/project/monobit/0.54.0/) — Rob Hagemans,
  MIT, independent raster/metric/codepoint reading and writing. Per-module SHA256
  values are recorded in `w5.a2-crosscheck.json`.
* [Unicorn 2.1.4](https://pypi.org/project/unicorn/2.1.4/) — [GPL-2.0 CPU engine](https://raw.githubusercontent.com/unicorn-engine/unicorn/2.1.4/COPYING) (the Python distribution metadata identifies its bindings as BSD); only the installed package is used. No engine source is copied into
  Rust. Its x86 real-mode core executes the original emitted DOS programs.
* [kosarev/z80 1.2.0](https://pypi.org/project/z80/1.2.0/) — Ivan Kosarev, MIT,
  external C++ Z80 CPU engine. The extension binary SHA256 is recorded. Its core
  executes original CP/M programs with documented USERF service hooks.

Primary documentation was read before implementation and is linked in each
format document. Cached first-party resources include Fontraption `FORMATS.inc`,
Wyse WY-60 Programmer's Guide (1987), Zap Fonts ReadMe and John Elliott's CP/M
XBIOS descriptions; cached hashes are in the crosscheck report. Published
functional signatures/field values are not treated as copied executable stubs.
No downloaded fonts, binary oracle packages, or vendor loader templates are
committed into the repository.

The crosscheck records rather than patches upstream limitations:

* Wyse's fixed oracle reader expands to ten columns without the terminal's repeat
  rendering. Direct load/save fails because the writer accepts eight columns.
  Explicit reconstruction of the stored eight-column model re-emits correctly.
* XBIN's 512-slot oracle writer supplies `has_512_glyphs`, although its header
  field is named `has_512_chars`. Its output carries the 256-slot flag with 512
  payloads. Our reader rejects that inconsistent screen remainder; our native
  512-slot output is independently decoded correctly.
* ZapRedraw's oracle reader treats nonzero table entries as sorted presence,
  ignoring their ordinal values and aliases. An original table with ordinals
  2,1,2 verifies the primary specification and records the oracle mismatch.
* ZapRedraw's oracle writer normalizes Acorn control positions, adding slots and
  changing some native control rasters. The original source mismatch is recorded;
  our reader still matches the oracle's decoded emitted output, including its
  additional slots. This is not reported as a lossless native re-emission.

DOS execution checks cover 8/32-row fonts, INT 10h installation, resident memory
size, text modes 3/7 reinstallation and graphics mode 13h forwarding. CP/M checks
cover PCW/CPC/Spectrum, 8/16-row PSFCOM and Spectrum 512 slots, with lower-memory
bank contents replaced at USERF entry. Installed bytes and unaffected bank memory
are compared exactly. These checks do not claim physical-machine compatibility
beyond the documented CPU/BIOS contracts.
