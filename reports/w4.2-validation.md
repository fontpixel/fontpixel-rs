## Implemented behavior

- PF2: native uncompressed PFF2 sections, 9-byte CHIX entries, absolute offsets and equal-offset aliases, continuous MSB bitmap packing, signed glyph metrics, arbitrary ordered byte sections, and native GRUB joining variant IDs. Unsupported storage flags fail explicitly. Only the public format and published field declarations were consulted; no GPL implementation was copied.
- FONTX2: native ANK and double-byte tables, exact raw Legacy codes, explicit ANK charset declaration, strict Shift-JIS identity, preserved native block order, bounds checks, native writes and sparse range construction. More than 255 runs are coarsened into page ranges with inserted-slot loss diagnostics.
- HZK/ASC: all 25 declared presets, explicit complete geometry override, row/column storage, non-square transpose, partial grids, exact GB2312 or ASCII raw slots, and optional exact glyph count. Headerless input requires declared geometry/preset; it has no registered content detector.
- Actual Unicode/GB2312 or Shift-JIS conversion uses the existing exact codecs and requires `cjk-charsets`. Native raw Legacy transfer remains available without that feature; unknown identities are never guessed. Unmapped and out-of-repertoire source codes receive individual omission entries.
- Fixed-cell metrics derive from cell height at 72 dpi, origin (0,0), ascent height and descent zero. This convention is documented and supports immediate BDF export. PF2 normalizes absent display/global fields as documented in its format note.
- Writers report alias splitting/reordering, metric changes, omitted names/sequences, ordered properties including multiplicity and raw provenance, charset and source-format changes, blank slots, and thresholding. Unrepresentable glyph rasters/fields produce located omissions retained in a fatal report. Output is not returned after a fatal raster error.
- Resource checks cover retained source slots, raster bytes, strings, aliases, recursive properties, mapping growth, working/output allocation, and every report entry within one aggregate writer allowance. Output input/table/glyph/pixel/aggregate constraints are also checked against the reader's allocation estimate. Recursive source properties beyond depth 64 fail explicitly. Successful writer output must read back under the same limits.

Production codecs do not invoke external tools. Shared registration, CLI flags, Cargo features, and public retained-input/slot-count helpers are owned and integrated by the parent task.

## External and catalogue checks

[w4.2-crosscheck.json](w4.2-crosscheck.json) records 26 passing cases and 91,379 verified glyph slots, input hashes, source provenance, tool versions, and the final binary/source hashes. Reproduction:

```sh
../local-work/oracles/bin/python tests/crosscheck/w42.py \
  --binary ../local-work/target-w42/debug/examples/w42_timing \
  --output-dir ../local-work/w42-crosscheck-freeze --fetch-misaki
```

The script uses monobit 0.54 independently in both FONTX2 directions, compares every code/metric/raster, and verifies BDF output with the supplied independent catalogue parser. It covers both original fixtures and all three FONTX files in the author's Misaki distribution. The pinned archive is `misaki_fontx_2012-06-03.zip`, SHA256 `30453aec50689f24fc4eb87a2cd3e89c62fcc7e8fc4f18916cfafeb908afc760`, from [the author's distribution](https://littlelimit.net/arc/misaki/misaki_fontx_2012-06-03.zip), with [M+ unrestricted use/copy/modify/distribute terms](https://littlelimit.net/font.htm#license). The archive stays outside the repository; no font asset is vendored.

PF2 checks use a separate, bit-oriented Python wire decoder, the installed `grub-mkfont` executable, and read-only `/usr/share/grub/{ascii,euro,unicode}.pf2` files. Every raw code and glyph raster is checked, including 162 joining variants in the Unicode font. Catalogue Tom Thumb and Terminus BDF inputs are converted to PF2 and back; comparison against `grub-mkfont` uses advance and ink in font coordinates because GRUB trims bounding rectangles. GPL implementation source is not imported or used as codec implementation.

HZK checks cover 14 distinct geometries with 100 glyphs each, crossing a GB2312 zone boundary, independent grid arithmetic and transpose, monobit raw raster loading, byte-equal native roundtrip, and the catalogue BDF parser. Full supplied OFL TongPixelSans14Large-SC BDF (38,653 glyphs) is additionally converted to HZK16 and FONTX2. CPython strict GB2312/Shift-JIS encoding, with encode/decode equality, establishes the expected source repertoire; every emitted cell is compared using independent font-space clipping. HZK emits 8,178 slots for 7,445 mapped source glyphs, and FONTX2 emits 7,037 slots for 7,037 mapped source glyphs. Unmapped characters and cropping are deliberately reported by the writer.

The catalogue parser is invoked with raw code preservation (`remap_charset=False`) for native Legacy exports. This avoids its separate charset-remapping policy masking or discarding otherwise valid raw FONTX2/GB2312 codes.

## Fuzz and performance handoff

`fuzz/seed_w42.py` emits 21 original deterministic seeds; [w4.2-seeds.json](w4.2-seeds.json) records each hash. Local seeds are in `../local-work/w42-seeds-final/{pf2,fontx2,hzk}`. Targets assert same-limit readback and full native-model equality whenever the writer reports no loss. Seeds include joining variants and invalid bases, reserved storage, aliases, truncated records, table overlap, and row/column geometry variants.

No long fuzz campaign or formal performance run was performed by this worker. The parent task coordinates ASAN fuzz runs of at least 610 seconds and five performance rounds after source freeze. `w42_timing time FORMAT INPUT [PRESET]` provides an in-memory 100-iteration read/write benchmark; it has not been used here to claim performance results. Packed PF2 row conversion, byte/set-bit HZK transpose, cached charset codecs, and populated-map range construction avoid per-pixel or empty-domain scans where applicable.

## Limits of this evidence

- Monobit exposes FONTX and raw codecs but no PF2 or dedicated HZK codec. PF2 therefore uses the public-spec decoder plus GRUB tool; HZK uses raw decoding plus independent grid/transpose checks. No unsupported monobit comparison is claimed.
- There is no single self-describing HZK standard. Presets document the selected conventions and every field can be overridden. No proprietary UCDOS bitmap was redistributed or presented as a freely licensed fixture; print layouts are checked with authored data and the supplied OFL source.
- The frozen manifest is scoped to this worker's files. Complete feature combinations, shared CLI integration, formal fuzz/performance outcomes, and the eventual integrated commit remain the parent task's responsibility.
