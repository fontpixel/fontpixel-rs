# W4.1 native CPX writer: independent read-only review

Review date: 2026-10-04. Reviewer: W4.5 agent, independent of the W4.1 implementation agent.

## Conclusion and scope

No blocking defect was identified in the reviewed native CPX writer. The review covered bounded compression time and memory, NRV2B encoding, overlapping copies, the FreeDOS MODE first-literal patch, executable stub address bounds, and failure diagnostics. This conclusion applies to the exact source versions below; it is not a replacement for the coordinator's integration, sustained fuzzing, or performance gates.

The review did not modify production source, build the project, or run sustained fuzzing. The implementation agent's later eight-case validation and 15 CPI tests were reported separately and are not claimed as independently rerun here.

## Source inspection

- Checked the encoder and decoder agreement for literals, repeated distances, distances 1–256, short and long match lengths, and the standard NRV end marker. The original 8086 decoder intentionally accepts the writer's restricted valid token subset.
- Checked that the first three bytes are literals, meeting MODE's `FF FO` probe, and that a match never references source position zero. By induction, changing the first literal from `FF` to `CB` cannot propagate into later decoded bytes through overlapping matches.
- Checked the 64-candidate search bound and the 58,880-byte input cap. Candidate comparison work is bounded by the selected longest match, whose length advances the input, giving a bounded amortized search cost. The fixed dictionary and stream/output reservations are charged before allocation.
- Checked the `max_delta` relocation inequality: after each token, the output end stays at or below the next unread compressed byte. A whole control word is already buffered when its bytes count as consumed. Forward overlapping match copies and backward initial relocation are consistent with these bounds.
- Checked patched immediates, the 16-bit address range, decoder placement, MODE's 320-byte work area, and stack headroom. The stub clears the direction flag before decoding and preserves the caller's stack balance.
- Checked that resource failures retain the typed `ResourceLimit` error. Other fatal conversion failures retain the source projection diagnostics through the bounded report. This follows the existing error/decision contract; typed resource errors do not attach a separate loss report.

## Independent supplementary replay

The supplementary checks used these existing implementation-agent artifacts:

`/home/chen/githubprojects/fontpixel/local-work/w41/cpx-writer-5/`

For each of the seven cases below, inputs were `<case>-native.cpx` and `<case>-expected.cpi`. The directory's existing `results.json` contains the implementation agent's artifact hashes and separate oracle results. This review read those artifacts; it did not generate or overwrite them.

Two temporary Python programs were executed through standard input using `/home/chen/githubprojects/fontpixel/local-work/oracles/bin/python`, with bytecode writing disabled. Their scripts and output were **not saved to files**. They are independent review supplements, not a checked-in reproducible test runner; no script/result path or hash is claimed for them.

The first program extracted the checked-in machine-code bytes from `stub.rs`. It verified each artifact's bootstrap after zeroing the six patched immediate words, and verified its decoder bytes exactly. It then applied MODE's unconditional-jump and first-literal `RETF` patches and executed the artifact in Unicorn's 16-bit x86 mode. Both memory-read and memory-write hooks asserted that every data access remained within the 59,200-byte MODE buffer or the small caller-stack interval. Execution had an instruction cap and timeout. The program checked the far-return destination and compared all decoded bytes with the expected CPI after restoring the first byte to `FF`. Instruction fetches were not included in the data-read hook; executable placement was also reviewed from source.

The second program independently decoded each artifact's NRV stream, checking declared input/output lengths and exact CPI bytes. For every match it asserted distance 1–256 and a source position strictly greater than zero. After every output token it asserted `decoded_length <= relocated_stream_start + consumed_stream_bytes`. The minimum margin was 50 bytes across the seven cases.

All seven cases passed both supplementary checks. Read/write high-water marks below are exclusive byte offsets from the MODE buffer start; the permitted buffer end is 59,200.
