## Findings fixed

1. A physical source `.notdef` inherited the regional exporter's synthesized
   placeholder bearing and vertical-origin rules. Nonempty TrueType glyph-zero
   ink at x=-2 moved to x=1. Its explicit vertical origin was discarded; an
   unrepresentable non-centered origin could pass without error. Native source
   glyph zero now uses normal source-glyph shape, origin and metric validation.
   The separate regional synthetic placeholder is unchanged. Native empty glyphs
   preserve vertical origins against their actual zero outline top.
2. Native output silently reset underline position and thickness. They now scale
   into post with checked arithmetic/range conversion. Source fields -2/1 at
   100 units per pixel independently decode as -200/100.
3. Outline-only reading bypassed a zero-font budget. The derived output-size
   list now enforces the same max_fonts contract as embedded and collection
   paths.
4. Enabling vector-raster indirectly through a web wrapper suppressed embedded
   detection even when no canonical TTF/OTF codec was enabled. OTB hybrid reading
   now defers only to actually enabled canonical codecs.
5. Selecting the second embedded strike left diagnostics at source index 1 even
   with only one output font. Selection/family deduplication now remaps retained
   diagnostics and omits strike-scoped messages for unretained strikes. Existing
   collection flattening then applies correctly.

All findings were reproduced with focused failing-before tests. Tests also cover
blank glyphs and rejection of non-centered source glyph-zero origins. Independent
FontTools/FreeType/OTS validation exercises square, separate-square and dot native
TTF/CFF exports, including real glyph zero, blank glyphs, hmtx/vmtx, EBDT metrics
and post underlines. No production assertions or sanitizer checks were weakened.

## Review coverage

Reviewed new reader/raster code, expanded TrueType/CFF traversal, phantom and
vertical metrics, native single-font export reuse, registry/CLI dispatch, collection
offsets/shared spans/signatures, WOFF2 collection transforms, aggregate resource
limits, tests and independent oracle assertions. Candidate source provenance was

dropout control. Native projection and low-level table preservation remain distinct.

## Known limits and next scope

- Variable instances, CFF2 and documented unsupported CFF1 programs require prior
  external handling. No hint execution, antialiasing or dropout-control engine.
- Complete anisotropic physical strikes are retained. Sparse anisotropic fallback
  requires explicit square ppem or bitmap-only extraction.
- Native projection retains nominal Unicode mappings, normalized names and pixel
  metrics; arbitrary layout, localized/encoding records and source-table semantics
  are not preserved. Loss diagnostics and low-level preservation APIs are explicit.
- OTS 9.2.0 rejects mixed TTF/CFF/TTF collections with the same maxp failure for
  native and independent FontTools packaging. Homogeneous collections and every
  extracted face pass. Google's independent decoder reconstructs all mixed faces.
- FreeType 2.13.3 rejects non-first CFF faces directly in WOFF2, also reproduced
  with independent Google compression. Reconstructed raw TTC faces load correctly.
- Leak detection is disabled for ASan runs; leak freedom is not claimed. Correctness
  timings are not new isolated five-run benchmarks. Whole-phase export/performance
  gates and W2.8 SVG work remain outstanding.

No source, reference/sample file or prior evidence was deleted. All 690 protected
