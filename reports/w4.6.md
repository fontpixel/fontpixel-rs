# W4.6 Amiga / GEM / SNF 实现与验证记录

日期：2026-10-04。工作分支由主代理管理；本 worker 未执行 checkout、暂存或提交。SNF 在本批完整提前实现，不再留作 phase 5 的重复项目。本记录是 worker 的定向验收，**不代表第 4 阶段验收完成**；冻结后的正式 ASan fuzz、全 workspace 验证和五轮性能测量由主代理统一执行。

## 交付

- `amiga`：原生 `.font` / tagged contents、多个尺寸的 `ReadContext` sidecar、`OutputBundle` 输出、CODE/DATA/BSS hunk 与长/短 relocation、单色和 1–8 plane ColorTextFont。代码永不执行 hunk 指令。
- `gem`：88 字节 GDOS 头、独立整数/位图 word 字节序、横向 pre/post offset、packed strip、差分 RLE 解压、linked compressed sections；输出标准未压缩文件。
- `snf`：X11 SNF v4、双版本戳 endian、机器顺序 bitfield、二维稀疏字符表、属性/字符串、可选 ink metrics，完整 ByteLayout 写出。历史输入缺少位图布局时要求调用者明确指定；默认输出携带合法私有 X11 布局属性，可直接读回。
- 公共 `formats::legacy_common` 由主代理注册，避免多模块重复声明。三个 feature 都能独立编译。
- 新 typed options、registry codec、CLI 接线由主代理维护；本 worker 提供模块、测试、文档、crosscheck adapter、原创 fuzz targets 和种子生成器。

生产代码没有 Python、monobit、外部字体工具、unsafe 或对文件系统的隐藏访问。单色读取与合并使用 packed rows。限额预检覆盖输入、输出、位图、表、glyph/model 元数据、重复源克隆与报告，Amiga 各 strike 共享预算；GEM 链接节限制数量并拒绝回环；SNF bitmap offset 限制为 24 位。writer 在同一原始限额下解析自己的输出后才返回。

## 语义与损失合同

各 writer 对实际生成文件的读回模型逐字段审计：字体全部 metrics、names/localized、charset、ordered headers/properties、glyph 顺序、移除 slot、码位/alias 顺序、Unicode sequences、glyph name/metrics/bitmap/properties、数量及容器属性。格式 provenance 不构成字体语义损失。任何不可表达数据均逐项记录；后续 fatal 保留先前 mapping omissions，Amiga 多 strike 的 font_index 也保留。strict 返回错误，不返回任何 assets。

GEM 不从平台名称猜编码；Unicode 数值转换需要 `unicode_as_legacy`。Amiga 明确 ISO-8859-1，Unicode U+0000–00FF 可以按 typed option 映射。SNF 只有明确 ISO10646-1 声明才产生 Unicode。Mono 目标 Gray8 输入需要显式阈值。

Amiga 彩色索引不冒充 Gray8：灰阶按 index 范围映射 coverage；RGB12 palette 以整数 BT.601 luminance 映射 coverage，非中性色 read report 标 loss。原 palette / indices 保存在 opaque properties，未编辑时可精确回写索引；编辑后匹配最近 coverage，改变的 bitmap/缓存均进入损失报告。运行时指针、hunk 指令与链表工作字段不进入字体模型。

## 定向验证

最终命令与 exit code：[`w4.6-validation.json`](w4.6-validation.json)，完整输出：[`w4.6-validation.log`](w4.6-validation.log)。构建使用 `CARGO_TARGET_DIR=../local-work/target-w46`、`CARGO_BUILD_JOBS=2`、`CARGO_PROFILE_DEV_DEBUG=0`、`CARGO_INCREMENTAL=0`。

- 19 个测试通过：Amiga 7、GEM 8、SNF 4，含三个 proptest 随机字体 roundtrip；独立 wire fixtures、每个字节边界 truncation、受限 mutation、aliases/slots/metadata 灰度损失、strict、partial loss 后 fatal 和资源限制。
- 每种 feature 单独执行 library+对应 integration test 的 Clippy `-D warnings`；三个 feature 组合也通过同样检查。
- 组合 Rustdoc `-D warnings` 通过；全部 worker Rust 文件 rustfmt check 通过。
- 三个 fuzz binary check/build 通过。原始 12 个 wire seeds 做了无 sanitizer 的初始化 smoke：Amiga 2、GEM 6、SNF 4；这不是正式 fuzz 验收。Targets 都对成功 writer 结果用相同 limits 重新读取，报告无 loss 时断言整个 FontSet 相等。Amiga 使用返回 bundle 的 resolver，默认保留 color/gray 和显式 threshold 两种路径均可进入。

## 独立交叉验证与合法样本

[`tests/crosscheck/w46.py`](../tests/crosscheck/w46.py) 通过 8 组双向比较，结果与每个输出 SHA-256 在 [`w4.6-crosscheck.json`](w4.6-crosscheck.json)。比较绝对坐标 ink pixels 与 advance，不只比较 glyph 数量。

- Amiga、GEM：monobit 0.54 writer → Rust reader，以及 Rust writer → monobit reader。
- SNF：monobit 没有 SNF handler，使用根据 X11 `snfstr.h` 编写的独立 Python encoder/decoder，分别验证大小端输入及 Rust 输出；没有把自己的 writer 当唯一 oracle。
- 输入各包含一个原创 2-glyph 字体和 MIT 许可 Tom Thumb 的 95 个 ASCII glyph。Tom Thumb 源 SHA-256 为 `d07edd9d110a5106d6a19c6bac4897650f1b1a0fba2c6923b75e51dcc2b7ea0b`。源文件保持只读；没有将第三方字体字节提交入库。原 BDF 的 CHARS 声明与实际数量不一致，monobit 会警告；显式选择 32–126 范围。Amiga oracle 输入先进行合法水平 cell normalization，确保符合该文件格式的共同高度。

GEM monobit 0.54 对未压缩数据忽略 standard-form flag，little-endian 输出清除此标志但保持标准 raster bytes；本实现按格式标志解释。交叉验证使用其 big-endian writer，非标准历史输入可通过显式 bitmap word order 读取。monobit 还会写 odd stride，本 reader 接受，writer 输出 word-aligned。独立 compressed fixture 和 linked-section fixture 不依赖 monobit 的 writer。

## 来源、许可与边界

实现前已编写三份格式文档并据 primary layout 确定偏移：[`amiga`](../docs/formats/amiga.md)、[`gem`](../docs/formats/gem.md)、[`snf`](../docs/formats/snf.md)。来源 URL、实际抓取内容 SHA-256、oracle Python 文件和样本哈希在 [`w4.6-sources.json`](w4.6-sources.json)。

- AmigaOS/MorphOS header：仅使用声明中的格式事实，不复制保留版权的实现。
- GEM VDI / FONT_HDR 及 John Elliott GEM 文件格式说明：格式事实；没有复制 GPL 实现。
- X11 SNF：DEC 1987 / X Consortium 1994 的 permissive layout 来源；独立 Rust 和 Python wire codec。
- monobit：MIT，`amiga.py` 与 `gdos.py` 作为字段/算法/互操作参考。当前安装版 MIT LICENSE 是 Rob Hagemans 2019–2023，文件头分别注明 2019–2026 与 2022–2026。共享 THIRD_PARTY_NOTICES 由主代理管理。

有意的格式边界：只处理 bitmap diskfont，不支持 IntelliFont 轮廓数据；GEM writer 不生成压缩流，flatten linked sections 的 opaque metadata 若不能保留会报告；SNF 没有可证明的历史 bit/scan order，未标注输入必须显式 ByteLayout；彩色 Amiga 转成模型 Gray8 无法保留 chroma 的显示语义，读取即报告。各项边界已在公开文档与 typed options 中说明。

`fuzz/seed_w46.py --output DIR` 可重建 12 个原创 seeds；`w46_timing` example 提供 dump/write/bench adapter。worker 未进行正式性能宣称，未启动长 fuzz。正式阶段验收以主代理统一结果为准。
