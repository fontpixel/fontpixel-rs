# W5.C1 — six historical printer/workstation codecs

Owned source and harness are frozen at manifest SHA-256 `e801ffe1a048ee713fdafa15ae229ce656a1efaef97071104b48835b8707b361`. The28 per-file hashes, source-document hashes, external oracle hashes, raw artifact hashes, validation logs and fuzz summaries are in [w5.c1-freeze.json](w5.c1-freeze.json). Work stayed on the shared checkout; no branch/worktree/commit operations were performed. W5.3 frozen sources were not modified.

Native bounded readers and writers now cover Daisy-Dot I/II, III and magnified fragments; Polyprint; the observed Printshop contiguous-raster profile; Tasprint48k/QL, +3DOS, CPC and PCW127/128; PXL1001/1002 with optional TFM; and Signum E24/P9/P24/L30. Every codec has typed `*ReadOptions`, `*WriteOptions`, `*Codec`, `read`, `write` and `detect` APIs. No production dependencies were added. Private wire/projection helpers live in `formats/daisy/common.rs`, registered by root as `historical_common`; existing legacy validation, selection, grayscale reduction and field-level loss audit are reused.

Each of the six features independently passed its integration tests, Clippy `-D warnings` and rustdoc `-D warnings`. Combined Clippy including the adapter passed, as did owned-file rustfmt. Commands, exits and log paths are recorded in [w5.c1-validation.json](w5.c1-validation.json); final logs are hashed in the freeze file.

[Crosscheck results](w5.c1-oracles.json) contain24 original MIT byte-authored fixture cases, covering sparse and full code tables, platform variants and both PXL alignments. Native reads and native outputs match independent monobit0.54 on legacy codes, nonempty rectangles, absolute ink coordinates and advances. Tasprint additionally has five monobit-writer/native-reader cases. The generated layouts do not call native encoding code. PXL's monobit reader exposes fractional pixel `scalable_width`, so device advances are checked against its rounded value and the per1000 scalable advance against the independently authored fixed-point width. Zero-area rectangles are normalized only for comparison. PCW127 uses the documented127-slot form; monobit hardcodes128, so its independently decoded padded form is compared after removing the synthetic final slot.

A real John Elliott Polyprint `002.fnt` (144 glyphs,12288 bytes) also passes native-read and native-write comparisons. Its64-byte CP/M record trailer established an additional real-file layout. The fixture stays outside the repository because font redistribution permission is not established. Source URL and SHA-256 are in the oracle report.

## Scope and real limitations

- All positions remain legacy codes; Unicode-to-position mapping and Gray8 reduction require explicit options. Writers require at least one representable code position. Names, metrics, aliases, removed codes, source metadata and glyph geometry are compared with an actual native reread; strict mode rejects Loss.
- Daisy permits at most128 stored rows across four resources. The manual forbids graphics bytes13/155. Reading retains them with an explicit diagnostic; writing requires `allow_control_bytes`. Underline placement supplies an inferred baseline. Missing sidecars and mismatched widths fail.
- Polyprint accepts the12224-byte payload and the observed12288-byte CP/M record form. Opaque trailer/header/character fields survive writing. The double-height flag and baseline conventions follow the independent reader's documented inference; callers may override input baseline. No character-set guess is applied.
- Printshop's proprietary offset and kerning semantics remain unestablished. Its native implementation covers the independently observed contiguous-raster profile. Existing offsets survive when dimensions are unchanged. New/changed layouts use glyph-section-relative offsets and emit `printshop.write.offset_convention` Loss. Original proprietary-application interoperability is not claimed.
- Tasprint48k/CPC may contain multiple complete strikes; +3/PCW are single-strike outputs. +3DOS/AMSDOS headers and checksums are checked. Ink in columns outside declared width remains only in original bytes and produces Loss. Both PCW127 and128 forms are supported. Headerless lengths never yield a registry detector match.
- PXL1001 is specified by Fuchs; the1002 extension is corroborated by the independent monobit reader. Device metrics are explicitly rounded while fixed-point values remain properties. Optional TFM applies widths; full TFM ligature, kern, height/depth/italic and parameter semantics are retained as raw data with explicit layout Loss. New TFM emits only supported width semantics and valid zero metric tables.
- Signum uses authoritative offsets, including aliases/reordering. E24 width is advance; printer width is stored byte width and advance is inferred from trimmed ink. Editor/printer baselines follow observed conventions and are overridable. Opaque fields are preserved; unknown printer spacing semantics are not invented.
- Polyprint has no auto detector. Printshop is at most Possible. Tasprint's registry detector only considers headed +3DOS/AMSDOS forms; naked48k/PCW require explicit selection. Daisy/PXL/Signum use explicit signatures. Supported filename evidence is `.nlq/.nl2/.nl3/.nl4`, Polyprint `.fnt`, Printshop `.pnf/.psf` (the latter conflicts with console PSF), Tasprint fixed names `tasfont0`/`font.obj`, PXL `.pxl`/`.<digits>pxl`, and Signum `.e24/.p9/.p24/.l30`.
