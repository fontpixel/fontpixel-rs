## Delivered

- Feature-gated native SVG 1.1 font detector, reader and writer, with registry
  configuration and CLI `convert`/`info`/render integration. CLI defaults enable
  SVG; BDF/PCF-only library builds do not acquire XML/path dependencies.
- Deterministic merged-square, separate-square and true-circle SVG paths, complete
  text images and a single-glyph image API. Typed RGBA colors preserve disjoint
  paper/ink alpha. CLI exposes shape, diameter, scale and explicit raster size.
- Unicode scalars, aliases, ligature sequences, unencoded and blank glyphs,
  missing glyph selection, negative bearings and effective horizontal/vertical
  metrics. Native namespace attributes retain the original raster rectangle,
  pixel size and alias identity without storing a second hidden bitmap.
- General SVG path commands, relative/smooth segments, cubic/quadratic curves and
  elliptical arcs; upward-facing font coordinates, horizontal origins, explicit
  ppem or exhaustive automatic 4–64 ppem grid detection. Filled paths share the
  existing nonzero-winding pixel-center rasterizer.
- Pre-allocation XML token limits, DTD/external/active content rejection, bounded
  arc normalization, per-glyph streaming geometry, aggregate work/raster/model
  budgets, alias consistency checks and rejection of clipping native bounds.
- Structured metadata/charset/grayscale/raster-projection loss diagnostics, strict
  atomic output, and explicit error when a required CJK charset feature is absent.
  Historical bdfparser SVG compatibility serializers remain unchanged.

## Findings and decisions

1. A full CJK separate-square font exposed avoidable retention of every expanded
   path. The reader now makes a bounded first grid pass only when necessary,
   then parses/rasterizes one glyph at a time. A small-budget regression verifies
   many individually bounded glyphs do not accumulate expanded geometry.
2. XML DOM limits were too late for an enormous attribute/namespace list; token
   preflight now enforces counts/depth/bookkeeping before DOM allocation and its
   duplicate-name checks. Arc radius correction/subdivision is bounded before
   svgtypes/kurbo creates its intermediate segment buffer.
3. A generic-curve oracle initially sampled half a supersample to the right/below
   the mathematical center. The independent Cairo viewBox is shifted by half a
   subpixel so the sampled pixel is centered exactly. A 4× resolution check
   independently confirmed this harness issue. No Rust geometry assertion was
   weakened. Earlier failing oracle logs are retained; final evidence uses the
   corrected script. Initial comparison harness corrections also distinguish BDF
   BBX pixels (`draw(1)`) from storage-byte padding (`draw(2)`).
4. The first final parity pass straddled a source-dirty-state change from added
   tests; it returned zero NEW differences but is not the final gate. A fresh
   stable-fingerprint run is retained as the final parity evidence.
5. Monobit 0.54's SVG adapter targets single-stroke fonts, requires optional
   numeric font-face fields, and searches descendants rather than a glyph's own
   standard `d` attribute. Its recorded attempt fails on an optional missing
   underline field. It is not claimed as a successful filled-font oracle.
   FontTools, Cairo and the supplied independent producer provide that coverage.
6. Disk pressure was resolved by removing only 86 verified old, reproducible
   `.rlib`/`.rmeta` caches (1,229,168,474 bytes), with a retained cleanup manifest.
   No source, executable evidence, prior report, generated validation output or
   durable delivery ZIP was removed.

## Limits and next gate

- This is a path-filled SVG-font reader, not a general SVG document renderer.
  CSS, transforms, strokes, graphical effects/children, external references,
  active content and contextual glyph selectors are rejected explicitly. Kerning
  and unrepresented metadata are reported as loss.
- SVG 1.1 font embedding is historical and unsupported in many modern browsers.
  Standalone image outputs use paths and need no installed font.
- Arcs are normalized to cubic Béziers by svgtypes (its design-unit tolerance is
  0.1); exact center filling applies to those curves. Extremely anisotropic arcs
  can be conservatively rejected by the pre-allocation radius bound. There is no
  antialiasing or hint execution in font import.
- Full CJK circular SVG output is about 100 MiB and exceeds the default 64 MiB
  input budget. The library caller can explicitly raise its input limit; the
  full-font oracle does so. The CLI retains its existing common input-byte cap.
- Original source headers/properties, scalable/ABC/image metrics and charset
  identity are diagnosed when not represented. Native roundtrip guarantees apply
  to the documented SVG/native fields and visible raster, not all foreign metadata.
- OTS, FreeType and HarfBuzz OpenType container gates do not parse standalone SVG
  fonts; the accepted W2.7 implementations are unchanged. Whole-phase export and
  performance gates remain with the phase-2 coordinator. No new isolated five-run
  benchmark is claimed by these correctness checks.
