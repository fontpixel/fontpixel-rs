# W5.1 — General bitmap-font survey

2026-10-04 · accepted implementation baseline `5c79f81` · survey complete

**53 new canonical IDs are required:** 42 families from monobit and 11 additional families from the selected primary sources. Together with the original 46 IDs this gives 99 canonical IDs. All 53 have an implementable native read/write path. Missing upstream writers or historical samples do not justify dropping a format.

The complete per-format wire scope, variants, source links, independent oracle, sample permission, complexity and implementation group are in [w5.1-survey.json](w5.1-survey.json). [w5.1-survey-check.json](w5.1-survey-check.json) records reproducible coverage checks. This report and the JSON describe requirements, **not completed production codecs**.

## Reproducible survey boundary

The bitmap input/output catalogue in Bits'N'Picas was checked separately, followed by the cited primary developer documents for Qt QPF/QPF2, SSFN, Processing VLW, PFR, Hangul composition, Palm, GDR and embedded C formats. This is not a claim to have discovered every unpublished or future format worldwide. Newly documented general formats should extend the inventory.

## Decisions and existing-ID gaps

Aliases are not new codecs. Conversely, an existing suffix or similar header does not establish native support. A format may have multiple explicit variants under one ID, but each needs real read/write behavior and independent evidence. A read-only monobit decoder does not waive fontpixel's writer requirement.

The accepted phase-4 baseline had **38 readers and 37 writers**: `snf` was already done; `hanfont`, `iigs`, `vfont`, `fzx`, `figlet`, `palm`, `gdr`, `drcs` remained P3, and `color` still needed its writer. This historical snapshot does not describe concurrent phase-5 edits.

| Existing ID | Required completion / expansion |
|---|---|
| `hanfont` | Compose all 11,172 modern Hangul syllables using Johab 8×4×4 variant rules; retain native components for optional export. |
| `palm` | FontFont PDB, PRC, standard NFNT, extended nfnt/afnx density records and documented GrayFont resources require explicit variants. |
| `gdr` | Versioned EPOC/Symbian font stores, collection metadata, indexes, metrics and bitmap compression; fnttran/independent loader validation. |
| `c` | U8g2 and LVGL are original P3 requirements. Add NetBSD structured headers, and separately track legacy U8glib/U8x8 profiles; LVGL binary tables are a container/profile of that family. |
| `image` | Add filename-indexed, one-image-per-glyph directory bundles (`imageset`); an atlas with a private sidecar is not equivalent. |
| `nfnt` | Add BinHex fork transport. Existing Mac resource wrappers can host the new fbit/HFNT family but do not decode those payloads today. |
| `iigs` | Add BinSCII transport with bounded checksums/segments, beside the original IIgs font codec. |
| `bmfont` | Add the Jam3-style JSON descriptor variant supported by monobit; baseline text/XML/binary-v3 support does not include JSON. |
| `raw` | Add strike-major, bit-aligned and column-major layouts where RawLayout cannot express them; keep existing presets and C64 .64c prefix behavior. |

**Hanfont is composition, not just component storage.** Johab 8×4×4 uses 160 leading + 88 vowel + 112 trailing cells, selected according to the syllable's L/V/T classes and OR-combined into 19×21×28 syllables. Test every combination against an independent table-driven reference from the [published composition rules](https://www.unifoundry.com/hangul/hangul-generation.html). Arbitrary raster syllables are not uniquely factorable; preserve native components and report incompatible arbitrary input instead of inventing a decomposition.

Palm's [FontTypeV2 documentation](https://palm.wiki/development/docs/601/PalmOSReference/Font.html#1000130) defines extended densities; PDB/PRC envelopes and endian variants are separate coverage obligations. The release's experimental, **unregistered** GrayFont helper is not an oracle-support claim. GDR has an official [fnttran compiler interface](https://docs.huihoo.com/symbian/s60-3rd-edition-cpp-developers-library-v1.1/GUID-35228542-8C95-4849-A73F-2B4F082F0C44/html/SDL_93/doc_source/ToolsAndUtilities93/FileConversionUtilities-ref/Tool_Ref_Fonts_Fnttran.guide.html), published SDK field definitions and independent loader tooling; version differences are not grounds to dismiss it as undocumented.

The [U8g2 format](https://github.com/olikraus/u8g2/wiki/u8g2fontformat) requires compressed glyph decoding and Unicode jump-table handling. [LVGL's format](https://github.com/lvgl/lv_font_conv/blob/master/doc/font_spec.md) adds cmap forms, bit depths, RLE and kerning. Merely parsing a C byte array does not implement either family.

## Implementation groups

Complexity labels in the JSON are structural, not time estimates: **S** one compact layout/text grammar; **M** multiple tables, sidecars, variants or raster projection; **L** nested resources, compression/version/ABI details, substantial metrics or executable-loader validation.

| Group | Area | New IDs |
|---|---|---|
| A | Text, terminal streams and compact legacy envelopes | `bbc`, `comfont`, `consoleet`, `dosstart`, `drhalo`, `edwin`, `grasp`, `hrcg`, `mkwinfont`, `pcr`, `plus3dos`, `psf2txt`, `writeon`, `wyse`, `xbin`, `zapfont` |
| B | Operating-system bitmap resources and console fonts | `beos`, `geos`, `gpi`, `oberon`, `pcgeos`, `symbos`, `vtfont`, `wsfont` |
| C | Historical publishing, printer and workstation formats | `catalyst`, `chiwriter`, `daisy`, `dashen`, `hppcl`, `polyprint`, `prebuilt`, `printshop`, `pxl`, `riscos`, `signum`, `tasprint`, `xerox` |
| D | Apple resource families and Qt prerendered fonts | `fbit`, `lisa`, `mgtk`, `qpf`, `qpf2` |
| E | Atlas, device and compact modern bitmap formats | `pilfont`, `sfont`, `rockbox`, `u8m`, `cybiko`, `playdate`, `hmzk`, `sbf`, `ssfn`, `vlw`, `pfr` |

Group A can begin with eight single-file codecs: **dosstart, edwin, mkwinfont, psf2txt, pcr, plus3dos, drhalo, writeon**. Continue with `grasp`, `bbc`, `wyse`, then `consoleet`, `hrcg`, `xbin`, `zapfont`, and `comfont` in increasing complexity.

`consoleet`/`imageset` need a bounded directory or known-file-list resource interface. `comfont` combines seven native executable envelopes; writer acceptance requires independently authored or explicitly licensed working stubs and external emulator checks. A recognisable but inert prefix is insufficient. Playdate combines standalone FNT/base64-PNG, FNT+PNG and compiled PFT as distinct variants; source-font tests cannot establish compiled PFT support.

## Raw equivalents, wrappers and ancillary data

VGA F08/F14/F16, C64/64C, Spectrum/MSX, DEGAS/Warp9, Genecar and CHET raw cells share the `raw` family with explicit geometry/code maps. **64C is already implemented by C64Prg**, including its two-byte load address. **Harlekin III is a real layout gap**: 512 8×8 glyphs share one 4096×8 strike, which the existing contiguous-cell RawLayout cannot express. +3DOS has a separate native header and is a new family; CP/M UDG loaders belong to `comfont`, not ordinary raw UDG cells.

All monobit wrappers are accounted for below. Generic archives/compression/byte encodings contain arbitrary files and have no intrinsic glyph/metric schema; they are **not independent bitmap-font IDs**. This classification does not claim all generic transports are implemented. Font-resource containers carrying forks remain explicit codec/container obligations.

## Explicit exclusions

Monobit's stroke table was checked row by row: `borland`, `hurt`, `gimms` are nonbitmap stroke formats; `yaff`, `svg`, `win`, `fon`, `dosstart` refer here only to their stroke branches. Their bitmap or explicitly planned SVG paths remain in scope. This applies PLAN §1.3's general nonpixel vector-editing exclusion, not a convenience exclusion of a difficult bitmap format.

The private game exclusions are exactly those directed by PLAN §1.3: Might and Magic VI–VIII/Heroes III FNT, Daggerfall FNT, Fallout FON/AAF, Blizzard FNT, Infinity BAM, and ZDoom FON1/FON2. General desktop software, printer/device SDKs and shared development formats are retained: in particular Catalyst, Print Shop, Playdate, Cybiko, SFont and BMFont are not private-game exclusions.

## Sample rights and acceptance limits

Each new-family record identifies a permitted specimen or explicitly states that no ready-made native specimen with verified rights was found. A missing native specimen is an evidence gap, **not a deferment**: use project-authored MIT glyphs or a verified public-domain seed; encode them with the independent oracle when available, otherwise make an original fixture assembler from documented fields and verify with a separate decoder. Self-roundtrip alone is insufficient.

Monobit's MIT code license does not license all its font specimens. Alpha Palm/SymbOS fonts have commercial-use conditions and are not adopted as permissive fixtures. Free glyphs in a COM file do not license its loader stub. Konatu is CC-BY-SA-3.0, not MIT. Dr. Halo's historical stub bytes need separate rights checking. In contrast, System Fixed is Apache-2.0, Oberon MIT, Spleen/Gallant BSD and Terminus OFL; Computer Modern has Knuth's naming/license conditions. Individual source notices remain authoritative.

Implementation acceptance remains: native reader and writer per accepted variant; typed options and bounded structure detection; per-glyph/metric/metadata loss reports with strict no-output behavior; one cumulative resource budget across sidecars/decompression/rasters/diagnostics; independent pixel/metric comparisons; original or licensed fixtures with fetch hashes; reader fuzzing; and the parent stage's full checks/performance protocol. Where an upstream decoder is empirical (notably Catalyst and Dashen), test offset/layout variations independently and preserve unknown fields instead of treating one historical specimen as the complete specification.

No production implementation, shared registry/Cargo/CLI change, git operation or heavyweight run was performed by W5.1. The coordinator owns integration of the inventory into FORMATS and subsequent implementation work.
