# W5 public-path review and cumulative CLI budget repair

Reviewed on 2026-10-04. Initial scope was read-only inspection of CLI `assets.rs`
and `image_formats.rs`, library `resources.rs`, `formats/mod.rs` and
`formats/registry_codecs.rs`. The conversion loop in CLI `main.rs` was inspected
as a caller. Root subsequently assigned the cumulative model-budget repair to
this worker; root owns the other three fixes and `main.rs` integration.
No format codec or frozen W5.2/W5.D implementation was edited.

## Findings and disposition

1. **Directory writes silently retained obsolete glyph files.** The original
   persistence loop only inspected/replaced the new bundle's listed assets. An
   existing directory with two glyph files could receive a successful one-glyph
   write while retaining the second glyph, changing subsequent decoding. Root
   added an exact directory-member preflight: extra files, nested directories
   and notes reject the write before staging; complete existing bundles can
   still be replaced. Root reported the new regressions passing. Independently,
   this worker included the actual `assets.rs` module in an external test crate
   and ran all eight filesystem tests successfully after that fix. This verifies
   the original module, not a reimplementation.
2. **Shared gzip output bypassed native writer limits.** The original
   `encode_transport(OutputBundle)` had no limit parameter. A configured raw
   1×1 glyph with `max_input_bytes = 1` wrote one native byte and read back under
   the same limits. Naming that output `out.raw.gz` returned success with 21
   bytes; the same reader then failed `primary input bytes`, limit 1. The exact
   public-API probe and output are retained outside the repository. Root accepted
   this finding and owns the shared transport-budget fix; this report does not
   claim that fix's final validation.
3. **Entry-point publication ordering compared basenames.** The old stage sort
   compared `Stage.target` (a basename) with the primary resource path. For primary
   `font.json` plus sidecar `nested/font.json`, both sorted as the primary, leaving
   the actual entry point first. Root changed stages to carry `is_primary`, derived
   from the complete resource path and directory flag. Normal successful return
   had complete assets even before the fix; the defect concerned publication
   order during a transaction.
4. **Multiple CLI inputs reused the entire allocation allowance.** Each input
   previously decoded under the full `max_total_bytes`, while earlier models and
   diagnostics remained live. Only the eventual writer could reject the combined
   set. Root assigned and integrated the repair described below. No high-memory
   stress or OOM experiment was required to establish this unbounded accumulation.

All findings were sent to root immediately. The review stopped expanding after
root assigned the implementation work.

## Cumulative input budget

`FontSet::retained_usage(max_bytes)` returns `ModelUsage { bytes, fonts, glyphs,
glyph_slots }`. It walks the existing data directly, stopping at the allowance;
it creates neither a serialized representation nor a second model. Each new
input is visited once. Already accepted inputs are represented by scalar counters,
so processing many small inputs does not repeatedly traverse the growing set.

The count includes allocated vector and string capacities, not just lengths:

- FontSet's strike vector, source string and ordered container properties.
- Every glyph-table slot and unused vector capacity, including deleted IDs.
- Mono/Gray8 storage capacity; aliases, Unicode sequences and names.
- Font names, localized fields, XLFD fields, charset ranges and identity strings.
- Font/glyph/header properties, nested lists, byte payloads and raw source records.
- Both private mapping indexes, their duplicate-ID vectors and sequence-key copies.
- Report entry capacity and code, message and source-asset string capacities.

Two private, read-only capacity accessors were added to `Properties` and `Bitmap`;
the model's indexes are accessed from its child budget module. No storage layout,
codec behavior or mutation method changed.

B-tree accounting deliberately overestimates: each entry plus a possible empty
root is charged 16 key/value/edge slots and 128 header bytes, then its owned
vectors are counted separately. The current standard-library node has 11 keys
and values and at most 12 edges. This bound was checked against the
[official Rust source](https://doc.rust-lang.org/src/alloc/collections/btree/node.rs.html),
read on 2026-10-04. The implementation does not copy Rust's tree code. The estimate
excludes allocator bookkeeping and process-wide state; it is an owned-storage
budget, not a process RSS promise. Revisit the conservative node bound if the
standard library radically changes its tree layout. Property traversal rejects
more than 128 nested lists to bound its call stack.

CLI `InputBudget::remaining_limits()` subtracts all accepted retained bytes and
glyph slots before the next file open and decoder call. It also clips individual
input, companion, decompression and table bounds to the remaining byte allowance.
Per-glyph pixel bounds and per-input resource-operation counts are unchanged.
`admit(&Loaded<FontSet>)` checks all totals before updating any counter or merging
any data. Failure leaves the budget unchanged. Live glyphs and assigned slots
both obey the original aggregate `max_glyphs`; strike counts use checked addition
and their allocations obey the byte limit. ResourceLimits has no separate
max-font-count field.

An additional four receiving-array slots per incoming font, container property
and report entry reserve room for geometric capacity growth, minimum capacity,
and old/new arrays during reallocation. The original source arrays are counted
too. These are conservative reservations and are not reclaimed. Root's integration
explicitly drops `FileInput` after decoding and before admission/merging, so its
primary wire buffer does not overlap these receiving-array allocations.

The original strict flow remains intact: read and write diagnostics are combined,
Error is fatal, and strict rejects Loss before persistence. Shared resource paths
reject traversal and file/directory collisions; directory listings are bounded
before allocating names and revalidated in ReadContext. The macro registration
setters synchronize configured readers and existing structural detectors; formats
without meaningful headerless detection remain unregistered as detectors. Image
output flags validate the chosen format and atlas/directory option scope.
