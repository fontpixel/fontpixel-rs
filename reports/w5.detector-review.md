Independent W5 detector integration review, 2026-10-04. This was read-only with respect to production code, format documents, tests and manifests. Evidence uses the existing all-format CLI plus an external Rust probe linked to its all-format library; their hashes and build command are in the JSON report. The captured baseline predates the fixes delegated after these findings.

The registry advertised 99 readers/writers and 89 installed detectors. The filename-free probe exercised 189 distinct native fixture cases spanning 75 canonical format IDs. Seventy-five CLI read validations covered the requested core formats, suspect competing readers, text magic, legal HEX comments and two truncation controls. The archive preserves scripts, exact commands/exits, fixture hashes, source excerpts, model summaries and the specific issue fixtures. No long fuzz or performance run was performed.

| Finding | Actual behavior | Native reader evidence |
| --- | --- | --- |
| DR1: RISC OS claims FONTX2 | `FONT` prefix gives RISC OS Certain, tying FONTX2 Certain | FONTX2 reads 256 glyphs; RISC OS rejects version. |
| DR2: ChiWriter claims QPF | Header bytes alone add an invalid Possible candidate | QPF reads 256/2048 glyphs; ChiWriter rejects bytes outside bitmap records. |
| DR3: FON claims OS/2 GPI NE | Generic NE Certain defeats GPI Possible, selecting the wrong reader | GPI reads 3 glyphs; automatic and FON reads report no FONT resources. |
| DR4: C claims a HEX comment | `U8G_FONT_SECTION` or `u8x8_font_` anywhere in the text gives Certain | HEX reads 2 glyphs; automatic and C reads fail to find a byte array. Existing `U8G2_FONT_SECTION` has the same weakness. |
| DR5: extra Xerox candidate | A Palm/NFNT font receives an invalid Xerox Possible match | Palm and NFNT each read 257 glyphs; Xerox rejects bytes after its declared bodies. |
| DR6: existing Plan 9 boundary | Two initial integers select Plan 9 for explicit-only EDWIN text | EDWIN reads 4 glyphs; Plan 9 rejects ascent greater than height. This is recorded separately from the W5 regressions. |

DR1–DR5 were sent to the root and relevant owners before the final report. DR6 was sent as a pre-existing explicit-selection boundary, without claiming it was newly introduced by W5. The owner/root gates will validate their fixes; this review does not report those fixes as already passing.

Normal BDF, PCF, PSF1/2, HEX, C generic/GFX/U8g2/NetBSD, YAFF, OTB, PBF, DRAW, SFD, KBITS and BMFont files read automatically. DOSStart, PSF2TXT, Playdate, FIGlet, DRCS, HP PCL, PILfont and binary SSFN native samples also read automatically. The repaired SymbOS detector did not claim the reviewed ordinary C/PBF inputs.

Generic image/SFont PNG ambiguity is expected; the RFont sample had CRC-backed rfVM evidence and selected SFont Certain. Palm and NFNT are both valid interpretations of the reviewed Palm sample, so their ambiguity must remain after removal of the invalid Xerox candidate. Filename hints must not select a winner in either case.

`DosStartFont\n` and `RB12` truncations retain identifying native magic and correctly fail their readers; Certain confidence alone is not a bug in these controls. Explicit-only/headerless formats returning UnrecognizedFormat without a filename are also not failures. Public detector hooks that are not installed are shown in the probe's per-hook list for transparency; the actual registry result remains authoritative.

This bounded review is not an exhaustive proof that every format pair is disjoint. See [structured report](w5.detector-review.json) and [reproduction evidence archive](w5.detector-review.tar.gz).
