# W5.A1 — eight native text and binary font formats

Implementation is complete for `dosstart`, `edwin`, `mkwinfont`, `psf2txt`,
`pcr`, `plus3dos`, `drhalo`, and `writeon`. Each has a public codec, typed input
options, a named output-options alias, a format document, dedicated integration
tests and a fuzz target. The coordinator owns registry, feature, CLI and notice
integration. This worker result does not close phase 5 or claim all 99 codecs.

## Scope and representation

| ID | Native coverage |
| --- | --- |
| dosstart | DSF format 1 bitmaps; 3-digit dimensions, advance, ascent, ASCII name, historical short-vector top padding. Writer produces the native 32–127 interval. Format 0 contains strokes and is explicitly rejected. |
| edwin | Contiguous legacy interval, variable dimensions, non-digit-leading glyph labels, top alignment and arbitrary-width decimal rows. Width 129 is independently verified. UTF-8 labels are retained. |
| mkwinfont | FD font scalars, sparse byte positions, variable widths and shared height/baseline; UTF-8 family/copyright/comments. Charset, style flags and additional scalar fields remain in ordered native headers; implicit glyph positions remain Legacy. |
| psf2txt | Native PSF Tools header and raster syntax, UTF-8 comments/BOM, Unicode aliases, Unicode sequences and unmapped positional slots; version/flags and unknown native properties retained. |
| pcr | Optiks versions 1 and 2, 256 8-pixel-wide cells, retained reserved header byte and exact payload size. |
| plus3dos | Native +3DOS CODE font, header lengths/checksum/load address/reserved bytes and 96 8×8 cells. |
| drhalo | Positive-dimension bitmap FON, first position 0/32 inference plus typed input override, signed dimension validation and complete packed payload. Header authored from field semantics; no historical protection stub copied. |
| writeon | Native 22-byte WOF header, retained auxiliary words, contiguous character range and cells in 8×14 multiples. |

The shared output-options type offers an explicit grayscale threshold,
Unicode-number-to-legacy opt-in, cell geometry, Dr. Halo first position,
resource limits and output cap. Native field limits remain enforced. Writers
normalize cells when required, then decode the result under the same limits and
audit all public source model fields, including glyph metadata, code aliases,
sequences, names, metrics and raster data. Strict mode rejects reported loss.
Unknown user metadata is never silently treated as preserved.

EDWIN and mkwinfont have no registered detector. Dr. Halo requires complete
structure and returns `Possible`; its two-byte signature alone is insufficient.
The five other detectors use native
signatures; binary probes validate dimensions, ranges and terminal boundaries
without constructing font models. Integer/span checks and cumulative memory
accounting precede allocations; EDWIN additionally bounds big-integer arithmetic
work with `max_table_bytes`.

## Validation and independent evidence

- **44 dedicated tests pass.** They cover strict roundtrips, all-glyph metadata
  loss, cumulative limits, writer output reread under identical limits, invalid
  signatures/spans, checksums, geometry, Unicode aliases/sequences, grayscale
  reduction and extreme signed metric values.
- **24 independent-feature gates pass:** one test run, warning-denying Clippy
  run and warning-denying rustdoc build for each of the eight features.
- **15 independent crosschecks pass across all eight formats.** monobit 0.54.0
  generates source data where it has a writer. Native reads are compared with
  monobit reads, native rewrites are read by monobit, and every code/mapping,
  dimension, placement, advance and packed raster byte is compared. Native
  family names and font ascent/descent are checked too. Extra cases cover PCR
  v1/v2, Dr. Halo first0/32, EDWIN width129, PSF aliases/sequences/unmapped slots
  UTF-8 FD names, explicit point size, and variable-height EDWIN labels/baselines. Dr. Halo has no monobit writer: its original wire fixture
  is independently read by both implementations, then native output is checked
  by the monobit reader.
- **Eight final-source ASAN smoke runs pass**, each requested for 10 seconds
  with a 2-second per-input timeout and 1024 MiB RSS cap. Before and after each
  run, the shared production source hash is identical. Earlier single-feature
  smoke runs also pass. There are 71 reproducible original seed files.

## Reproduction and remaining coordinator work

Use `source scripts/local-env.sh`,
`CARGO_TARGET_DIR=$FONTPIXEL_WORK_ROOT/target-w5a1` and `CARGO_BUILD_JOBS=2`.
The exact individual commands are in the JSON logs. The independent tool uses
the unchanged shared Python 3.12 oracle environment. Its eight module hashes
are recorded in the crosscheck report and correspond to the official 0.54.0
PyPI source release verified by W5.1. monobit is MIT; native wire fixtures and
raster patterns are original project-authored MIT data. No files in reference,
samples or the installed oracle were changed.

The formal **610-second ASAN runs, five quiet release-performance repetitions,
whole-repository gates and final acceptance remain assigned to the coordinator**.
Only adapter functionality was checked here; the one-iteration timing-interface
smoke is explicitly not performance evidence. The two timing adapters are:

```text
w5a1_timing bench FORMAT INPUT COUNT
python tests/crosscheck/w5a1.py --bench FORMAT --file INPUT --count COUNT
```

Both return JSON nanoseconds and perform in-memory parsing/serialization;
Dr. Halo's independent writer time is `null` because the oracle has no writer.
EDWIN's independent benchmark prepares ASCII labels before the timed writer
loop, as required by monobit's writer. Inputs are reproducibly generated in
`$FONTPIXEL_WORK_ROOT/w5a1-crosscheck` by the crosscheck script. The coordinator
must build the Rust example in release mode for formal measurements.

Requested worker configuration: `gpt-6-astra`, `xhigh`, isolated task context;
fast-mode status is not independently observable. No subagents, branch changes,
commits, shared-file edits or whole-repository builds were made by this worker.
