## Delivered behavior

- Native DEC DRCS read/write, 7/8-bit controls, sixel packing, 94/96-character
  sets, typed VT320/VT510 dimensions, explicit baseline/cell/designator options.
  Complete Pe=1 reloads and matching G0 designation suffixes are accepted;
  state-dependent partial reloads and unrelated terminal commands fail.
- Existing generic C/font8x8/Tmat/Adafruit GFX support and original tests retained.
  New typed families are U8g2, LVGL, NetBSD wsdisplay_font, U8glib and U8x8.
- U8g2 native compressed pairs/repeats, ASCII accelerators and Unicode blocks;
  U8glib native formats 0/1/2; U8x8 modern tile grids and explicit pre-2019 arrays;
  NetBSD native names, encodings, cell geometry and bit/byte order.
- LVGL all four cmap forms, plain/RLE/XOR raster, native 1/2/3/4/8-bpp reading,
  1/2/4/8-bpp writing and explicit fractional-advance/kerning projection losses.
  Binary head/cmap/loca/glyf/kern tables use typed `CContainer::LvglBinary`.
- C input is literal data, never compiled or executed by the library. A bounded
  LVGL-only condition selector handles ordinary split generated initializers
  under the documented v8.3.11 ABI. Unknown active macro conditions fail.
- Source metadata, native structures, pixels, diagnostics, intermediate output
  and readback storage count cumulatively. Successful writes are read back with
  the remaining aggregate budget, guaranteeing readability with the original
  limits. Decompression/packing is bounded by input and pixel limits; repeated
  RLE pairs avoid pathological uncompressed checkerboard records.

## Limits and decisions

U8g2 supports BMP native codes and the consumer's signed local height <=127;
record size/metric overflows fail. U8glib/U8x8 have native 8-bit ranges and
representability limits. The old U8x8 layout is explicit. NetBSD host-dependent
KNOWN ordering is rejected. LVGL emitted C fits normal v8 descriptors; its
reader also permits large descriptor dimensions. V9-specific behavior,
subpixel fonts, custom callbacks and fallback chains are explicitly unsupported.
The conditional selector uses v8.3.11 and 32 levels maximum. Kern pairs/classes
and fractional advances are validated, then projected with Loss diagnostics.
Neither fixed-cell DRCS nor the core glyph model can preserve arbitrary source
metadata, aliases and kerning without projection; those changes are reported.

The LVGL binary reader uses a bounded internal literal representation to share
native cmap/raster validation. Conservative cumulative budgets include that
representation and readback; minimum file-size budgets may therefore reject
otherwise valid files. Rejection is preferable to exceeding declared limits.

`w5.5-decisions.md` contains the coordinator-ready decisions. Primary references
are linked in `docs/formats/c.md` and `docs/formats/drcs.md`. U8g2/U8glib/U8x8
runtime references are BSD, LVGL is MIT, NetBSD Spleen is BSD; no upstream runtime
implementation was copied into the library. Runtime/download hashes are pinned
by the crosscheck script. The coordinator may acknowledge these format/runtime
references in NOTICE; no bundled third-party source was added.
