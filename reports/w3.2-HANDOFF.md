## Implemented scope

1. Windows raster FNT v1/v2/v3: checked headers, v1 fixed/proportional packed
   strikes, v2/v3 byte-column rasters, font/glyph metrics, exact legacy byte codes,
   names, copyright, device and named source header properties.
2. Typed read/write options and registry hooks. Source versions are preserved by
   default; new sources default to v2. Unicode export uses selected Windows code
   pages; unknown/OEM/symbol mappings require explicit interpretation. Existing
   CJK byte codes can roundtrip without loading CJK conversion tables.
3. FON: checked NE resource read/write and PE32/PE32+ resource reading; multiple
   sizes/styles; deterministic resource-only NE with MZ exit stub, FONTDIR/FONT,
   resident/nonresident names and alignment. Executables are never run.
4. Structured loss reports, strict CLI protection, limits on input, glyphs,
   pixels, tables, resources, output and working/model allocations. Unsupported
   vector, ABC and color layouts fail explicitly.
5. CLI `fnt` / `fon` features enabled by default. Controls:
   `--fnt-version`, `--fnt-charset`, `--fnt-code-page`,
   `--fnt-read-code-page`, existing `--gray-threshold`. Ambiguous `.fnt` output
   still requires `--to fnt`. Multiple inputs can produce one `--to fon`.
6. Original field-by-field fixtures and generators, integration/property tests,
   monobit/FreeType/catalogue-boundary crosscheck, dedicated FNT/FON fuzz targets,
   reproducible five-run timing example and format/decision documentation.

## What changed at the final safe stopping point

A late real-source probe attempted to export the supplied 38,653-glyph Tong SC
BDF to CP1252 FNT. At `961d8fd`, conservative accounting rejected it at the
256 MiB default aggregate limit before returning the omission report.

Commit `7c53640` keeps source bitmaps, metadata, mappings and omission charges,
but reserves normalization diagnostics for at most 256 exportable byte positions
instead of charging them for every CJK source glyph. It adds a font-level reserve.
It also reports and omits zero-advance glyphs because a zero-width FNT slot means
“absent”; the former behavior could abort an otherwise useful partial conversion.

Focused tests then passed and the complete Tong probe succeeded, producing a
5,709-byte FNT and 77,994 diagnostic entries. Its full 25,905,345-byte JSON report
is retained as deterministic gzip (about 405 KB), with counts/checksums in
`w3.2-evidence/tong-default-budget.json`. The source font is not duplicated.

   conservative estimate, not an allocator-backed exact RSS meter. Recheck
   cumulative FON budgets, metadata/property-depth caps, report allocation,
   many-to-one code mappings, repeated resources, and writer readback scratch.
   The new source-length test/Tong probe proves the prior false rejection is
   fixed; it does not prove every adversarial boundary.
2. **Zero-advance omission needs independent review.** Verify per-code/per-glyph
   report coverage, strict-mode refusal, fonts containing only such glyphs,
   mixed unmappable/duplicate mappings, aliases and selected code pages.
3. Fully unrepresentable input currently fails with `InvalidInput` rather than
   returning a successful empty file. Review whether accumulated diagnostics in
   that error path should be returned more explicitly for the desired API.
4. Font metadata is deliberately conservative: legacy codes remain tagged;
   unknown/OEM/symbol pages are never guessed; names are byte-preserving Latin-1;
   nonrepresentable generic metadata is reported. Exercise source read overrides
   and explicit target-page selection together, and uncommon header fields.
5. v1/v2 size and offset limits are enforced; ABC/color/vector FNT layouts are
   intentionally unsupported. PE output is outside W3.2 (NE output is provided).
6. No Windows `AddFontResource`/actual installation test has been performed on
   this Linux executor. FreeType/monobit and structure checks are meaningful,
   but are not a claim of a real Windows install test.
7. The original specification/decision docs were written before implementation;
   later choices and oracle differences are appended. Preserve these rather
