# W3.4 KBITX implementation and independent checks — 2026-10-04

KBITX native reading/writing is implemented with exact Gray8 storage, bounded
WIB/base64 and inert XML processing. This report covers the KBITX portion only;
it does not mark all W3.4 or phase 3 accepted.

## Evidence

- `cargo test -p fontpixel --no-default-features --features kbitx --test kbitx`:
  **13 tests passed**, including proptest-generated Mono/Gray8 rasters.
- `cargo clippy -p fontpixel --no-default-features --features kbitx --all-targets
  -- -D warnings`: passed.
- `RUSTDOCFLAGS='-D warnings' cargo doc -p fontpixel --no-default-features
  --features kbitx --no-deps`: passed.
- Independent catalogue oracle: **9 original synthetic glyphs + all 15,932
  MuzaiPixel glyphs** match decoded dimensions, horizontal advances, signed
  bearings and every threshold-128 pixel. Zero catalogue warnings.
- The frozen catalogue importer independently consumes generated native output
  with the same results. Both source fonts also complete strict native conversion
  and a second native write produces byte-identical output.
- Output sizes: synthetic 671 → 747 bytes; MuzaiPixel 1,620,798 → 1,537,257 bytes.
  These are fixture font file sizes, not CLI executable sizes.
- Full input/oracle/binary/output hashes and source snapshot hashes are in
  [w3.4-kbitx-crosscheck.json](w3.4-kbitx-crosscheck.json).

The codec keeps all native scalar records in order, exposes known names/metrics,
and retains validated kerning, feature and PUAA XML as inert properties. It
preserves named unencoded glyphs and duplicate Unicode records. Source information
that the format cannot express produces explicit losses; strict registry output
returns no assets. Numeric name IDs normalize semantically (`+01` = `1`), with
last-record precedence. The standard metadata element order is enforced on output
and any reordering of retained properties is reported as loss.

## Independent source and license

The MIT frozen catalogue importer lives in the supplied read-only reference tree.
The upstream Bits'N'Picas DTD/importer/exporter were consulted only as format
specifications; no MPL implementation was copied. The Rust implementation and
synthetic tests/seeds are original project code.

The real fixture was downloaded to `../local-work/kbitx-oracle/`, outside the
repository, from fixed MuzaiPixel commit
`59e79de047d344c7675944424e56bb9a1ab5503c`. Its exact URL, SHA-256, OFL license URL
and license hash are recorded in the JSON evidence. No fixture font is committed,
and no reference or sample files were changed. monobit 0.54 has no KBITX handler;
there is no claimed monobit validation.

Reproduce the independent checks with:

```sh
PYTHONDONTWRITEBYTECODE=1 ../local-work/oracles/bin/python tests/crosscheck/kbitx.py \
  --binary ../local-work/target-kbitx/debug/fontpixel \
  --source ../local-work/kbitx-oracle/MuzaiPixel.kbitx \
  --output-dir ../local-work/kbitx-crosscheck-another
```

The output directory must not already exist. The synthetic fixture is regenerated
by the script. The Python interpreter, oracle hash, binary hash and generated
artifact hashes are recorded alongside the result. These checks use
`--kbitx-read-threshold 128` for catalogue/BDF parity; default native KBITX reads
retain exact Gray8 instead.

## Defects found and fixed during development

- Native pixel fonts lacked the point-size/resolution required by the BDF writer.
  KBITX now uses a documented reproducible 72 dpi convention, with point size
  equal to em pixel height (zero if absent), so ordinary native conversion works.
- A writer could otherwise return XML too large for its own reader input limit or
  an escaped attribute larger than the table limit. Output now obeys both limits,
  checks escaped attribute size before allocation, and runs an allocation-free
  XML/model/WIB reader-budget preflight before returning.
- Out-of-order native metadata would silently change ordered properties on
  roundtrip. The writer now reports that change and emits DTD-compatible ordering.
- Native numeric name aliases such as `+01` must update the same normalized name
  as `1`. Canonical numeric property IDs make both orders and single-record forms
  behave consistently.
- Duplicate scalar lookup now uses an ordered tree, avoiding quadratic behavior
  on large hostile record lists.
