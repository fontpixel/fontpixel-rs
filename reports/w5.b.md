# W5.B native system-font codecs

Implementation and independent validation completed on 2026-10-04. The eight canonical formats have native readers, writers, typed options, codec traits, bounded resources and individual loss reporting. The coordinator owns feature/registry/CLI integration. Palm/GDR W5.4 files were not changed.

| Format | Implemented native scope | Independent evidence |
| --- | --- | --- |
| `beos` | `\|Be;` sparse Unicode hash table, aliases/unmapped rasters, original 8-level coverage and explicit 16-level compatibility, finite float metrics with explicit rounding | Hirotsu primary note; upstream monobit read/write, documented coverage normalization |
| `oberon` | Original word-based bitmap file, separate run/box/raster sections, signed metrics, family/variant and source extrema | Project Oberon declarations; upstream monobit read/write |
| `symbos` | Medium, small, big; ordinary and 255-character extended layouts; native writing-system/WYSIWYG metadata | Original developer's structure specification; independent authored parser for all five fixture profiles; monobit medium only |
| `wsfont` | Native WSF, all four byte/bit order combinations, explicit KNOWN interpretation, mono and Gray8 alpha, padded strides | NetBSD kernel order conversions and FONT_IS_ALPHA macro; upstream monobit basic mono read/write |
| `vtfont` | VFNT0002 pool and four maps; non-byte-aligned left/right halves; independent bold fallback; unused physical glyphs; native preservation and rebuilt maps | Unchanged FreeBSD kernel lookup; native vtfontcvt independently compiles original HEX; monobit read/write |
| `geos` | Bare original strip; CVT standard, extended, UTF-8, MEGA, MEGA+UTF-8; all Unicode map levels; multiple strikes and native record directory | Publisher Bits'N'Picas wire classes independently read/rebuild all six profiles; monobit bare/standard read/write |
| `gpi` | Native fixed/proportional/ABC FOCA resources; inclusive final character; optional uncounted null; raw, OS/2 NE and LX; directory, resource/page tables, EXEPACK1/all EXEPACK2 tokens | Original public-domain parser/writer; native decompressor token checks; independent monobit NE extraction followed by native glyph decoding |
| `pcgeos` | BSWF SBCS and DBCS; all point/charset entries; exact 8.8 point values and retained metric fractions; native glyph flags, separate kerning pair/value tables | Independently compiled packed original declarations (including styled 12.5-point SBCS and DBCS); monobit simple regular SBCS pixels |

All readers budget input retention, cumulative fonts/glyphs, expanded rasters, tables and metadata. Writers validate source bounds, budget conversion and output, then read successful output with the same caller limits. Changes to representable fields and omitted information are audited individually; strict rejection is shared infrastructure. Gray-to-mono thresholding, BeOS palette quantization, Unicode/legacy reinterpretation and fractional metric projection are explicit. Native byte preservation is permitted only after a fresh parse exactly matches the supplied complete model.

Algorithmic checks include linear BeOS collision-chain validation, next-free allocation for adversarial writer collisions, cached LX object expansion, packed strip insertion/extraction, sorted VFNT mappings and bounded Unicode maps. No production parser invokes an external command or copies GPL/MPL/EPL implementation code.

## Validation

- **31 integration tests**, plus the GPI all-token EXEPACK unit test, passed.
- **24 single-feature gates** passed: tests, all-target Clippy with `-D warnings`, and rustdoc with `-D warnings`, for each of eight features. See `w5.b-gates.json` and `w5.b-extra-gates.json`.
- **46 independent checks**, **93 external commands**, and **49 source/tool fingerprints** passed in `w5.b-crosscheck.json`. Comparisons cover every mapped code, pixel, glyph rectangle, advance and strike count. PC/GEOS also independently checks global metrics, native style and rational points.
- **2,956,591 ASAN executions**, with eight separate 13-second smoke runs, passed. New native/rebuilt writer paths are both exercised. Final seeds for the last four harnesses were replayed under ASAN after the independent compressed fixtures were added.
- **50 embedded original synthetic wire seeds**, with deterministic truncations, are fingerprinted in `w5.b-seeds.json`. Native tools encode only original artwork; no external font artwork is included.

Reproduction starts with `source scripts/local-env.sh`, `CARGO_TARGET_DIR=$FONTPIXEL_WORK_ROOT/target-w5b`, and `CARGO_BUILD_JOBS=2`. Build `w5b_timing` with features `beos,geos,gpi,oberon,pcgeos,symbos,vtfont,wsfont`, then run `python3 tests/crosscheck/w5b.py`. The script records Python 3.12.13 and monobit 0.54 module fingerprints, fetches primary sources externally, and compiles its external oracles. Run `python3 fuzz/seed_w5b.py --root PATH`; use each `FORMAT-only` fuzz feature with the corresponding corpus. Production needs none of these external dependencies.

## Oracle scope and source licensing

The report fingerprints each exact source, compiled executable and fixture. GPL/MPL sources remain research or external-oracle inputs under `../local-work`, never production dependencies.

- **NetBSD**, BSD-2-Clause: unchanged `wsfont_revbit`/`wsfont_revbyte`, original reverse table and FONT_IS_ALPHA macro in an external standalone fixture wrapper.
- **FreeBSD**, BSD-2-Clause: unchanged kernel `vtfont_bisearch`/`vtfont_lookup`. Native `vtfontcvt` has a recorded Linux portability diff for libc, annotations, queues and endian headers. Its unavailable LZ4 compressed-C-output branch aborts; only native font output is exercised. Native font parsing/writing is unchanged.
- **Alexander Taylor OS/2 GPI tools**, public domain, revision `8c4cb34a013a9daa0039a4ff0a86bb5fea5dd08d`: unchanged parser, writer, EXEPACK decoders and glyph extractor. The author's NE branch is disabled upstream, so NE extraction uses the independent monobit OS/2 module. No OS/2 VM loading claim is made.
- **Bits'N'Picas 2.2.2**, MPL-1.1/LGPL alternative: external release JAR SHA-256 `22685a52bc1a7f26680f80197548e74dc61a9f58eb083d6f700220a48a1165a6`. Separate source revision `43b11dca0809a3342b8281b570897e8654ffe705` supplies documented field evidence; it is not misrepresented as the exact release build source. The original `isMega()` heuristic fails when an index-only record appends UTF-8 data. The wrapper explicitly selects the six native subsets and shares the native Unicode-map object for that combination; all strip/map parsing and rewriting remain in unchanged publisher classes.
- **PC/GEOS**, original GPL-3.0 declarations, revision `8251622828433bfe48873992245af36f19e6ae57`: independently authored packed C oracle based on field facts, with compile-time structure sizes. This is **not execution of the GEOS kernel**. No GPL implementation is copied.
- **SymbOS**, original developer's GPL-3.0 structure documentation, revision `13f125a73925a76b9016de5ebe874b591b8aec2b`: format facts and independently authored parser, not a native SymbOS runtime.
- **BeOS Hirotsu note / Project Oberon**: original field evidence, recorded source hashes, no implementation copied.
- **monobit 0.54.0**, MIT PyPI source release, exact called module hashes retained. The shared environment is unmodified.

Known monobit differences are explicit: BeOS native levels require `255/7` scaling rather than monobit's `255/15`; GPI's final-character field is inclusive (monobit omits the last glyph); PC/GEOS point-entry offsets/style/fraction and several flag meanings differ from the original declarations. Complete GPI ranges and PC/GEOS styles/fractions/DBCS therefore use independent native evidence instead of treating those monobit paths as authoritative. The GPI author's writer assumes an extra null descriptor and may emit an invalid uncounted descriptor for a source without one; those bytes remain opaque and are exposed as a glyph only when structurally valid.

## Explicit limits and coordinator handoff

PC/GEOS 1.0/1.2 `80 10` / `EF BE` signatures are not BSWF: no field-complete public declaration or runnable independent reader was found in the pinned survey sources, and these are explicit errors. PC/GEOS region/outline-generated FontBuf records and GPI outline/combined/CJK libraries are not bitmap resources and fail explicitly. Oberon follows the documented original word layout, not the later RISC renderer's low-byte truncation. These boundaries are also in the individual format documents.

Native/large synthetic fixtures are in `../local-work/w5b-oracle/fixtures`; the crosscheck manifest hashes them. `w5b_timing emit DIR` reproduces original fixtures, `dump PROFILE FILE` emits model JSON, and `bench PROFILE FILE` runs three warmups then 100 reads/20 writes. The `vtfont` writer profile measures native byte preservation. The separate `vtfont-rebuild` profile uses the same fixture with preservation disabled for fair comparison against a rebuilding writer. Other explicit GEOS/GPI/PCGEOS profiles already rebuild.

The coordinator still owns ≥610-second ASAN runs, five quiet release performance rounds, complete repository gates and any resulting fixes. No long fuzzing or quiet-performance result is claimed here. Frozen owned source/harness/documentation paths and hashes, external artifacts, evidence hashes, and a non-owned shared snapshot are in `w5.b-freeze.json`.
