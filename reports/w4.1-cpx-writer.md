# Native CPX writer verification

`Version::Cpx` now emits a real DOS COM wrapper around FONT data. The loader is
original MIT project code: 39 bootstrap bytes plus 96 decoder bytes. NASM's
`cpu 8086` check rejects instructions requiring later CPUs. The production crate
embeds ordinary byte constants from `cpi/stub.rs`; it neither invokes tools nor
depends on NASM during a build.

The native encoder emits standard NRV2B LE16 literals, matches with a distance
of 1–256 bytes, and the standard termination marker. Its hash search visits at
most 64 candidates per token. The small loader supports exactly that valid
output subset. First-byte references are excluded because MODE temporarily
changes the first CPI literal from FF to CB; otherwise a matching copy could
propagate the return instruction into glyph data.

## Interoperability constraints

The [FreeDOS MODE consumer source](https://gitlab.com/FreeDOS/base/mode/-/blob/master/SOURCE/MODE/CPITRICK.ASM)
requires the initial stack-check instruction, patches the following conditional
branch, searches for the pack header in its first 100 bytes, replaces the first
CPI literal, and makes a far call at offset 0100. The original loader honors that
interface and returns through the patched decoded byte. The consumer restores
the CPI signature and its saved registers afterward.

[MODECP.C](https://gitlab.com/FreeDOS/base/mode/-/blob/master/SOURCE/MODE/MODECP.C)
limits file input to 58,880 bytes and allocates 320 additional bytes. The encoder
checks decoded size before constructing the intermediate FONT output and proves
the relocation gap at every token. Code plus overlap must fit the 320-byte
allowance; no DOS allocations or system calls are needed by the loader.

UPX's [header decoder](https://github.com/upx/upx/blob/v5.2.1/src/packhead.cpp)
rejects compressed lengths exceeding decoded length, and its
[file entry point](https://github.com/upx/upx/blob/v5.2.1/src/work.cpp) rejects
files below 512 bytes. Pure literal encoding therefore cannot satisfy standard
UPX consumption. This writer uses real matches and rejects inputs that do not
meet the size constraint. Very small packed files receive trailing zero fill
outside the stream and loader. The [COM unpacker](https://github.com/upx/upx/blob/v5.2.1/src/p_com.cpp)
uses header/stream lengths to recover the complete original CPI.

## Independent tests

`reports/w4.1-cpx-writer-crosscheck.json` records eight passing cases: positional
patterns, zeros, short matches, repeated FONT headers, distance-256 dictionaries,
a 57,600-byte run, and real EGA/EGA18 collections imported through the native
reader. Each output passes native import and independent monobit raster checks.
UPX 5.2.1 decompression equals the expected CPI bytes, including all metadata.

Unicorn 2.1.4 executes the generated loader both directly under the published
MODE protocol and through the actual `cpx2cpi` consumer function. The latter is
assembled without changing the original CPITRICK.ASM. Assertions cover AX=1,
all saved BP/BX/CX/DX/SI/DI values, FLAGS (including an initially set direction
flag), DS/ES/SS/SP restoration, exact payload and guards before/after the work
buffer. Every memory write must stay inside the documented work area or the
small caller stack region. This is CPU emulation of the real consumer function;
it does not claim a full DOS boot or physical VGA display test.

An independent second agent also replayed every token and checked overlapping
input/output inequalities, then monitored both emulator memory reads and writes
for seven pre-final artifacts. Its minimum unread-input clearance was 50 bytes;
no blocking defect was found. The eighth final case adds the near-limit run.

The 15 standalone CPI tests include randomized successful CPX output, byte/model
round trips, deterministic repeat output, output/decompression bounds, and
incompressible/oversize failures retaining all omitted mapping/property notes.
Standalone clippy and rustdoc pass with warnings denied. The parent will run the
final CPI fuzz/performance gate after this freeze.

To regenerate the constants, split the assembled binary at byte 39 into
`BOOTSTRAP` and `DECODER`; neither block needs a linker or relocation metadata.

```sh
../local-work/nasm-oracle/usr/bin/nasm -f bin \
  ../local-work/w41/CPITRICK.ASM -o ../local-work/w41/cpitrick.bin
../local-work/oracles/bin/python tests/crosscheck/w41.py \
  --binary ../local-work/target-w41/debug/examples/w41_timing \
  --output-dir ../local-work/w41/cpx-writer-final \
  --cpx-writer-only --upx ../local-work/w41/upx \
  --mode-consumer ../local-work/w41/cpitrick.bin \
  --nasm ../local-work/nasm-oracle/usr/bin/nasm
python3 fuzz/seed_w41.py ../local-work/w41/seeds \
  --writer ../local-work/target-w41/debug/examples/w41_timing
```

The output directory must be new. `font-compressible` is independent synthetic
input; `native-cpx` is generated from it, so neither fuzz seed contains real
third-party font data. No production files were changed after the final
independent review and freeze hash.
