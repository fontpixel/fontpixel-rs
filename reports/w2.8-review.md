## Review findings and fixes

The review inspected the XML preflight/DOM boundary, namespace/active-content
policy, arc expansion guard, path rasterization, bounds/origins, glyph identity,
metadata, strict loss behavior, feature gates and registry/CLI dispatch. It read
DOT-README, PLAN, FORMATS, existing decisions and the candidate's raw evidence.
The SVG 1.1 [font specification](https://www.w3.org/TR/SVG11/fonts.html) and
[path specification](https://www.w3.org/TR/SVG11/paths.html) were checked directly.

1. **Separate paint was incorrectly combined.** Two identical child paths with
   opposite winding became a blank glyph. Independently painted paths now union
   their raster layers; subpaths of one path still follow nonzero winding. Raster
   work is charged per layer, so the correction cannot multiply unbounded work.
2. **Alias grouping was quadratic and diagnostics had stale indices.** Every
   alias cloned and reindexed its growing mapping list. Groups now accumulate
   once before indexing; diagnostics use the retained output glyph index. The
   8,192-alias test is retained. A single observed candidate suite took 40.68 s;
   the corresponding corrected suite took 0.36 s. This is a regression observation,
   not an isolated five-run benchmark or a whole-phase performance result.
3. **Metadata expansion escaped caller budgets.** UTF-32 mapping storage and
   names are charged before decoding. Fixed native vector/bounds fields no
   longer collect an arbitrarily long integer list. Registry aggregate-byte
   limits now reach the native reader even with an explicit format override.
4. **Free-form style names were emitted as invalid standard descriptors.** Exact
   style names use `fp:style`; `font-style` is emitted only for valid SVG values.
   A further failing-before test found negative horizontal advances could also
   be emitted, despite the SVG requirement that widths be nonnegative. Writing
   those advances now fails explicitly; negative bearings remain supported.
5. **Active/unrepresented content was incompletely classified.** SMIL animation
   elements are explicitly rejected. Unknown native glyph fields produce loss
   diagnostics rather than silently bypassing the attribute check.
6. **Large native outputs could not be reopened by the CLI.** The 64 MiB default
   remains, but `--max-input-bytes` now reaches inspection/conversion/rendering and
   SVG dispatch. The independent 256 MiB aggregate cap remains. This resolves the
   previous full-CJK circular CLI limitation instead of merely documenting it.

The unchanged candidate fails five corrected edge regressions in
`regressions-before-corrected.log`; the advance failure is separately retained.
Initial grid-selection and Clippy/harness failures remain in the evidence rather
than being rewritten as passes.

## Scope limits and the next gate

- This codec reads filled SVG-font paths, not arbitrary SVG documents. CSS,
  transforms, strokes/effects, contextual selectors and external/active resources
  remain explicit unsupported inputs. Kerning and unrepresented source metadata
  remain diagnosed losses; native fields do not promise every foreign-format
  property is preserved.
- Elliptical arcs use the bounded svgtypes/kurbo cubic approximation (0.1 design
  unit tolerance). The conservative pre-allocation guard can reject extreme
  anisotropic arcs. There is no hinting or antialiasing on import. These bounds
  are compatible with the specified pixel-font projection scope and are explicit.
- Native SVG-font embedding is historical and poorly supported by modern
  browsers; standalone image paths do not require embedded-font support.
- Monobit 0.54's single-stroke SVG adapter remains unsuitable for the filled-font
  oracle. It is not counted as a pass. Cairo, FontTools and supplied independent
  bdfparser producer checks cover the supported filled-path contract.
- OTS/FreeType/HarfBuzz OpenType-container checks do not consume standalone SVG.
  Their previously accepted implementations are unchanged; W2.8 passing does
  not stand in for the combined phase-2 acceptance gate.
- Phase 2 remains incomplete. The next separate task must establish the combined
  PLAN §9.3 fontTools/OTS/FreeType/HarfBuzz matrix, §9.4 full Tong equivalence across
  regional/style/size outputs and locl shaping, and §10 whole-export five-run
  timing/size comparisons (including WOFF2 choices) on final integrated main.
  Write the combined phase report only after those gates pass. Do not start W3.
