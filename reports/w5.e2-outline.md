# W5.E2-outline — SSFN and PFR native bitmap support

Owned implementation is frozen after the checks below. This closes these two
codec work items; it does not claim completion of the other phase-5 formats or
of formal performance/fuzz acceptance. W5.X and W5.A1 remain separate freezes.

## Native behavior

- **SSFN:** binary SFN2, SFNC collections, bounded gzip via the existing transport,
  plus ASCII source. Mono bitmap and Gray8 pixmap fragments, narrow/wide fragment
  references, Unicode skips and ligature sequences are native inputs/outputs.
  Composition follows native fragment order. Writer emits real binary fragments,
  split pixmap packets and a native alpha palette. Contours are never rendered
  to manufacture bitmap support. Mixed contours, RGB reduction and omitted
  hint/kerning data have explicit reader Loss; outline-only input fails.
- **PFR:** complete v4 directory/logical/physical/GPS/trailer containers. Reader
  handles multiple logical fonts, multiple bitmap strikes per physical font,
  variable-width code/offset/size fields, raw/RLE4/RLE8 streams, positions and
  advances, native metadata and physical records above 64 KiB. Writer emits
  native bitmap records using all three image encodings and handles the high
  physical-size byte. Mixed outline programs are explicitly reported as Loss;
  they are not rasterized. Fractional DAVIC metrics remain in native properties
  and their integer projection is a reported loss.

Both codecs expose typed read/write options and a registry codec. All allocation
and scan work passes cumulative limits; readback keeps source/output/live model
costs under the same writer budget. The emitted model is fully audited, including
font/glyph metadata, aliases, sequences, metrics and stable slots. Direct codec
writers enforce strict mode. Binary detectors validate native signature, length
and section/trailer boundaries without constructing raster models.

## Observed differences are explicit

1. **PFR DAVIC versus FreeType:** BCT offsets, large-position units, top-row Y
   meaning and raw ink polarity differ. `PfrDialect::{Davic, FreeType}` and
   optional read/write overrides expose them. Absent an override, a BCT offset
   below the physical-record size selects FreeType; other offsets select DAVIC.
   Ambiguous nonzero tables have a typed override. Native output preserves the
   imported dialect, and new models default to FreeType. This is not a silent
   correction of the published specification.
2. **SSFN author terminals:** the converter writes a final skip ending one
   position past U+10FFFF and can omit the documented zero ligature terminator.
   Those exact complete-section endings are accepted with Repair diagnostics;
   the writer emits the documented form. Larger overshoots/truncations fail.
3. **SSFN ASCII widths:** documented byte-padded rows and the author's actual
   glyph-width rows both read; output uses actual width. Nonzero padded ink fails.
4. **SSFN ASCII alpha coalescing:** the pinned author ASCII importer replaces
   different alpha values sharing white RGB with alpha 139 in the original
   fixture. The crosscheck asserts this exact difference rather than discarding
   mismatched pixels. Native binary output consumed by the author exporter keeps
   every original alpha sample. Written ASCII also has every exact sample under
   independent text parsing. The converter additionally synthesizes an empty
   U+00A0 (advance 10) for the Latin fixture; its absence for the PUA-only fixture
   and every synthesized field are asserted separately.

Details and public option contracts are in [SSFN](../docs/formats/ssfn.md) and
[PFR](../docs/formats/pfr.md). Native unsupported fields always remain subject to
Loss/strict handling; this is bitmap support, not outline editing.

## Evidence

- **19 tests pass**: 10 SSFN and 9 PFR. They include strict/loss audits, aliases,
  extra metadata, negative bearings, continuous non-byte raster widths, all PFR
  compression/polarity/order/dialect combinations, multistrike/multifont input,
  7,400-glyph high-size records, Unicode ligatures, exact grayscale, every prefix
  truncation, cumulative budgets and output readability under identical limits.
- **Six single-feature gates pass**: targeted tests, Clippy with `-D warnings`,
  and rustdoc with `-D warnings` for each feature. Exact argv, exits, logs and
  log hashes are in [w5.e2-outline-gates.json](w5.e2-outline-gates.json).
- **84 independent crosschecks pass** on the final source build: 75 PFR native
  writer outputs consumed by FreeType 2.13.2, the original fractional-metric
  projection check, and eight SSFN author-consumer output checks, plus author
  native-writer input comparisons in those cases. Every code, dimension, signed
  position, advance, sequence and pixel is compared. The result's external
  artifact directory is `../local-work/w5e2-outline/crosscheck-final`.
- **34 original seeds** are reproducible with
  `python fuzz/seed_w5e2_outline.py --out DIR`; the manifest includes byte sizes
  and SHA-256. Both format-specific fuzz harnesses perform bounded read → write
  → read and require complete model equality whenever the writer reports no Loss.
- **Final-source short ASAN passes:** PFR 1,071,929 executions and SSFN 393,855,
  each 11 actual seconds, exit 0. The requested campaign duration was 10 seconds.
  Commands, raw log hashes and source-unchanged assertions are in
  [w5.e2-outline-smoke.json](w5.e2-outline-smoke.json).

Earlier failing crosschecks were investigated before this freeze: they exposed
actual author terminal conventions and alpha coalescing, and the final checks
assert those behaviors. A transient missing shared `transport.rs` and subsequent
shared dead-code warnings were resolved by its owner; final six gates are clean.
No whole-repository gate was run against other workers' in-progress source.

## Performance handoff and remaining acceptance

`w5e2_outline_timing bench ssfn|pfr INPUT COUNT` is a quiet in-process native
read/write adapter. Two tiny functionality checks are recorded separately and
are not formal performance claims. PFR's independent consumer can use
`freetype.Face(BytesIO(bytes))`, select each strike and load known mapped codes;
this driver's `get_chars()` enumeration fails on the one-code fixture, whereas
`get_char_index(65)` and native bitmap loading are exact, so a 65,536-code search
must not be counted as parsing performance. The author `sfnconv` is a real
consumer/writer but its command-line timings include startup and file I/O; they
must not be labeled an in-memory equivalent. MIT `ssfn.h` is available for a
separately labeled in-memory load/render consumer if the performance runner needs it.

Root owns final 610-second ASAN campaigns, five quiet release performance runs,
combined CLI/registry integration gates, shared NOTICE/decisions and catalogue
acceptance. [w5.e2-outline-freeze.json](w5.e2-outline-freeze.json) binds the owned
source, fixture/tooling files, reports and shared dependency snapshot for handoff.
