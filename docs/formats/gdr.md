# Psion / EPOC GDR

Research recorded before implementation, 2026-10-04.

Primary sources are Symbian's [fnttran compiler reference](https://docs.huihoo.com/symbian/s60-3rd-edition-cpp-developers-library-v1.1/GUID-35228542-8C95-4849-A73F-2B4F082F0C44/html/SDL_93/doc_source/ToolsAndUtilities93/FileConversionUtilities-ref/Tool_Ref_Fonts_Fnttran.guide.html) and Nokia/Symbian's published [bitmapfonttools](https://github.com/cdaffara/symbiandump-os1/tree/master/sf/os/graphics/graphicstools/bitmapfonttools) and [fontstore](https://github.com/cdaffara/symbiandump-os2/tree/master/sf/os/textandloc/fontservices/fontstore) wire declarations. These EPL-1.0 sources are used as format authority and an external oracle, not copied into this library. The compiler can be built externally on Linux with only ABI/standard-header adjustments; original sources, adjustments, hashes and generated fixtures are recorded by the crosscheck script. Monobit 0.54 has no GDR reader or writer.

The file is a little-endian direct-file store, identified by UIDs 0x10000037, 0x10000039, 0, and checked UID 0x47393853. The root stream offset at byte 16 leads to compiler version, collection UID, pixel aspect ratio, data-stream offset and copyright strings. The data stream contains strike descriptors followed by typeface descriptors. Every stream pointer is an absolute file offset; lengths/counts are signed 32-bit nonnegative numbers. Character ranges use 16-bit code values. Typeface entries refer to strikes by UID, optionally supplying width/height scale factors.

Strike descriptors contain UID, posture, weight, proportional flag, cell/ascent/maximum widths, bitmap encoding, metric-table pointer/count, and code-section descriptors. A code section has inclusive first/last code, an offset-array stream and a bitmap stream. Arrays have a 32-bit count prefix. Per-character metrics are five signed bytes: ascent, height, left bearing, advance and right bearing; width equals advance minus the two bearings. Metric indices use a low tag bit followed by 7 or 15 index bits. Pixels are stored in LSB-first bit streams. Each row packet has one literal/repeat bit, a four-bit nonzero row count, then either all literal rows or one repeated row. The writer uses this native compression and splits sections before their 16-bit offset space is exhausted.

Version 41 names use Symbian descriptors with compressed Unicode ([SCSU](https://www.unicode.org/reports/tr6/tr6-4.html)); both compressed Unicode and 8-bit descriptors must be decoded. Earlier supported layouts and version-dependent fields are checked against the runtime loader before implementation. Unknown versions/encodings must fail explicitly.

The model preserves source UIDs, encoding, native header fields and typeface associations as properties. Glyph coordinates use left bearing and ascent minus height. Each native strike is retained; synthetic typeface scaling is represented explicitly or expanded with a diagnostic. Writer diagnostics compare all source fields with decoded output, including unsupported codepoints, aliases, names, metrics, grayscale, metadata and synthetic associations. Aggregate allocation and decompression are bounded before allocation.

Crosschecks use original, locally generated BDF/GD input and the independently compiled Symbian fnttran. No bundled commercial device fonts are required.

Version 40 (Symbian 7.0) uses eight-byte per-character records (bitmap offset, five signed metrics, padding) and has no shared metric stream or metric-index bitmap prefix; 0xffff marks absent characters. This layout is independently documented by the external [EKA2L1 GDR loader](https://github.com/EKA2L1/EKA2L1/blob/master/src/emu/loader/src/gdr.cpp). The library implements these wire facts independently; the GPL loader is compiled only outside the repository as an interoperability oracle. Version 39 uses the shared-table layout, confirmed by Nokia's runtime accepting the 7650 compiler version alongside v41. Writers expose v39/40/41/42; v42 additionally carries five vertical metrics.

All four layouts now read and write native strikes. Version 40 uses inline metrics even for zero-area glyphs whose bitmap stream is empty. Versions 39/41/42 support shared metric indexes in both short and long forms, arbitrary ordered sections, aliased bitmap offsets, sparse missing slots, literal packets and repeated-row packets. Output uses repeated-row packets, and preserves all selected characters rather than assuming one contiguous byte range. SCSU names include non-BMP characters, Unicode-mode quoting and dynamic windows; input counts are UTF-16 code units.

The external EKA2L1 decoder validates v39/40/41 outputs, including a 256-glyph strike. A second external build adds only the five-byte v42 descriptor skip prescribed by Nokia's runtime; its metrics/bitmap decoder is unchanged. This adaptation is recorded with exact diff and hashes and is not described as upstream v42 support. The external descriptor shim uses ICU's independent SCSU converter. Crosschecks include multilingual names and a supplementary-plane character. The original EPL fnttran compiler provides independently generated v41 input, including its native crop-to-ink convention; comparisons use all positioned pixels, advances and mappings.

Native limits include signed-byte metrics, 16-bit code values and 15-bit shared metric indexes. Unicode surrogate slots require explicit native-code interpretation. External typeface UID references and synthetic size factors are retained as associations; the reader does not fabricate external pixels or generate scaled strikes. Unknown compiler versions and encoding values fail explicitly. These limits and every lossy writer change are distinguishable from success without loss.
