# OS/2 GPI bitmap font resources

W5.B research recorded before implementation, 2026-10-04.

Primary source: [OS/2 GPI bitmap font resources authority](https://github.com/altsan/os2-gpi-font-tools). Supplementary executable format evidence is MIT monobit 0.54, module `fon.os2.gpifont`; the installed release fingerprints and exact external-oracle scope are recorded in `reports/w5.b-crosscheck.json`.

LE typed records with u32 identity and size: FontStart 0xfffffffe plus OS/2 FONT signature, Metrics 1, FontDefinition 2, Kerning 3, AdditionalMetrics 4, End 0xffffffff. Native types 1 and 2 use fixed/variable increment; type 3 uses A/B/C spacing. Metrics, glyph descriptors, bitmap orientation and record-relative pointers require type-aware bounds. OS/2 NE/LX resource extraction is part of this family, not the existing Windows FON assumption. Alexander Taylor gpifont C/H declares public-domain status.

Preserve all header/metric/kerning fields, variants and container references; unsupported non-bitmap resources remain explicit. Container extraction and output follow native resource tables and the NE DOS entry point exits normally. Strict reports cover codepages, aliases, type conversion and fractional/native metrics.

All reads budget retained input, cumulative fonts/glyphs, table allocations, decompressed pixels and diagnostics before allocation. Every successful write is reopened under identical limits and compared field by field. Source resources and external fonts are never fetched implicitly. Synthetic fixtures are original MIT artwork; third-party tools remain outside the repository.

Native FOCA metrics are 168 bytes before possible extensions. The last-character word is an **inclusive offset**, so all `last + 1` descriptors are decoded; monobit 0.54 incorrectly uses it as a count. Descriptor stride is honored, and type-3 SPACE_UNDEF entries resolve their native A/B/C defaults. Bitmaps consist of consecutive vertical byte columns. The definition baseline offset determines glyph origins. An additional uncounted `.null` descriptor is exposed only when its pointer, dimensions and data extent are structurally valid; otherwise the gap remains opaque retained native bytes. The author's `os2font` writer assumes that an extra descriptor exists and can copy invalid data for inputs without one, which the crosscheck records separately.

NE resource segments and native type-6 directories are decoded independently of Windows FON. LX object/resource/page tables are bounded and cached once per object; native 4096-byte pages support ordinary, zero-fill, EXEPACK1 and every EXEPACK2 token (including overlapping references). Writers emit resource-only OS/2 NE/LX modules with real type-6 directories and type-7 faces; NE includes an executable DOS exit stub. No font code runs during conversion. Runtime loading inside an OS/2 VM is not claimed; the unchanged author parser directly validates LX and raw output, and an independent OS/2 NE parser extracts faces for the author glyph decoder.

Optional records, PANOSE, unknown metrics, descriptor extensions and kerning bytes are retained. Kerning descriptions disagree between packed 9-byte and documented 10-byte headers; the reader accepts only a layout whose following record boundary is unambiguous, bounds every pair and preserves it as native data. It does not invent a public kerning model. Invalid/range LX pages and non-bitmap GPI outline/combined/CJK library resources are explicit errors. Fixed/type-2 padding, mappings, bearings, unknown properties and every modeled field change are reported individually after the same-limit reread.
