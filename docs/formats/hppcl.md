# HP PCL bitmap soft fonts

Primary specifications are HP's [PCL5 Technical Reference](https://www.hp.com/ctg/Manual/bpl13210.pdf), [Downloading Fonts](https://developers.hp.com/system/files/attachments/PCL%20Implementors%20Guide-10-downloading%20fonts.pdf) and [Downloading Characters](https://developers.hp.com/system/files/attachments/PCL%20Implementors%20Guide-11-downloading%20characters.pdf). The MIT monobit PCL reader/writer is an independent oracle.

Font records use ESC`)s<size>W`, character selection uses ESC`*c<code>E`, and character records use ESC`(s<size>W`. Decimal fields and record sizes require bounded parsing. Bitmap font descriptors carry baseline/cell metrics, orientation, symbol set, fractional quarter-dot spacing, names and optional explicit resolution. LaserJet character format4 has a two-byte common header, a fourteen-byte descriptor and raw or run-length raster data. Continuation records carry only common bytes plus additional raster data. Class2 RLE alternates white/black run counts and prefixes each row with the number of additional repetitions; long runs use255,0 continuations. Stream appends must avoid repeated whole-buffer copying.

Native bitmap output uses typed orientation, raw/RLE and continuation choices. Portrait, landscape and reverse orientations need explicit geometric transforms. Scalable Intellifont/TrueType descriptors are rejected as outside this bitmap codec. Original descriptors and symbol-set numbers remain properties; no guessed encoding is substituted. Device metric rounding, unknown commands and unsupported metadata are explicit diagnostics or errors, and successful output is decoded again under identical limits.

`HppclOrientation` covers0/1/2/3, and `HppclCompression` covers Raw/Rle. Continuation size is17..32767 bytes. Bitmap header formats0,5,6,7,9,12,16 and20 are recognized when their minimum descriptor is present; only LaserJet format4 characters are supported. Other printer-family character descriptors and scalable fonts return explicit errors. Fractional quarter-dot advances remain original descriptor properties and report model rounding.

The official character descriptor length is14, excluding the2-byte common prefix. Read compatibility with a historical size16 field is opt-in and only accepted when the raw record length proves the actual descriptor is14. The writer always emits14. Font baseline is in dots, unlike monobit's quarter-dot interpretation; crosschecks state this difference and test baseline from HP's table directly. Unknown stream commands and text remain raw source properties with Loss; the writer emits canonical font commands and audits what cannot be preserved semantically.
