# GEM / GDOS bitmap fonts

The codec is original Rust written from the published [VDI FONT_HDR layout](https://freemint.github.io/tos.hyp/en/vdi_structures.html#FONT_HDR), the Atari Compendium font description, and [GEM bitmap file layout](https://www.seasip.info/Gem/filefmt.html). MIT-licensed monobit `gdos.py` (Rob Hagemans, 2022–2026) is an interoperability and compression reference; no GPL implementation is copied.

The 88-byte header contains 16-bit metrics and 32-bit file offsets. Character offsets are bit positions in a horizontal bitmap strip, with one sentinel offset. Codes remain `Legacy` values: an Atari or PC origin does not identify a character set. Header names use Latin-1. Glyph vertical placement is `y = -bottom`; global ascent is the inclusive header ascent plus one. Raw `top`, `half`, ascent/descent and other header metrics survive as namespaced properties. Signed pre/post byte offsets are subtracted from the left/right bearings.

Integer byte order and bitmap word byte order are separate typed options (`byte_order`, `bitmap_word_order`). Detection validates both complete structural interpretations, including offsets, ranges and strip sizes. Ambiguous headers require an explicit integer order. The standard-form flag controls bitmap word order unless explicitly overridden. Monobit 0.54 ignores this flag for uncompressed rasters and emits standard raster bytes with the flag clear for its little-endian output; use an explicit raster override for such files, or its big-endian output. The reader accepts odd row sizes encountered in monobit output; our writer emits word-aligned strips.

The reader also handles the extended compressed layout, bounded differential run-length decoding, and linked compressed sections with absolute offsets. Repeated/backward section pointers and invalid ranges fail. Sections merge into one font; differing global names or metrics report loss, and raw extended/section headers remain in namespaced properties. The writer emits a standard uncompressed font. Flattening compressed sections or dropping their opaque headers is reported rather than silently advertised as an exact round trip.

Read and write operate on packed rows. `unicode_as_legacy` explicitly permits numeric Unicode-to-GEM mapping; it defaults to false. Gray8 needs an explicit `gray_threshold`. Unsupported mappings, aliases, localized names, metrics, property order, changed cell rectangles, glyph order and inserted/removed slots are diagnosed individually. Later fatal errors retain preceding omission diagnostics. Writers validate output with the same limits before returning it; a report without loss promises full model equality apart from format provenance.

Validation includes original little/big-endian and swapped-word fixtures, signed bearings, zero-width glyphs, compressed/linked sections, truncations/mutations, randomized round trips and both directions against monobit using an original font and the licensed Tom Thumb sample. See [W4.6 validation](../../reports/w4.6.md).
