# Amiga disk fonts

Primary references: AmigaOS `graphics/text.h`, `diskfont/diskfont.h`, and the AmigaDOS hunk layout. Accessible declarations are the [MorphOS text header](https://morphos-team.net/sdk/includes/graphics/text.html) and [diskfont header](https://morphos-team.net/sdk/includes/diskfont/diskfont.html); only format facts are used, not implementation. MIT-licensed monobit `amiga.py` (Rob Hagemans, 2019–2026) provides an independent interoperability reference. Production parsing and writing are original Rust.

A `.font` contents file has magic `0x0f00` or tagged `0x0f02`, a count, and 260-byte records. Every sidecar path passes `ResourcePath` validation and resolves solely through `ReadContext`. Writing returns a descriptor and every strike in an `OutputBundle`. `Packaging::{Auto,Contents,Strike}` controls packaging; Auto produces contents for `.font` primary names or multiple strikes. Duplicate sizes get distinct sidecar names. A direct strike must contain exactly one font.

Hunk headers, CODE/DATA/BSS segments, long/short relocation records, symbol/debug/name data and end markers are parsed as bounded data. Embedded instructions are never executed. The writer emits a diskfont hunk with a conventional return stub and pointer relocations. Scalable IntelliFont data is outside this bitmap codec and fails explicitly.

The DiskFontHeader contains TextFont metrics, a word-aligned MSB-first strip, locations, signed advances and signed left bearings. The final slot is an unencoded default glyph. `tf_Baseline` is zero-based, so ascent is `baseline + 1`. Codes remain `Legacy` with ISO-8859-1 charset metadata. `unicode_as_latin1` explicitly maps U+0000–U+00FF to that documented encoding and defaults to true. Tagged contents preserve their original tag bytes and extract device DPI.

ColorTextFont uses 1–8 bitplanes. Gray8 model values represent coverage, never palette indices. Gray fonts scale the index range to 0–255. RGB12 palette entries expand each channel by 17 and map to rounded BT.601 luminance `(299R + 587G + 114B) / 1000`; non-neutral color produces a read loss diagnostic because the model cannot express chroma. Original per-glyph indices (`amiga.color_indices`), palette and plane metadata remain as opaque properties. Unedited coverage can reuse those indices exactly. After editing, the writer chooses the nearest palette coverage and reports any changed pixels or discarded indices.

`color_depth: Some(1..=8)` requests color planes; absent preserves an existing color font. New Gray8 input otherwise requires an explicit `gray_threshold` to become monochrome. Names and flags/revision/smear survive through typed fields or properties. Reports cover every changed name, metric, mapping, alias, sequence, property, slot and bitmap; failures preserve earlier omission diagnostics, including the correct strike index. Runtime hunk code and host linkage fields are not model font metadata.

Budgets are shared across all strikes, sidecars, generated assets, model allocations, bitmap scratch and diagnostics. Every emitted strike is parsed again under the selected limits; the final bundle also satisfies primary/resource/count/aggregate limits. Validation covers independent hunks and both relocation widths, multi-strike tagged bundles, palette-to-coverage semantics, randomized packed rows, bounded malformed data, and bidirectional monobit comparisons. See [W4.6 validation](../../reports/w4.6.md).
