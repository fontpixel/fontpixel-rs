# RISC OS bitmap fonts and IntMetrics

Primary specification: [RISC OS Programmer's Reference Manual, Appendix E, Font files](https://www.riscos.com/support/developers/prm/fileformats.html), with [Font Manager naming/resolution rules](https://www.riscos.com/support/developers/prm/fontmanager.html). MIT monobit provides independent readers; its12-bit, packed and subpixel limitations require direct specification fixtures as well.

Old `x90y45` files contain16-byte strike indexes terminated by a zero point-size byte. Each bounded, word-aligned strike has geometry/resolution fields and256 u16 offsets relative to its offset table. Glyph coordinates are signed bytes;4bpp pixels run bottom-up with low nybbles first and no per-row padding. A short file may name a master bitmap resource instead of containing pixels; such indirection must use the scoped resolver.

New `FONT` files specify1/4bpp, version, placement flags, bounding box, table data and chunk offsets. Versions4–8 move the index and add dependency/flag data; bitmap chunks contain32-character offset tables multiplied by four horizontal/vertical phases as requested. Eight- and twelve-bit signed glyph coordinates, raw pixels and the documented packed run-length representation must be handled under bounded decoding. Nonzero subpixel phases must be retained as explicit strikes/properties rather than silently discarded. Vector-only chunks are not represented as successful bitmap fonts.

Optional IntMetrics/IntMetricn input and output use explicit ResourcePath resources and OutputBundle assets. Metrics counts, versions, mapping tables and signed scalable values are checked; unknown layout/kern information is retained with explicit representational diagnostics. Native writing covers old and new bitmap profiles, including native Gray8 projection, and audits every output strike against a same-limit reread. No implicit filesystem search or character-set guess is performed.

Public versions are Xy/V4/V5/V6/V7/V8; depth is Mono/Gray4, compression Raw/Packed. XY is raw4bpp only. New formats support raw1/4bpp and packed1bpp, signed8/12-bit coordinates, phase grids1/4/16, and V8 extended codes through65535. Writers require a complete declared phase grid with compatible point sizes/resolutions. Gray4 quantization and grayscale threshold are explicit. Master-resource cycles and missing assets return errors through the scoped resolver.

IntMetrics input versions0/1/2 are parsed, with mapped/direct indexes, optional metric arrays, bounded extra and kerning tables. Output selects V0 or V2 and includes complete canonical arrays. Kerning/miscellaneous tables are retained as source bytes with Loss because their full semantics are not in the core model. Missing metric entries leave bitmap-derived advances and report Loss. Both horizontal and vertical point sizes are used for independent nearest-even device scaling. V0 output reserves index0; V2 direct output supports codes through65534.

The 12-bit pair packs x into byte0 and byte1 low nibble, y into byte1 high nibble and byte2. This is confirmed by the original BSD [TTF2f producer](https://www.netsurf-browser.org/projects/ttf2f/), including signed two's-complement coordinates. Its old width/height packing typo is not used as a bounding-box oracle.

Autodetection requires the full62-byte FONT bitmap header, version4–8, valid depth/flags/table-size/point-size/resolution fields and a bounded generation-specific chunk directory ending at the input size. The shared `FONT` prefix alone is insufficient: valid `FONTX2` files must not be claimed by this codec.
