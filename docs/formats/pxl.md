# TeX PXL 1001 and 1002

Primary specification: [David Fuchs, The Format of PXL Files, TUGboat 2(3), 1981](https://tug.org/TUGboat/tb02-3/tb04fuchspxl.pdf). Monobit's MIT PXL loader is the independent oracle. PXL1001 is big-endian 32-bit words, with raster rows padded to words; 1002 is byte-packed. Matching leading/trailing IDs surround raster data, a 128-entry sixteen-byte directory and a twenty-byte postamble. Directory fields are u16 width/height, i16 x/y offset, raster pointer and fixed-point TFM width. The postamble stores checksum, magnification, design size, directory pointer and ID. Pointers use words for1001 and bytes for1002; the directory location is validated, not guessed from the end alone.

Model coordinates are x=-xoffset and y=yoffset+1-height, consistent with PXL's reference-pixel convention. TFM widths and design sizes retain their exact fixed-point integers. Design point size is an exact Rational; dpi is magnification/5 and TeX uses72.27 points/inch. Device advance and per-1000 scalable advance are rounded explicitly; original numbers remain source properties. Optional TFM input is an explicit ResourcePath, never filesystem guessing. It is bounded and retained, with width/design/checksum validation and unsupported layout semantics reported. Native writing supports both PXL variants and optional TFM sidecars.

All missing/blank directory entries, signed metrics, pointer ranges, padded rows, glyph limits and cumulative allocations are checked. Unsupported metadata, mappings above127, independent vertical metrics and normalization are reported against an actual same-limit reread. No external programs are invoked by the codec.

The original Fuchs article specifies1001; the1002 byte-pointer extension is independently described by monobit's reader. Optional TFM follows [Knuth's public-domain TFtoPL format description](https://mirrors.ctan.org/systems/knuth/dist/texware/tftopl.web): zero checksum is a wildcard, width index zero means absent, a present zero-width glyph receives a nonzero index, and design size must be at least one point. The native TFM writer emits widths plus zero height/depth/italic tables. It does not synthesize ligatures, kerning or font parameters; original TFM properties and layout changes receive explicit loss diagnostics. FontTools tfmLib and monobit independently validate emitted TFM widths/design size.
