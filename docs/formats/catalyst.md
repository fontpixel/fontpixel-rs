# Quark Catalyst SYSTEM.FONTS

The primary empirical source is the [MIT monobit Catalyst reader](https://github.com/robhagemans/monobit/blob/040b1738085ce7967478499eef2835d2cffc95fd/monobit/storage/fontformats/catalyst.py). Its author explicitly states that the layout was reverse engineered from a single file. No additional authoritative publisher specification is established.

A byte counts resources. Each resource has a little-endian u16 body size,128 little-endian u16 glyph offsets,128 width/vertical-shift bytes, then byte height, leading and sidebearing. The width byte's high bit lowers a glyph by one row; its remaining bits describe stored pixels. Raster bytes are LSB-first Apple seven-pixel data, with each eighth bit excluded from the model. Advance is logical width plus sidebearing; line height is height plus leading. Codes are legacy0..127. Native code must validate and follow offsets, including reordered/shared glyph spans, rather than assuming the oracle's contiguous layout. Resource sizes delimit subsequent fonts and all allocations are charged cumulatively.

Native writing emits canonical offset-addressed resources, retains original format fields, audits unsupported metrics/metadata and does not infer a Unicode character set. Auto detection is weak structural evidence only; explicit `catalyst` selection is preferred. Exact offset origin and high-bit raster behavior require independently authored perturbation fixtures in addition to monobit contiguous-fixture comparisons.

`CatalystOffsetBase::{ResourceBody,GlyphData}` makes the historically ambiguous directory origin explicit for reading and writing; ResourceBody is default. Writer height, leading and sidebearing overrides are optional bytes. High color bits remain original per-glyph raster properties; their visual color meaning is outside the monochrome model. Up to255 resources contain exactly128 glyph slots each; slots and all resource storage count cumulatively. Catalogue registration deliberately omits autodetection. The monobit sparse-glyph path divides by zero on zero-width slots, so dense128-slot fixtures provide the independent read/write comparison.
