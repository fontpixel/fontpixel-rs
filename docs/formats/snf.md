# X11 Server Natural Format (SNF)

Primary layout: X Consortium/DEC [`snfstr.h`](https://sources.debian.org/src/tightvnc/1:1.3.10-11/Xvnc/lib/font/bitmap/snfstr.h) and [`snfread.c`](https://sources.debian.org/src/tightvnc/1:1.3.10-11/Xvnc/lib/font/bitmap/snfread.c), version 4. The references carry permissive X11/DEC notices; the codec is original Rust. The format contains a 108-byte FontInfo, 16-byte CharInfo records, a 32-bit-aligned bitmap area, 12-byte property records, strings, and optional ink metrics. Serialized pointer fields are offsets, never host pointers.

Two version stamps identify integer byte order. C bitfields follow the corresponding little/big-endian allocation conventions. Character codes are `(row << 8) | column`, retained as `Legacy` unless explicit ISO10646-1 charset properties establish Unicode. The `exists` bit distinguishes absent slots from zero-width, zero-advance or blank glyphs. Character attributes and optional per-character/minimum/maximum ink metrics are preserved as namespaced properties; ordered signed and string X11 properties remain ordered.

SNF does **not** encode bitmap bit order, scan-unit byte order, or row alignment. Untagged historical files therefore require an explicit complete `SnfReadOptions.bitmap: Some(ByteLayout { ... })`. Offset analysis can identify candidate row alignments for the error message, but cannot prove bit order, so it never silently selects one. Integer endianness does not prove raster endianness. An explicit `byte_order` can further constrain header interpretation.

Writing exposes integer byte order and the full bitmap `ByteLayout`. Defaults are little-endian integers, MSB-first bits, byte scan units, top-down rows and four-byte row alignment. By default the writer includes the legal private integer X11 property `_FONTPIXEL_SNF_BITMAP_FORMAT`, allowing its output to be read without external options. The low byte stores row alignment, the next byte scan unit; bits 16, 17 and 18 record LSB-first bits, little-endian scan units and bottom-up rows. `include_layout_property: false` omits it for applications requiring historical files; the same explicit bitmap layout must then be supplied when reading. Bitmap alignments and scan units are 1, 2, 4 or 8; incompatible combinations fail.

Both directions operate on bounded packed rows. SNF is monochrome; converting Gray8 requires `gray_threshold`, and every changed glyph receives a loss diagnostic. Sparse ranges may require missing table slots; unsupported aliases, slot topology, names, metrics, properties and mappings are diagnosed field by field. Limits include input, table/model/bitmap allocations and reports. The writer validates generated bytes with its selected layout under the original limits before returning them.

Validation uses original wire fixtures for both endian/bitfield conventions and ink metrics, randomized sparse round trips, every fixture truncation, bounded mutations, and an independent Python SNF encoder/decoder derived from the X11 layout. Monobit 0.54 has no SNF handler; it is not claimed as an SNF oracle. See [W4.6 validation](../../reports/w4.6.md).
