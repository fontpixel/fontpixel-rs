# Caller-owned storage during CLI writing

**Reconstruction correction, 2026-10-04.** This documents the current source
policy; fresh gate results are tracked in the coordinator's
[local phase-6 report](../reports/phase6-local.md). The source now compiles and
its unit/integration tests pass (2026-10-05). Source inspection or a successful
compilation is not accepted default-workload evidence.

Standalone CLI commands first divide their original total byte limit `L` into
an identity reservation `I = min(1 MiB, floor(L / 256))` and working allowance
`W = L - I`. The default total remains 256 MiB, now split into 1 MiB for the
shared source-identity table and 255 MiB for model/codec work. This is a CLI
partition; it does not change `ResourceLimits::default()` for library callers
or add a new CLI option.

The full identity slice stays reserved until the command's source scope ends,
including sidecar resolution and output persistence. Unused capacity is not
refunded to `W`. The identity table admits growth against retained capacity
and old/new allocation overlap. Failed admission retains existing charges and
leaves source protection incomplete, so output commits fail. This avoids using
a table's temporarily small size as a credit while a codec can still discover
sidecars. The working reservations below are taken from `W`, without subtracting
the identity slice again.

Batch keeps its existing policy: source identities share the default 512 MiB
`max_pending_bytes` ledger with prepared output bundles. Its per-task working
allowance is not reduced by the standalone identity slice; default 256 MiB task
reservations remain subject to the separate 1 GiB `max_working_bytes` admission
limit. Neither policy is a promise about process RSS.

`charset` reserves its incoming read, mapping and metadata-edit diagnostics
using their actual retained vector and string capacities and then, like
`convert`, moves the edited model into `Registry::write_owned` (strict phase 6,
unit I). The model is charged there exactly once through the shared
capacity-aware `FontSet::retained_usage` bound (metadata, unused vector and
string capacity, glyph slots and mapping indexes). Glyph-count limits are not
subtracted: the writer is operating on those same glyphs.

`convert` (including its `vectorize` alias, `--each` and batch `convert`
tasks) reserves only the incoming diagnostics the same way and then *moves* the
model into `Registry::write_owned` (strict phase 6, unit G, 2026-10-05). The
allowance it passes on includes the model:

- Outline writers (`ttf`, `otf`, `woff`, `woff2`, `ttc`, `vector-raster`)
  charge the model's `retained_usage` on the first ledger they use. Each face
  goes to `variants::encode_single_owned`, which admits the face, copies its
  glyphs into the plan, drops everything but the metrics and names that export
  reads, and releases exactly that charge before any table is encoded. Faces
  still waiting, the container metadata, encoded sfnt capacity and the writer's
  own diagnostics are subtracted from each later stage's allowance, so the whole
  model has dropped before the TTC/WOFF/WOFF2 encoder is admitted with the
  allowance minus the retained sfnt and diagnostics. The writer's diagnostics
  array now grows by exactly its trailing notes instead of doubling (it holds
  one entry per renamed glyph, about 8 MB for full Tong SC).
- Every other writer, and any gzip-named output (its envelope replays the
  writer with the model), has the model's `retained_usage` removed from the
  allowance by the registry before the borrowing route. Since unit I the
  registry calls `FormatWriter::write_reserved` there (and
  `validate_transport_reserved` for the gzip replay), so a writer with a
  reserved route does not charge its estimate on top in a `.gz` output either.
- Writers that keep the model until they return (they audit their readback
  against it) take the reserved route (strict phase 6, unit H, 2026-10-05):
  the legacy-aggregate family (`snf`, `gdr`, `beos`, `psf2txt`, `zapfont`,
  `u8m`, `ssfn`, `vlw`), the editor family (`bmfont`, `kbits`, `sfd`), `pf2`
  the TeX writers `pk` and `gf` (unit I) and the embedded writers (`otb`,
  `bdat`, `color`). The limits are exactly
  the borrowing route's (allowance less the model's `retained_usage`,
  `TransportLimits::without_model`), and the codec is told the model is
  reserved (`ModelCharge::Reserved`), so it no longer charges its own
  estimate of that same model on top: `legacy_common::source_budget`'s model
  sums (it keeps its 1 KiB final-diagnostic reserve), the editor
  `model_bytes`/container estimate (initial ledger, readback allowance, audit
  report allowance and failure report), `pf2`'s initial `source_cost` and
  container property cost, and the embedded `write_preflight` model admission
  (plus the source term of explicit-name `prepare`). Validation is unchanged,
  and every copy the codec makes (grayscale conversion, readback models,
  output, diagnostics) is still charged. Direct calls and `write_with_report`
  still charge the estimate. A unit test checks, for `snf`, `u8m`, `kbits` and
  `pf2`, that the owned minimum equals the borrowing minimum less exactly that
  estimate plus the model's `retained_usage`, with identical output, and that
  one byte less fails; for `otb` the owned minimum is strictly below the
  borrowing minimum plus the model.

The writer's own budget still bounds everything except the model, as on the
borrowing route: the owned ledger is the model plus the writer's budget
intersected with the allowance less the model, and within that ledger the
model's charge is reused once the model has dropped. For the outline writers
(`ttf`, `otf`, `woff`, `woff2`, `ttc`, `vector-raster`) an explicit total
larger than the default now raises that budget (strict phase 6, unit I): when
the codec's own total is still the library default of 256 MiB, a larger common
`max_total_bytes` (CLI `--max-total-bytes`, batch `max_total_bytes`, or a
library `TransportLimits`) becomes its total; every other limit still
intersects, a configured non-default codec total is never enlarged, and with
no explicit limit the default stays exactly 256 MiB (the CLI default common
allowance is at most 255 MiB, so nothing changes at defaults). Before this, no
`--max-total-bytes` could admit an outline job whose working ledger exceeds
256 MiB.

`merge` (strict phase 6, unit I) hands its merged model to
`Registry::write_owned` for its last (or only) output, with an allowance that
includes the model, so the outline writers drop it before encoding tables or
the webfont envelope; earlier outputs borrow it through
`Registry::write_reserved_with_report`, so writers with a reserved route do
not charge their estimate on top of the caller's reservation. The full
Unifont 13 plus Tong Latin merge now needs 227.4 MiB to TTF (was 246.3 MiB;
peak RSS 195 MiB, was 262 MiB) and, to WOFF2, 303.9 MiB (before: failed at any
budget, even 1 GiB; peak RSS 291 MiB). Its WOFF2 still fails cleanly at the
default: the q11 Brotli admission alone needs a 281.5 MiB working ledger,
above the 255 MiB CLI working allowance, so this is genuine. TTF and WOFF2 in
one command need 327.9 MiB (was impossible). `charset` from full Tong SC BDF
to `snf` needs 164.0 MiB (was 283.0 MiB, so it now succeeds at the default),
to `pf2` 294.5 MiB (was impossible even at 1 GiB), to `pk` 139.4 MiB, to `gf`
103.1 MiB and to `zapfont` 194.4 MiB; `otb` is unchanged at 231.0 MiB (its
binding stage is the embedded diagnostic allowance, not the model).

Outputs and reports are unchanged. Before this, the CLI charged the model while
the writer's later stages ran on their own full-size ledgers, so full Tong SC
BDF to OTF/WOFF/WOFF2 and a full Tong TTF to WOFF2 failed at the default limit
(minimum `--max-total-bytes` for SC to OTF, SC to WOFF2 and TTF to WOFF2: 266.0,
283.7 and 278.2 MiB); they now need 214.7, 246.5 and 238.4 MiB. These quality-11 WOFF2 conversions fit the ledger but still
peak at about 298-309 MiB process RSS (Brotli envelope, allocator overhead;
v4 needed 333-347 MiB at a 300 MiB budget).

There is no guessed credit for a codec's internal source-model estimate: the
reserved route above drops it only where the caller has charged the model
exactly. Full Tong SC BDF now converts at the default limit to `snf`, `gdr`,
`beos`, `psf2txt`, `u8m`, `ssfn`, `vlw`, `bmfont`, `kbits` and `sfd` (minimal
`--max-total-bytes` 172.0, 145.7, 217.9, 235.2, 207.0, 215.9, 233.3, 223.4,
198.1 and 213.1 MiB, was 290.9-353.9 MiB; each drop equals that codec's model
estimate, 124.4 MB legacy or 67.5 MB editor, plus the smaller identity slice;
peak RSS 111-193 MiB).

Unit I replaced three more codec envelopes with exact charges:

- **TeX `pk`/`gf`.** `model_budget`'s 6144 bytes per glyph (plus three times
  each bitmap and 512 bytes per code), applied twice per write, is gone. One
  working ledger of the codec's total now holds the model's exact
  `retained_usage` (nothing on the reserved route, which `pk`/`gf` now take),
  then admits before allocating: the mapping array at its final size, each
  glyph's monochrome copy (released after the glyph), the output buffer's
  every growth step (old and new buffers overlapping), the readback model
  (its exact `retained_usage`, after its reader parsed within the remaining
  allowance), the seen flags of the alias check, and every diagnostic (entry
  array growth, and code and message strings formatted into exactly sized,
  pre-admitted strings). Previously the mapping array, the output buffer and
  the diagnostics were charged only after they were allocated, and the
  readback model not at all. Full Tong SC BDF to `pk`/`gf` now succeeds at the
  default with byte-identical output and report (minimal 147.4/102.8 MiB, was
  496.7/427.9 MiB; peak RSS 139/70 MiB; `gf` is now bound by source loading).
  Plan 9 still uses the old envelope.
- **`zapfont`.** Each cell raster is released once its bits are copied; the
  output file is allocated once at its exact final size and charged once (was
  twice); the readback no longer charges a copy of the output it parses in
  place, and once the parser returns its per-glyph admissions (2048 bytes plus
  twice the bitmap per glyph) are replaced by the decoded model's exact
  `retained_usage` and its report's exact bytes. Full Tong SC BDF to `zapfont`
  now succeeds at the default (minimal 202.4 MiB, was 276.4 MiB; peak RSS
  152 MiB, identical output). Its audit still charges each diagnostic through
  the shared legacy ledger at twice its entry and string size (about 30 MB of
  over-count for SC).

Still open, from the codecs' own working bounds rather than the model: `pf2`
319.0 MiB (twice `source_cost` for its `expected` mirror and 512 bytes per
diagnostic) and `color` 548.9 MiB (the fused `color_memory_preflight`
envelope, 48 bytes per pixel and 4 KiB per glyph, including source rasters).
No default limits are enlarged to hide that cost.

Default sweep after unit I (`scripts/phase6_default_sweep.py`, 109 cases,
outputs compared with frozen v4 at a 1 GiB budget): 45 cases succeed and all
45 are byte-identical; 57 are format rejections. The seven resource-limit
exits are `pf2` and `color` (the two envelopes above; they succeed at 1 GiB
with 137 and 186 MiB peak RSS), the fixed format limits of `c`, `pbf`,
`plan9` and `hmzk` (they still fail at 1 GiB), and the Unifont merge to WOFF2
(genuine: 291 MiB peak RSS at its 303.9 MiB minimum, above the 256 MiB cap). Full
Tong, Unifont, catalogue and other default workloads must be retested against
this exact source before their acceptance is claimed
(`scripts/phase6_default_sweep.py` runs a default-limit sweep).

Incoming reported errors take precedence over strict-loss rejection; both are
handled before writer-budget accounting and without cloning the report. A
budget rejection prepares no file replacement. For `convert --each`, previously
prepared output bundles, reports and summary storage have already been removed
from the next group's allowance; the live report reservation and the model charge
taken by the writer (or the registry fallback) are additional.
All outputs still enter the existing single grouped transaction.

This closes the caller-owned-storage omission. It does not prove that every
codec's transient allocations are fully accounted for, and it is not a bound on
allocator overhead, retained allocator arenas, process RSS or whole-system RAM.
The model-accounting implementation has its own documented standard-library
layout assumptions.

Pending regressions cover exact capacity reservations, the zero-remaining-byte
boundary and one byte below it, metadata-heavy models with spare capacities,
BDF text and RAW projection writer boundaries, diagnostic/strict precedence and
`--each` rollback while earlier outputs consume the next group's budget.
The standalone source-scope regressions additionally cover the fixed split,
nested scope restoration, identity growth failure and sticky source protection.
Their current execution status belongs to the local phase-6 report above;
the full default Tong, Unifont and catalogue workloads pass under the tighter
255 MiB default working allowance (2026-10-05, phase 6 report).

## Codec working ledgers (strict phase 6, 2026-10-05)

PLAN §9.6 requires configurable caps on decompressed size, glyph count, pixels
per glyph, table size and similar inputs, each returning an error when exceeded,
plus a fuzz campaign for every reader. Beyond that, the user asked on 2026-10-05
for the stricter standard: every codec-owned allocation admitted against the
caller's single working ledger before it is made. The status per path:

- **WOFF1/WOFF2 encode and decode (closed, 2026-10-05).** Each public
  `woff1`/`woff2` encode/decode (and the WOFF2 collection paths) builds one
  working ledger from `max_total_bytes` and admits every owned stage before
  allocating it: directories, decompressed/copied tables, raw streams, table
  maps (tree nodes and values), glyf/loca/hmtx transforms including all seven
  transform streams, canonical sfnt reassembly, compressed tables, compressor
  input/output buffers, the fixed miniz deflate/inflate workspaces, Brotli
  decoder cells and the growable output. A table shared by collection faces is
  retained once. `sfnt::collection` keeps its own ledgers, so a source-derived
  bound of its heap is reserved around each call (tied to that file's current
  allocations). Codec errors carried through `io::Error` stay `ResourceLimit`.
  A counting allocator shows the whole-call heap stays within the smallest
  succeeding ledger plus report strings.
- **Brotli encoder heap (admitted; quality 10-11 empirical, 2026-10-05).** The
  pinned `brotli` crate still allocates through an infallible allocator, so its
  heap is admitted as a whole before each stream and held until every worker
  joins; the dependency is not patched. For quality 0-9 the admitted amount is
  a bound derived from every reachable allocation site of `brotli 9.0.0`
  (`woff::woff2::brotli_encoder_proven_heap_bound`). For quality 10-11 the
  sound bound grows by kilobytes per input symbol (block-split clustering) and
  would reject every full font under the 256 MiB default, so admission uses an
  **empirical, not proven** envelope: exact persistent tables plus
  1.5 x a linear model fitted on an 816-case counting-allocator matrix
  (adversarial repeat structures and the 16 full Tong TTF/OTF exports
  included; data-dependent heap at most 0.65 of the envelope, total
  observed/admitted at most 0.90 at the WOFF2 window). An input whose clustering
  allocates far more than any measured one could exceed it. Measurements:
  `crates/fontpixel-heap-check` (`cargo test --release -p
  fontpixel-heap-check -- --ignored`). With this admission the default Tong
  batch (q11, two WOFF2 workers) succeeds inside the 255 MiB CLI working
  allowance with about 10 MB to spare on the largest stream. A font whose WOFF2
  raw stream exceeds roughly 7.5 MB at quality 11 with two workers does not fit
  the default CLI allowance and fails cleanly with `ResourceLimit`; raise
  `--max-total-bytes` or lower `--woff2-quality` for such fonts.
- **Variants planner and export (closed, 2026-10-05).** Planning, export,
  `encode_single` and every prepared encode charge one working ledger built
  from `limits.sfnt.resources.max_total_bytes`. Everything is admitted before
  it is allocated: plan records, exact-capacity names, signature buckets, maps,
  layout, glyph copies, outline grids, edges, points and contours, dot-row
  catalogues, metric arrays, report entries and every table. cmap, GSUB, hhea/hmtx,
  OS/2, post, EBDT/EBLC and the builder use their own ledger entry points. glyf,
  name, maxp and gasp run under bounds derived from their encoder sources
  (`variants/tables.rs`), and only the output capacity stays charged. CFF
  (strict phase 6, unit H) is encoded by `sfnt::cff::Encoder` as each glyph is
  built: the glyph's path (56 bytes per command) drops right after its
  Type 2 program is written into one shared, ledger-grown buffer, admitted
  first with the exact program length model (`cff::program_len`). Only the
  programs, the glyph names (in order and in the duplicate check) and their
  end offsets stay live; the table is then laid out once into a byte counter
  and written once into an exactly sized, admitted buffer, with no
  `Vec<Vec<u8>>` charstrings and no INDEX copies. `Font::encode` uses the same
  encoder, so bytes are unchanged; per-glyph validation errors are held until
  the whole-font checks that used to precede them have run. Full Tong SC BDF
  to OTF now needs 85.7 MiB (was 214.7) at 88 MiB RSS. The full Unifont 13
  plus Tong Latin merge to OTF succeeds at the default (9.8 MB, 142 MiB RSS;
  before, 334 MiB RSS and a failure even at 1 GiB). Its WOFF2 still fails:
  the q11 WOFF2 encode of that 9.8 MB sfnt alone needs a 281.5 MiB working
  ledger (Brotli envelope; 216.3 MiB measured heap), above the 255 MiB
  default CLI working allowance, so it fails cleanly at the default and, since
  unit I, succeeds with `--max-total-bytes` 303.9 MiB or more (see above). `PreparedVariants` charges its retained plan once on
  each encode's own ledger. Concurrent encodes each take their own allowance
  (`encode_allowance`), with no process-wide total implied. The CLI `variants`
  command (and therefore batch) calls `Variants::encode_owned`, which admits the
  model's `retained_usage` on the same ledger. It drops each alternative face
  after that face is planned, and drops the base once its glyphs are copied
  (keeping only its metrics and names). Each face's exact charge is released
  only after the face has dropped. Under the default 256 MiB, full Tong Large
  square/dot TTF/OTF export succeeds and is byte-identical. The minimum
  `--max-total-bytes` is set by source loading (250.46 MiB, unchanged), and
  peak RSS fell from 335–552 MB to 238–250 MB. A counting-allocator harness
  outside the workspace (`strict/alloccheck-C`) confirms the measured heap never
  exceeds the minimal ledger. Excluded, as everywhere: allocator overhead and
  process RSS.
- **Subset internals (closed, 2026-10-05).** `sfnt::subset::subset` builds one
  working ledger from the caller's remaining allowance
  (`limits.sfnt.resources.max_total_bytes`) and every nested codec charges it;
  no nested full-limit budget remains. Covered before allocation and kept
  until drop: directory, selected cmap, GSUB model/closure/remap/encode, glyf
  validation temporaries of every glyph (only composite child IDs retained),
  keep/mapping trees, CFF model, DICT bookkeeping and exactly sized output
  (no INDEX/template copies), selected metrics, OS/2, post names and encoder,
  embedded strike records/canvases/retained images/encoder buffers,
  EBSC/VORG/LTSH/hdmx, copied global tables, builder nodes, final sfnt and
  report entries. Validation of unselected data is unchanged. Output, mapping
  and report stay charged until return; after return the caller accounts for
  them. Tree storage uses the shared conservative node estimate, so the ledger
  peak exceeds the real heap peak. Minimal working allowance for full Tong
  exports, of the 255 MiB CLI working allowance: TTF 5.9–8.1 MiB to ASCII and
  52–53 MiB for every mapped scalar; OTF 5.9–6.0 and 51–57 MiB; OTB 28.6 and
  85.9 MiB. CBDT PNG compression buffers are outside the
  subset path (subset rejects CBDT) and are charged only once they exist.

What remains approximate: glyf, name, maxp and gasp encoding inside variants
export is admitted through bounds derived from their encoder sources rather than
charged allocation by allocation (CFF program bytes are admitted with an exact
length model before they are written), and the Brotli encoder at quality 10-11 is
admitted through the measured envelope above. As stated above, no limit here is
a bound on allocator overhead or process RSS.
