# Final batch/inspection contract — reconstructed recovery notes

**Recovery status (2026-10-04):** this phase-6 documentation/source reconstruction is uncompiled and untested. Historical observations are not current acceptance. See [recovery status](recovery-status.md) for known gaps and catalogue metadata/metric work.

Reconstructed from worker messages and the pre-loss documentation view. No code
or behavior has been revalidated in the restored workspace.

`diff` compares complete per-code duplicate lists and unencoded glyphs in their
relevant source order, metrics, bitmap, sequence and charset. Order between distinct
encoded codes is ignored. Names/raw properties are outside equality. Differences
return 1. `validate` covers model checks and implemented sfnt header/table/checksum,
glyf/CFF/bitmap/color budget checks; it is not general OTS certification. `charset`
uses --to for charset, --format for output codec, --from for input, and explicit
source-charset overrides. Unknown names fail, sequence/unencoded glyphs survive,
unmappable aliases lose mappings with diagnostics, and alias-less glyphs can drop.

## TOML schema

version=1; optional jobs (1..64, default available CPUs capped at32).
Defaults: max_working_bytes=1073741824, max_pending_bytes=536870912,
max_report_bytes=2147483648, max_task_report_bytes=67108864. File limit 8 MiB;
1..10,000 tasks with unique nonempty IDs up to256 UTF-8 bytes.

Each [[tasks]] requires id and kind. Kinds: convert, vectorize, variants, subset,
merge, charset, validate, diff. Convert/vectorize have one-or-more inputs;
charset/subset/validate one, diff two. Single-output tasks use output; merge uses
ordered outputs and parts, optionally output_formats of exactly equal length.
Each part has input,take and optional dy,from,font_index. Variants uses base,
family,languages,scripts; language/script maps iterate lexical keys. Merge parts
remain in array order. from/to/strict/family are structural where applicable.

options values are scalars or flat repeated arrays; underscores normalize to
hyphens. true adds a flag and false omits it, except gl passes an explicit bool.
Negative values remain values. Options cannot override structural path/report/strict
fields. text_file is a permitted path option resolved relative to the TOML.
All typed relative paths resolve against TOML location, absolute paths remain
absolute, and destination parent directories must already exist.

## Concurrency, transactions and JSON

CLI --jobs overrides the file. Each task reserves its max_total_bytes (normally
256 MiB) against max_working_bytes. Actual persistent workers are the minimum of
requested jobs, valid queued tasks, and floor(working/minimum queued task weight).
All-invalid queues spawn zero. The admission gate still handles mixed weights.
Default1GiB permits at most four default256MiB tasks. Brotli within-font workers
are a separate bound. Reservations are not an exact RSS estimate.

No task dependencies. All declared inputs, including missing/invalid-task inputs,
and dynamic sidecars are protected before persistence. Outputs cannot alias any
input, another output, directory ancestor/member or inode identity. Successful
independent preparations can survive another task's preparation failure, but all
successful writing tasks enter one rollback-capable transaction. Transaction
failure fails every would-write task; successful read-only tasks remain successful.
Batch has no in-place overwrite exception. This is normal-error rollback, not
crash atomicity or protection against hostile concurrent filesystem mutations.

Stdout is one JSON document, including malformed TOML failures. Task order is
input order. Fields: index,id,kind,success,exit_code,committed,result,report,
diagnostics_truncated,error. Result stays an object, not a JSON-encoded string.
Aggregate: version,success,exit_code,jobs,workers,summary,total/succeeded/failed/
committed and tasks. jobs is requested ceiling capped by task count; workers is
actual threads. No timestamps/durations. Exit precedence2 >1 >3 >0.

Each task may use its entire report allowance, with actual raw cumulative bytes
charged to the aggregate ledger and metadata separately reserved. Reports under
1MiB stay in memory; reports >=1MiB use one private batch-owned temporary file
after budget admission, with one descriptor and unchanged quotas/diagnostics/order.
Counting and serialization load at most one admitted payload at a time under the
task cap; no aggregate JSON DOM or duplicate full aggregate buffer. Counting checks
spooled payloads and total serialization before commit. Aggregate exhaustion aborts
the entire output transaction. Oversized success diagnostics fail explicitly;
failure truncation is flagged. The old4MiB/task64MiB aggregate/equal-share policy
was superseded and must not be restored accidentally.

Large runs need writable OS temporary space, up to report ceiling. Private storage
cannot overlap declared inputs, and its identity/ancestry is protected from output
replacement. Normal completion/error unwinding removes it; abrupt death may leave
files. Output assets use the distinct in-memory pending budget. Runtime spool
coverage belongs to integration tests; miniature documentation smokes stayed below
the threshold and cannot prove spool behavior.
