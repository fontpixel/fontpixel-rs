`diff` compares complete per-code duplicate lists and unencoded glyphs in their
relevant source order, metrics, bitmap, sequence and charset. Order between distinct
encoded codes is ignored. Names/raw properties are outside equality. Differences
return 1. `validate` covers model checks and implemented sfnt header/table/checksum,
glyf/CFF/bitmap/color budget checks; it is not general OTS certification. `charset`
uses --to for charset, --format for output codec, --from for input, and explicit
source-charset overrides. Unknown names fail, sequence/unencoded glyphs survive,
unmappable aliases lose mappings with diagnostics, and alias-less glyphs can drop.

## Standalone source identities and working allowance

Before reading input, a standalone command partitions its original total byte
limit `L`. It reserves `I = min(1 MiB, floor(L / 256))` for the shared input-identity
table and uses `W = L - I` for model/codec work. The original default remains
256 MiB: 1 MiB is reserved for identities and 255 MiB remains for work. No new
CLI budget option is introduced. Existing per-input/resource limits still apply.

The full identity slice remains reserved for the command's scope, through dynamic
sidecar discovery and output persistence. It is not refunded according to the
table's current size or when decoded inputs are dropped. Identity growth checks
retained capacity and overlapping old/new allocations; rejected growth keeps
existing charges and marks protection incomplete, preventing output commits.
Working reservations for live models, reports and prepared outputs are taken
from `W`; the identity reservation is not subtracted again from those remainders.

This is a tighter effective working allowance, not a raised default limit. The
full default Tong, Unifont and catalogue workloads pass under it (2026-10-05,
[phase 6 report](../reports/phase-6.md)). The accounting
does not claim complete codec-transient coverage or a process RSS bound. See
[caller-owned writer storage](w6.1-writer-budget.md) for additional reservations.
Batch uses the separate pending ledger below and does not apply this standalone
partition to each task.

## TOML schema

version=1; optional jobs (1..64, default available CPUs capped at32).
Defaults: max_working_bytes=1073741824, max_pending_bytes=536870912,
max_report_bytes=2147483648, max_task_report_bytes=67108864. File limit 8 MiB;
1..10,000 tasks with unique nonempty IDs up to256 UTF-8 bytes.

`max_pending_bytes` bounds retained transaction state: prepared output bundles
**and the shared input-identity table**, including its retained allocation
capacity. The default remains 512 MiB. It is not solely a font-output-byte cap.
The standalone identity/working split does not change that shared batch ledger
or the existing per-task working reservation.
The TOML/job size limit, task-count/ID limits and the 100,000 declared-input-path
cap are separate admission bounds. Working reservations and report quotas also
remain separate. Their combination is not a bound on process or whole-system RSS.

Native writer allowance is also reduced by live caller-owned models and incoming
diagnostics. See [caller-owned writer storage](w6.1-writer-budget.md) for the
current convert/charset reservation and conservative double-counting caveat.
When a registry write supplies common `max_output_bytes`, plain output checks
the aggregate serialized asset lengths, including sidecars and directory members,
after error/strict diagnostics and before returning assets. That sum is separate
from the retained-capacity transaction ledger. A codec may finish encoding before
this returned-output check, so the cap does not promise universal preallocation
prevention. With no common limits, typed limits stay in force; gzip budgets and
defaults are unchanged. The full default workloads pass with these corrections.

Each [[tasks]] requires id and kind. Kinds: convert, vectorize, variants, subset,
merge, charset, validate, diff. Convert/vectorize have one-or-more inputs;
charset/subset/validate one, diff two. Single-output tasks use output; merge uses
ordered outputs and parts, optionally output_formats of exactly equal length.
Each part has input,take and optional dy,from,font_index. Variants uses base,
family,languages,scripts; language/script maps iterate lexical keys. Merge parts
remain in array order. from/to/strict/family are structural where applicable.
The structural `family` field is accepted by convert/vectorize as well as
variants/merge; use it instead of `options.family`. Other naming options such as
`style`, `full_name` and `copyright` go in `options` for supporting commands.

options values are scalars or flat repeated arrays; underscores normalize to
hyphens. true adds a flag and false omits it, except gl passes an explicit bool.
Negative values remain values. Options cannot override structural path/report/strict
fields. text_file is a permitted path option resolved relative to the TOML.
All typed relative paths resolve against TOML location, absolute paths remain
absolute, and destination parent directories must already exist.

## Concurrency, transactions and JSON

CLI --jobs overrides the file. Each task reserves its max_total_bytes (normally
256 MiB) against max_working_bytes. Actual persistent workers are the minimum of
requested jobs, valid queued tasks, and floor(working/minimum queued task weight).
All-invalid queues spawn zero. The admission gate still handles mixed weights.
Default1GiB permits at most four default256MiB tasks. Brotli within-font workers
are a separate bound. Reservations are not an exact RSS estimate.

No task dependencies. All declared inputs, including missing/invalid-task inputs,
and dynamic sidecars are protected before persistence. Outputs cannot alias any
input, another output, directory ancestor/member or inode identity. Successful
independent preparations can survive another task's preparation failure, but all
successful writing tasks enter one rollback-capable transaction. Transaction
failure fails every would-write task; successful read-only tasks remain successful.
Batch has no in-place overwrite exception. This is normal-error rollback, not
crash atomicity or protection against hostile concurrent filesystem mutations.

An input-identity admission error marks source protection incomplete for the
whole batch. That state is sticky: even otherwise successful tasks cannot commit,
because a failed task may have opened a sidecar whose identity could not be
retained. Reducing the retained budget must not turn a protected source into a
permitted destination. The CLI integration suites (`phase6_cli_recovery`,
`input_budget`, `cli`) exercise these batch admission, spool and rollback paths
and pass (2026-10-05).

Stdout is one JSON document, including malformed TOML failures. Task order is
input order. Fields: index,id,kind,success,exit_code,committed,result,report,
diagnostics_truncated,error. Result stays an object, not a JSON-encoded string.
Aggregate: version,success,exit_code,jobs,workers,summary and tasks. `summary`
contains total/succeeded/failed/committed. jobs is requested ceiling capped by task count; workers is
actual threads. No timestamps/durations. Exit precedence2 >1 >3 >0.

Each task may use its entire report allowance, with actual raw cumulative bytes
charged to the aggregate ledger and metadata separately reserved. Reports under
1MiB stay in memory; reports >=1MiB use one private batch-owned temporary file
after budget admission, with one descriptor and unchanged quotas/diagnostics/order.
Counting and serialization load at most one admitted payload at a time under the
task cap; no aggregate JSON DOM or duplicate full aggregate buffer. Counting checks
spooled payloads and total serialization before commit. Aggregate exhaustion aborts
the entire output transaction. Oversized success diagnostics fail explicitly;
failure truncation is flagged. The old4MiB/task64MiB aggregate/equal-share policy
was superseded and must not be restored accidentally.

Large runs need writable OS temporary space, up to report ceiling. Private storage
cannot overlap declared inputs, and its identity/ancestry is protected from output
replacement. Normal completion/error unwinding removes it; abrupt death may leave
files. To reduce whole-system retained memory, use a disk-backed temporary
directory; a tmpfs-backed `TMPDIR` still stores the spool in RAM. Neither storage
choice makes the report quotas an RSS guarantee. Output bundles and shared input
identities use the distinct retained-transaction budget above. Runtime spool
coverage belongs to integration tests; miniature documentation smokes stayed below
the threshold and cannot prove spool behavior.

## Conversion, naming and metric controls

The CLI has a visible `vectorize` alias for `convert`
and `--each`. `--each` requires
an explicit `--to` and existing output directory. It strips a final lowercase
`.gz` suffix before deriving the stem, appends the target catalogue's first
extension, rejects colliding destinations, and prepares every
output for one normal-error rollback transaction. `--font-index` is zero-based:
one selected strike in the combined ordered inputs, or one per input with
`--each`. Direct convert currently bounds its input list at 1,024 paths.

Convert's `--family`, `--style`, `--full-name`, `--postscript-name`,
`--font-version`, `--copyright`, `--license`, `--license-url` and `--foundry`
apply normalized names to the selected strikes through `metadata::apply_names`.
Changes generate non-loss audit entries; subsequent codec losses remain subject
to strict mode. Raw properties/XLFD/provenance stay separate. Empty identity text
fails, while empty notice text can clear normalized notices. Family/style changes
clear stale full/PostScript names unless replacements are supplied. No option
infers legal permission or a complete catalogue metadata mapping.

Variants separately exposes `--family`, `--style`, `--legacy-style`,
`--full-name`, `--postscript-name`, `--font-version`, `--vendor`, `--copyright`,
`--license` and `--license-url`. Its version input omits the `Version ` prefix;
convert's normalized version is literal. `--style` controls the typographic
subfamily, while `--legacy-style` controls name ID2 (default Regular independently).
Exact full/PostScript overrides control IDs4/6. `--ppu`/`--upm` are outline
design-scale controls, not the embedded bitmap metric API below.

Shared writer options expose `EmbeddedWriteOptions` in `convert` and `merge`:

- `--otb-upm 16..16384` sets explicit design units per em; omission keeps automatic
  scaling.
- `--otb-reference first|largest|N` selects metric priority. `first` is the default;
  `largest` uses greatest effective y-ppem, with the last original input winning
  ties and the same descending priority for missing glyphs. `N` is a zero-based
  index into the FontSet passed to the writer, then other strikes in original
  order. It must be in range after `--font-index` selection or merge projection.
  This does not select/drop strikes or change the codec's existing physical
  ordering. OTB uses source order; bdat keeps its canonical `(ppem_y, ppem_x)` sort.
- `--otb-rounding half-away|ties-even` selects nearest pixel-to-design rounding;
  omission uses `half-away`. The separate OS/2 average-width rule is unchanged.

Explicit embedded flags require OTB/bdat output with its feature enabled. Other
outputs, including color, reject them even for default-valued flags. Merge applies
the writer options to every output, so all outputs must be compatible when these
flags are present. Vector `--upm` remains an outline control. The typed Rust API is
`Registry::set_embedded_write_options`; see the [API guide](api.md#explicit-output-names-and-embedded-metrics).

Command example (flags checked against the current `--help`):

```sh
fontpixel convert small.bdf large.bdf --to otb -o combined.otb \
  --otb-upm 1000 --otb-reference largest --otb-rounding ties-even
```

Batch scalar options use the same shared parser. This complete illustrative job
expects both inputs and the destination parent to exist:

```toml
version = 1

[[tasks]]
id = "embedded-metrics"
kind = "convert"
inputs = ["small.bdf", "large.bdf"]
output = "combined.otb"
to = "otb"

[tasks.options]
otb_upm = 1000
otb_reference = "largest"
otb_rounding = "ties-even"
```

Catalogue FontTools defaults and metric differences are documented in
[catalogue download differences](migration-fontpixel.md#catalogue-download-differences).
Exposing these controls does not establish equivalence.
