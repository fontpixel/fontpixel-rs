# Third-party notices

The W0.1 skeleton contains no copied third-party implementation or font sample.
The supplied PLAN.md and FORMATS.md define this project's requirements; the
catalogue metadata transcribes their format names and extension hints.

Rust dependencies (resolved versions are in Cargo.lock):
- clap, serde, serde_json, and most supporting crates: MIT OR Apache-2.0
- strsim and zmij: MIT
- memchr: Unlicense OR MIT (this project selects the MIT alternative)
- unicode-ident: (MIT OR Apache-2.0) AND Unicode-3.0

Use `cargo deny --all-features check` to check every resolved license, source,
and advisory. Dependencies keep their upstream licenses; this notice does not
relicense them. Update this file with exact origins before porting reference code.

standard-library codecs, following SPEC-v3's explicit choice of reference. No

The Windows charset metadata comes from Microsoft's documented character-set
and code-page identifiers, linked in `docs/charsets.md`; no Microsoft, Wine,
FreeType or GPL font-codec implementation is copied. `cargo deny` covers Cargo
packages, not these non-Cargo source/data attributions.

## W1.5 bdfparser compatibility, outlines, TrueType and parity harness

`crates/fontpixel/src/compat/bdfparser` ports the exact SPEC behavior and narrowly
scoped outline/SVG/TrueType algorithms from the supplied MIT bdfparser source,
Tom Chen. Native model, bitmap, BDF/PCF and render engines are reused. The complete
upstream license is `LICENSES/bdfparser-MIT.txt`. The Mac glyph-name list is
reproduced from that same permissive TrueType reference.

`tests/parity/{gen_cases,run_py,probes,compare,known_issues,minimize,run_all}.py`
are adapted from the supplied MIT bdfparser-js parity harness, Tom Chen. Changes
are limited to source paths, the Rust execution command, source fingerprints,
Rust known-issue applicability and surrogate-safe diagnostics. Original reference
trees are never modified. Python is an independent test oracle only and is not
invoked by the library or `fontpixel-parity`.

`tests/data/compat` contains the MIT synthetic Mini fixture from bdfparser
`tests/info.py`, the literal expected SVG from `tests/test_svg.py`, generated
TTF/round-trip goldens and synthetic operation-script oracles. Exact files and
hashes are listed in its `SOURCES.json`; regeneration is documented in
`tools/gen_compat_goldens.py`. No large external font designs are vendored.

The compatibility feature uses serde_json (MIT OR Apache-2.0), including its
exact integer and ordered-map support. SHA-256 and base64 are runner-only
optional dependencies (sha2 MIT OR Apache-2.0; base64 MIT OR Apache-2.0).
Cargo.lock pins all transitive dependencies; cargo-deny audits the graph.

## W2.1 sfnt common layer

The public OpenType OS/2 Unicode block assignments and 258 Macintosh standard
PostScript glyph names in `crates/fontpixel/src/sfnt/data.rs` are reproduced from
fontTools 4.61.1, Copyright (c) 2017 Just van Rossum, MIT license. The full notice
is in `LICENSES/fontTools-MIT.txt`; `tools/gen_sfnt_data.py` reproduces the data
and boundary oracle. fontTools 4.66.1 independently verifies the same data.
Only these published data tables and generated expected outputs are copied;
FontForge's code-page heuristic (including its fontTools translation) is not
used. The code-page algorithm here is project-authored full-repertoire coverage
using the already-attributed native charset tables.

The deterministic sfnt checksum/assembly algorithm refactors the existing MIT
bdfparser compatibility implementation; its table-specific byte choices remain
unchanged. Other common-table encoders and bounded adapters are project code
written from the OpenType specification linked in `docs/formats/sfnt.md`.
Fontations read-fonts 0.44.0 (MIT OR Apache-2.0) is an optional production
reader dependency, with its dependency graph locked and cargo-deny checked.
fontTools, OTS, freetype-py/FreeType and uharfbuzz/HarfBuzz are independent test
executables/bindings; their implementation code is not copied into the project.
