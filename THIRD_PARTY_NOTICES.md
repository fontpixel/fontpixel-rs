# Third-party notices

The W0.1 skeleton contains no copied third-party implementation or font sample.
The supplied PLAN.md and FORMATS.md define this project's requirements; the
catalogue metadata transcribes their format names and extension hints.

Rust dependencies (resolved versions are in Cargo.lock):
- clap, serde, serde_json, and most supporting crates: MIT OR Apache-2.0
- strsim and zmij: MIT
- memchr: Unlicense OR MIT (this project selects the MIT alternative)
- unicode-ident: (MIT OR Apache-2.0) AND Unicode-3.0

Use `cargo deny --all-features check` to check every resolved license, source,
and advisory. Dependencies keep their upstream licenses; this notice does not
relicense them. Update this file with exact origins before porting reference code.

## W0.2 charset generation and reference semantics

The following supplied MIT sources (copyright 2017–2025 Tom Chen,
https://tomchen.org) informed/underlie `crates/fontpixel/src/charset/mod.rs`,
`tools/gen_charsets.py`, and the registry metadata. Canonicalization and GL/strict
per-glyph behavior are adapted from Python; the Rust range/array representation
and the independent probe/comparator are newly written. The TypeScript stream
compression implementation is not copied.

- `reference/bdfparser/src/bdfparser/encoding.py`, SHA-256
  `ad4978d0b6e49e215ec92c5fe950a5015265379f6e0f4c990ab76cf2ea995098`
- `reference/bdfparser-js/tools/gen_charsets.py`, SHA-256
  `2eb166bd271930499bd1f0a7c959b092a2dd802b2f7b802fc0085eb0d1185fdc`
- Canonicalization vectors copied from the `canonical` section of
  `reference/bdfparser-js/test/fixtures/charsets.json`, SHA-256 of the full source
  `265ef6529606777ddde6929ff3a7e4bfabb14c5f24a118bf60db45200e4be367`
  into `crates/fontpixel/tests/data/charset_canonical.json`

The complete upstream MIT notice is retained in `LICENSES/bdfparser-MIT.txt`.
The supplied source snapshots are authoritative; upstream project addresses are
https://github.com/tomchen/bdfparser and https://github.com/tomchen/bdfparser-js.

Mapping values are generated by exhaustive queries to CPython **3.12.14**'s
standard-library codecs, following SPEC-v3's explicit choice of reference. No
Python runtime or C/Python codec implementation is bundled, and no GPL code is
ported. As provenance for generated codec data, the installed CPython's license
is retained unchanged in `LICENSES/CPython-LICENSE.txt` (PSF license and historical
notices; https://docs.python.org/3.12/license.html). Changes: query strict codecs,
exclude multi-character/non-roundtripping or disallowed-length results, compress
mapping facts into Rust segment/array tables, and generate regression digests.
The Python implementation itself is not modified.

The Windows charset metadata comes from Microsoft's documented character-set
and code-page identifiers, linked in `docs/charsets.md`; no Microsoft, Wine,
FreeType or GPL font-codec implementation is copied. `cargo deny` covers Cargo
packages, not these non-Cargo source/data attributions.

## W1.1 bitmap semantics and oracle data

`crates/fontpixel/src/bitmap/` implements the supplied bdfparser SPEC-v3 bitmap
semantics in a newly written bounded packed-byte Rust engine. Coordinate rules,
label precedence, negative-gap concatenation, shadow/glow, bold/italic and textual
conversion behavior were adapted from the following MIT reference sources:

- `reference/bdfparser/src/bdfparser/bitmap.py`, SHA-256
  `2c37d08deebe07f9a4f802c120e0b3d888e795c1d5b5bbe6c10a93790451c3d8`
- `reference/bdfparser/docs/SPEC-v3.md`, SHA-256
  `38de6696d4371f89be35c4ed56ee456dea4ad8e5be5697f4f0592e90780626ad`

Copyright 2017–2025 Tom Chen; full MIT notice remains in
`LICENSES/bdfparser-MIT.txt`. No GPL implementation was copied. The packed-byte
kernel, resource checks, typed model/indexes, scalar differential tests and
benchmark harnesses are original project code. The generated fixture
`crates/fontpixel/tests/data/bitmap_reference.json` is deterministic synthetic
input/output from that reference, generated by `tools/gen_bitmap_cases.py`;
it contains no font from a third party.

Criterion 0.8.2 and its supporting packages are development-only dependencies;
resolved licenses are verified by the unchanged `cargo deny --all-features check`
policy. Criterion is MIT OR Apache-2.0; no production dependency is introduced.
